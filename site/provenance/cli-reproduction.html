CLI Reproduction Checklist

Purpose

Give another CLI enough detail to reproduce this package for another channel.

Process

  1. Create a repo named after the topic, not after a temporary extraction job.
  2. Save raw playlists, metadata, raw captions, and clean transcripts separately.
  3. Build concept pages from first principles: problem, domain, why it matters, kept information, left-out information, and failure boundary.
  4. Add family routes, comparisons, worked examples, diagrams, learning path, glossary, domains, reader checks, and decision guide.
  5. Run build validation and a wording scan before committing.
  6. Before remote handoff, run git status --short --branch and make check.
  7. After pushing, run make remote-check or make audit to compare local main with origin/main.
  8. After GitHub Actions finishes, run make ci-check to verify the workflow result for the current commit.
  9. Create or grant access to the GitHub repository configured as origin.
  10. Run git push -u origin main, then verify git ls-remote --heads origin main matches git rev-parse main.

Local Files

Checks

  • repo has a clear topic name
  • raw source material is preserved
  • generated pages are validated
  • commits are small enough to review
  • remote main hash matches local main after push
  • make review prints the strongest local review URLs
  • make ci-check verifies the current commit's GitHub Actions run after CI completes
