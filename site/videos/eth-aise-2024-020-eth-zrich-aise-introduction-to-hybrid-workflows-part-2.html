First-Principles Walkthrough

What this lecture is really about: Hybrid Workflows: Putting Neural Networks Inside Physics Solvers

The question it answers: Instead of replacing physical simulations with neural networks, what if we keep the physics and just teach the network to fix the parts we don't understand? How do we build and train these hybrid systems?

Something concrete to hold onto: Imagine a fluid simulation that's fast but inaccurate on a coarse grid. You could add a small neural network inside the loop to learn a correction factor. Feed the whole thing through backpropagation, and suddenly your network learns what the discretization error looks like.

Start with the big picture: almost all scientific code—fluid solvers, weather models, medical imaging pipelines—can be written as a composition of functions. You feed in numbers (vectors, tensors, matrices), apply operations sequentially, and get out answers. Mathematically it's just a vector function: input X becomes output Y through a chain of primitive operations like multiplication, sine, matrix solve. This matters because if the entire computation is differentiable, you can backpropagate gradients all the way through.

Automatic differentiation (autodiff) is the key enabler. It's what PyTorch and JAX do behind the scenes when you call loss.backward(). The machinery is elegant: decompose the Jacobian (the matrix of all partial derivatives) using the chain rule, then compute vector-Jacobian products in reverse mode. You don't need to build or store the full Jacobian matrix—you propagate a single "gradient vector" backwards through the computation graph, multiplying by each operation's local gradient as you go. The result: exact gradients, computed efficiently, without finite differences or symbolic math.

Now the hybrid idea: instead of replacing a physics solver with a neural network, embed a learnable network inside the solver. Real example: Navier-Stokes for fluid flow. The traditional numerical solver uses a coarse grid (fast, but loses accuracy to discretization error). Insert a neural network inside the time-stepping loop that learns a correction to make each coarse step look more like a fine-grid step. To train it, use autodiff to compute gradients of a loss function (like L2 distance to high-fidelity reference data) with respect to the network weights. The gradients flow backwards through both the solver and the network.

To make this work in practice, there are four steps. First, rewrite your traditional algorithm (probably Fortran or C++) into an autodiff approach like PyTorch or JAX. This is usually the hardest step because high-performance code is often intricate, but it unlocks the real wins. Second, open up the algorithm by inserting learnable components—maybe a correction network, maybe just a scalar parameter to learn. Third, collect training data: what you expect the outputs to be (real measurements or high-fidelity simulations). Fourth, train using gradient descent: compute the loss, backprop through the hybrid system, update weights.

A concrete example: the brachistochrone problem (what curve minimizes roll time?). A neural network parameterizes the curve shape. You don't feed the network training examples of the 'right' curve; instead, you minimize the actual quantity you care about—roll time. The network outputs a curve, a physics solver (using conservation of energy) computes the time, and autodiff gives you gradients with respect to the curve. You use autodiff twice: once to get the curve's slope (needed for the physics), and once to backprop the time loss. The network converges to the optimal curve (a cycloid) without ever seeing ground-truth labels. The loss function is derived from physics, not from labeled data.

Another use case: inverse problems like computed tomography. You have X-ray measurements (a sinogram) and want to recover the internal image. Traditionally, this is solved by gradient descent: guess an image, simulate the sinogram, compare to measurements, compute gradients, and update. But the forward simulation (radon transform) can be expensive, and the loss landscape is non-convex with many local minima—gradient descent gets stuck. Hybrid fix: train a neural network to predict a better step than naive gradient descent. At each iteration, the network ingests the gradient of the loss (what gradient descent would do), the current image, and maybe regularization scores, and outputs a smarter update direction. This is learned from many trial inverse problems: run gradient descent on synthetic data with known truth, collect the trajectory, and train the network to predict better steps.

The memory trade-off in autodiff is subtle but important. Reverse-mode autodiff (backprop) must store all intermediate activations from the forward pass, so memory grows linearly with the depth of computation. Forward-mode autodiff (propagating sensitivities forward) doesn't need to store intermediate states and uses constant memory, but it must run once per output dimension you want gradients for. In scientific computing where you have millions of parameters but a scalar loss, reverse mode is standard. In contrast to misconceptions: autodiff is not symbolic differentiation (you don't manipulate equations) and not finite differences (you get exact gradients, not approximations).

The philosophical shift: by embedding learned components directly into physics, you're admitting uncertainty while using structure. If you knew all the physics perfectly, you wouldn't need the network. If you knew nothing, a pure neural network might work but needs huge data. Hybrid methods split the difference: 'Here's what we know is true (the conservation laws, the geometry), and here's what we'll learn (the parameterization, the closure term, the discretization correction).' The result generalizes better and trains faster than either extreme, because the network only learns what physics doesn't already tell you.

Key ideas in plain words

  • Scientific code is differentiable composition of functions. Any program written as a chain of operations (solves, simulations, integrals) can have gradients computed through it using autodiff, because each step is differentiable.
  • Autodiff via reverse mode computes exact gradients by backpropagating a 'gradient vector' through the computation graph. Memory cost is linear in depth. Forward mode has constant memory but must run multiple times for multiple outputs.
  • Hybrid workflows insert learnable neural networks inside traditional physics solvers (not replacing them). The network learns to correct, accelerate, or improve parts the solver handles poorly, then the whole thing is trained end-to-end with autodiff.
  • Loss functions come from physics, not labels. Instead of feeding the network training pairs, you compute a physically meaningful loss (travel time, image error, simulation accuracy) and backprop through both the physics and the network.
  • Inverse problems are hard because they are underdetermined and noisy. A hybrid approach can learn to take smarter steps than gradient descent by observing the loss landscape in context, replacing naive descent with a learned optimizer.
  • Four-step recipe: (1) rewrite physics code in autodiff approach, (2) insert learnable components, (3) gather training data, (4) train end-to-end with backprop. This works because autodiff handles the chain rule automatically.
  • The hybrid approach is a confession and a strength: 'Here's what we know (physics), here's what we'll learn (the unknown part).' Generalizes better than pure neural nets, trains faster than pure solvers.

Worked intuition: Take the brachistochrone example step by step. (1) Define a neural network that takes X-position and outputs Y-position of the curve. (2) For a given curve shape, compute the actual travel time using conservation of energy: v = sqrt(2gy), and integrate distance/speed along the curve. (3) Use torch.autograd.grad to compute dy/dx (the slope of the curve) by differentiating the network's output with respect to X. (4) Plug dy/dx and y into the travel-time integral formula. (5) Use torch.trapezoid to approximate the integral as a sum. (6) Call loss.backward() to backprop the travel time with respect to the network weights. (7) Take an optimizer step. After many iterations, the network converges to the cycloid shape that actually minimizes time. The key insight: you never showed the network what the answer looks like. You only told it what quantity to minimize, and the physics did the rest.

Where it breaks down: Hybrid methods inherit the brittleness of physics solvers: if the solver fails (diverges, requires tiny timesteps), backprop fails with it. The network can't learn if the forward model is broken. Also, if the physics is wrong, the network learns to compensate but can't generalize beyond the data regime it saw. Scalability: in very high dimensions (turbulence, climate) or with very expensive solvers, the cost of running the solver many times (once per gradient step) can dominate. If the loss landscape is extremely non-convex, the network's learned updates might help but can still get stuck in local minima, especially if the network architecture doesn't match the problem structure. Finally, interpretability: a learned correction inside a physics solver is harder to debug than either a pure solver or a pure neural network.

Takeaway: Hybrid workflows are a way to blend learning and physics: keep the structure you trust (conservation laws, numerical methods), teach the network to fix what you don't understand, and use autodiff to wire them together. The network learns not from labeled examples but from minimizing what you actually care about—time, error, energy, or any objective derived from the physics.
