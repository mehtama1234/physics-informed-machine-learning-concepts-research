First-Principles Walkthrough

What this lecture is really about: How JAX lets you write code once and transform it many ways

The question it answers: Why do scientists and machine learning researchers choose JAX over other tools, and what does it actually do differently under the hood?

Something concrete to hold onto: Imagine you write a Python function that computes x squared. With JAX, you can instantly get a new function that computes the derivative (2x) without manually writing calculus. Better yet, you can take that derivative function and ask for its derivative too, or run your original function on thousands of examples in parallel automatically, or compile it to run 8x faster—all by adding one or two lines of code.

JAX is a Python library that does two fundamentally different things from most other tools. First, it makes matrix math and array operations blazingly fast by automatically sending them to GPUs (graphics processors) instead of CPUs. A 10,000 by 10,000 matrix multiply that takes 7 seconds on a normal computer takes 0.05 seconds on a GPU through JAX—126 times faster. This works because GPUs have thousands of tiny cores that can do the same operation on different pieces of data at the same time, whereas CPUs have only a handful of very fast cores designed for tasks that happen one after another. When you do machine learning or scientific computing, almost everything boils down to matrix operations, so GPUs are perfect.

But the truly revolutionary part of JAX is not the speed. It is something called program transformation, which is the idea that you can take a Python function and automatically rewrite it into a completely different function that does something mathematically related. The most famous example is automatic differentiation: you define a function f(x) that computes something (say, x squared). Then you write grad_f = jax.grad(f), and grad_f is now a brand new Python function that when you call grad_f(5), it returns the derivative of f at that point. The clever part: JAX didn't just memorize the rule that the derivative of x^2 is 2x. Instead, it actually rewrote your function into lower-level code, figured out the derivative using calculus rules (chain rule, product rule, etc.), and handed you back executable Python code that computes it.

What makes this effective is composability: you can chain transformations together. If you have grad_f, you can call jax.grad(grad_f) to get a function that computes the second derivative. You can keep going: third derivatives, fourth derivatives, as deep as you want. Each transformation takes the output of the previous one and transforms it further. This is hard in tools like PyTorch because PyTorch tracks gradients through specific numbers you give it (you compute f(5), then ask for the derivative at that value). JAX gives you the derivative as an actual reusable function. You can take it anywhere, call it at any point, compose it with other functions.

JAX implements this magic by treating your Python code as data. When you ask it to transform a function, JAX doesn't just run your function. It first converts it into an intermediate language (JAX's own low-level representation) that strips away Python specifics and exposes the raw mathematical operations—addition, multiplication, matrix multiplies, element-wise operations, etc. Then it applies the transformation to this intermediate code to produce a new intermediate program. Finally, it converts that back into executable Python. This is what we mean by metaprogramming: programs that write other programs.

A second effective transformation is vectorization (vmap). Suppose you write a function that takes one number x and computes x times a weight plus a bias. If you want to do this for 1,000 different x values (a batch), you would normally write a for loop. But that's slow in Python. Instead, you call jax.vmap(f), and it automatically rewrites your function so it accepts an array of x values and computes the result for all of them at once using matrix operations, which runs in parallel. JAX is smart enough to see that your scalar dot product can become a matrix multiply when the input has an extra dimension. You tell vmap which dimension of which argument contains the batch, and it figures out the rest.

A third transformation is compilation (jit, just-in-time). Your original function might call multiple operations: compute x squared, compute x cubed, add them together. Normally this means three separate jobs submitted to the GPU: one kernel (small program) computes squares, one computes cubes, one sums. Each kernel has to read data from GPU memory and write results back, and that read/write is the bottleneck. When you wrap your function in jax.jit, JAX's compiler (called XLA) notices it can fuse these three kernels into one: read x once, compute all three things in fast on-chip memory, write the result once. This can easily make code 8 times faster. The catch: compilation takes time (a few seconds) and only pays off if you call the function hundreds of times.

JAX makes these transformations composable and chainable, which is why it has become the tool of choice for research. You might vmap a function across a batch, then jit the result, then wrap the whole thing in grad to get gradients. You write the core logic once, and the transformations handle the parallelism, the acceleration, and the calculus. This is especially effective for scientific machine learning: you write the physics simulation (finite difference solver, ODE integrator) in a handful of lines of NumPy-like code. Then you can instantly ask for gradients through the entire simulation so you can optimize a parameter (like material properties) to match experimental data. You cannot do this easily in PyTorch because it wasn't designed for these kinds of intricate transformations and compositions.

The ecosystem around JAX is growing rapidly. Libraries like Optax provide off-the-shelf optimizers (Adam, SGD, etc.) so you don't write gradient descent by hand. Diffrax lets you train neural differential equations—neural networks that are built into physics equations. DeepXDE helps you solve physics-informed neural networks. JAX MD does molecular dynamics. The fact that JAX is built on composable transformations means that once you implement one new technique, you get automatic differentiation through it, automatic parallelization, automatic compilation, all for free. This is why AlphaFold (which predicts protein 3D structure), Gemini (Google's large language model), and cutting-edge climate simulation all use JAX.

Key ideas in plain words

  • Accelerated arrays: JAX uses XLA to compile Python array operations to run on GPUs, making matrix math 100+ times faster by exploiting GPU parallelism.
  • Program transformation: JAX can rewrite your Python functions into new functions that compute related quantities (derivatives, batches, compiled versions) without you having to rewrite the logic.
  • Automatic differentiation (grad): turns a function into a new function that computes its gradient using the chain rule, composable so you can take derivatives of derivatives.
  • Vectorization (vmap): turns a scalar function into a batched function that processes many examples in parallel using matrix operations instead of loops.
  • Just-in-time compilation (jit): rewrites your function to fuse operations and minimize GPU memory traffic, typically 5–8x speedup but with upfront compilation cost.
  • Composability: transformations can be chained together (grad ∘ vmap ∘ jit), so you write core logic once and get multiple capabilities automatically.
  • Functional purity: JAX functions should be stateless and deterministic; no hidden side effects means transformations can safely reorder and fuse operations.

Worked intuition: Let's trace through a real example: linear regression with gradient descent. You write a forward function f(w, b, x) = w*x + b that takes weight w, bias b, and a single data point x, and returns a prediction. Then you vmap it: f_batch = vmap(f, in_axes=(None, None, 0)), meaning don't parallelize over w and b, but parallelize over x. Now f_batch(w, b, [x1, x2, x3]) returns [f(w,b,x1), f(w,b,x2), f(w,b,x3)] using a matrix multiply under the hood. Next, you define a loss function that calls f_batch, computes mean squared error. You ask for grad_loss = grad(loss_fn), which returns a function that computes dL/dw and dL/db. Then you compile the update step with jit. Now inside a for loop (which runs in Python, not JAX), you call the compiled jitted gradient update 1,000 times. The first call pays a 2-second compilation cost. The next 999 calls each take 1 millisecond because the GPU has a fused kernel ready. Total time: ~2 seconds for 1,000 steps. If you tried to do this naively in Python with explicit loops, it would take minutes.

Where it breaks down: JAX has real constraints. First, your code must be pure: no print statements, no random number generation (you must pass a random key explicitly), no if/else based on data values (only on static shapes known at compile time). This is because JAX needs to trace through code to build its intermediate representation, and side effects break that. Second, compilation is expensive and happens on the first call with a given input shape; if your function changes size, it recompiles. Third, JAX arrays are immutable (you cannot modify in place), which is fine for numerical code but feels weird if you are used to NumPy in-place operations. Fourth, JAX is not a complete replacement for scientific computing libraries; some things from SciPy do not have JAX equivalents yet, so you may need to use multiple tools. Finally, the error messages can be cryptic because errors can happen deep in the compiled code, not in your original Python.

Takeaway: JAX's core insight is that mathematical transformations (differentiation, parallelization, compilation) can be implemented as code-to-code rewrites of functions, not as runtime tricks. This makes your code simpler, faster, and more composable. You write the math once, and JAX automatically gives you derivatives, parallelism, and GPU speed.
