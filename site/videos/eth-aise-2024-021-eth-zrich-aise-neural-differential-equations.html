First-Principles Walkthrough

What this lecture is really about: Teaching Neural Networks to Act Like Differential Equations

The question it answers: What if we put neural networks inside differential equations to learn unknown physics, and what does that teach us about how neural networks themselves work? How can viewing neural networks as equation solvers help us design better architectures?

Something concrete to hold onto: Imagine trying to predict how a predator and prey population change over time. Instead of writing down the exact rules (which you only partly understand), you write a partial rule with a neural network filling in the blanks. The neural network learns what you didn't know. But here's the surprise: this idea reveals that ResNets (a standard neural network type) are secretly just solving differential equations one small step at a time.

The lecture starts with a concrete problem: we have real data showing predator and prey populations rising and falling over time, but the traditional equations we use to model this rely on simplifying assumptions that rarely hold in nature. Instead of guessing all the coefficients in our equations, what if we let a neural network learn the parts we don't understand? This is the core idea of a neural differential equation (NDE). You write down the structure you're confident about (e.g., 'the prey population changes based on predator population') but replace the exact function with a neural network that learns from data.

To actually solve an NDE, we use the same numerical methods as for regular differential equations. The simplest is Euler's method: break time into tiny steps, and at each step, ask the neural network 'what happens next?' and update the populations. This is simple to code: a for loop where inside each iteration you call the neural network. Crucially, because the entire forward pass (running the solver) is differentiable, you can use automatic differentiation to train the neural network by comparing its predictions to real data. The solver outputs the full trajectory through time, and you optimize the neural network weights to match what you actually observed.

Here's where it gets interesting. When you draw out the Euler solver as a diagram—showing how you take the current state, run it through the neural network, scale by a tiny time step, and add it back to the state—it looks exactly like a residual connection in a ResNet. That skip connection (adding input to output) is the same as the 'keep what you have and add a small change' principle of numerical integration. This means ResNets with millions of parameters are, in the limit of infinitely many thin layers, just solving a differential equation. Training a ResNet weights means learning the right-hand side of an ODE. This is a profound bridge between physics and machine learning: the architecture you use for image classification is secretly a discretized differential equation solver.

You can generalize this insight. Different numerical solvers (Runge-Kutta, implicit methods) produce different computational graphs, which are different neural network architectures. A 1D convolution layer, when stacked infinitely, solves a specific partial differential equation (PDE). This means you can ask the inverse question: what PDE does a given architecture solve? And more practically: if you know your data has oscillatory behavior, you could design a neural network based on the differential equation for coupled oscillators, giving it a physics-informed inductive bias without hand-coding features.

The lecture demonstrates this with human activity recognition. A smartwatch records acceleration (X, Y, Z components) while a person walks up stairs. Instead of using a generic LSTM or GRU, the researchers designed an RNN cell based on the coupled harmonic oscillator equation—the dynamics of multiple masses connected by springs. The hidden state represents the displacement and velocity of these coupled oscillators, and the network learns the spring constants and damping coefficients from data. When they plot what the hidden state does over time, it shows beautiful coupled oscillations, giving insight into what the network learned. Remarkably, this physics-inspired architecture works well not only on oscillatory data but also on non-oscillatory datasets like sentiment classification, suggesting the inductive bias generalizes.

A key insight emerges from comparing different approaches. If you tried to predict populations by training a neural network on time alone (ignoring the underlying differential equation), it would memorize the training data but fail badly on times it hasn't seen. But an NDE trained on one full cycle of oscillation generalizes much further because the network only ever sees inputs in its training range (the phase space is bounded), so any new time query falls back on inputs the network has encountered before. The structure of the differential equation—assuming a first-order rate-of-change form—adds strong physics constraints that prevent overfitting. This is why NDEs generalize so much better than naive neural networks on dynamical systems.

The distinction between NDEs and Physics-Informed Neural Networks (PINNs) matters. A PINN uses a neural network to approximate the solution to a differential equation (the output is the solution). An NDE puts a neural network inside the differential equation itself (the neural network is part of the right-hand side). So an NDE solver is a hybrid method: it's a numerical integrator with learned components. This opens a design space: you can keep parts of your equation fixed (because you're confident in the physics) and let neural networks learn only the mysterious pieces. You can also think of NDEs as surrogate models—they learn to mimic expensive simulators by learning the dynamics directly.

The training process is straightforward but effective. You start with initial conditions (known from your data), run the NDE solver forward in time, and compare the entire trajectory to observations. Automatic differentiation flows gradients through the entire solver, updating the neural network weights to minimize the difference. This works for very long time horizons because the solver is deterministic and differentiable. The neural network doesn't need to memorize a long sequence; it learns a compact representation of the dynamics that generates long sequences correctly. This is why NDEs are so sample-efficient compared to opaque model sequence models.

Key ideas in plain words

  • Neural Differential Equations embed learnable neural networks into differential equations, replacing unknown physics with learned functions while keeping the known structure intact.
  • Residual Networks (ResNets) are, in the continuous limit, just Euler solvers for differential equations—each residual block is one time step of numerical integration.
  • Different numerical methods (Euler, Runge-Kutta, implicit) correspond to different neural network architectures, so you can use knowledge of PDEs to design better neural networks.
  • NDEs generalize far beyond their training time horizon because they learn dynamics (the rules), not solutions (the answers), staying within the bounded phase space the network has seen.
  • By designing neural networks from differential equations that match your data (e.g., coupled oscillators for rhythmic signals), you inject physics domain knowledge without hard-coding features, improving both accuracy and interpretability.

Worked intuition: Consider predicting the motion of a pendulum swinging back and forth. A standard neural network trained on time values (0.0, 0.1, 0.2 seconds) to predict angle can nail the training interval but will be garbage at t=2.0 seconds because it only memorized angles for those specific times. An NDE learns the pendulum equation instead. It learns 'the acceleration is proportional to the negative angle (gravity pulling back)' and a damping term. Once trained on one swing cycle (0 to 5 seconds), it can predict 100 seconds forward because it's computing new positions from current position and velocity every tiny time step, following the learned dynamics. The hidden state (position and velocity) stays bounded between -90 and +90 degrees, so the network only queries inputs it has effectively seen during training. If you plot the learned hidden state over long time, you see the sinusoidal oscillations decay due to damping—the network's learned representation of the physics.

Where it breaks down: NDEs struggle with truly chaotic systems where tiny changes in initial conditions lead to wildly different long-term futures (sensitive dependence). They also require good physics assumptions; if you pick the wrong base equation (e.g., coupled oscillators for non-oscillatory data), you've added constraints that harm performance. Very long-term forecasting is still hard because small numerical errors in the solver accumulate. NDEs also require differentiable solvers, so you can't use adaptive step-size solvers (which are conditional and hard to backpropagate through) without special techniques. Finally, the interpretability benefit only works if your base equation is meaningful; wrapping a opaque model neural network in an ODE that gets discretized as an RNN doesn't magically make the weights interpretable, just more constrained.

Takeaway: Neural networks aren't just function approximators—they're fundamentally discretized differential equation solvers. By recognizing this, you can reverse-engineer better architectures from physical principles, make neural networks more sample-efficient on dynamical data, and gain insight into what hidden states actually represent. The same idea works in both directions: classical numerical methods inspire neural network design, and neural network innovations (like attention) can suggest new ways to solve PDEs.
