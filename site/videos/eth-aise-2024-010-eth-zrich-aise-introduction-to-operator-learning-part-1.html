First-Principles Walkthrough

What this lecture is really about: Learning to Solve Differential Equations as Opaque model Transformations

The question it answers: How can we teach a machine learning model to predict the solution to a differential equation without physically solving it, when the inputs and outputs are both infinite-dimensional functions rather than fixed-size numbers?

Something concrete to hold onto: Imagine you have a physical simulator (like a weather model or aerodynamic design tool) that takes a description of initial conditions or design parameters and outputs a intricate flow pattern. Running that simulator even once takes hours. Can you train a neural network to act like that simulator, so that after you've run it a few times, the network can instantly predict new outputs without the expensive computation?

At its heart, solving a differential equation (a PDE) is a transformation: it takes inputs—like material properties, source terms, or initial conditions—and produces outputs, which are solutions spread across space and time. The key insight is that these inputs and outputs are not single numbers; they are functions. A function is something defined at every point in space, so it cannot be fully captured by a finite list of numbers. When you describe a function, you need infinite information. Because of this fundamental fact, solving a PDE is really about learning an operator: a machine that takes a function as input and produces a function as output. This is fundamentally different from a standard neural network, which takes a finite list of numbers and outputs another finite list.

To see why this matters, consider a simple advection equation: if you start with some initial shape (a function of space) and let it move at constant velocity, the solution is just that shape shifted by a distance. The operator here is the 'shifting' operation. It takes any input function (like sine wave, exponential, or a square bump) and produces the shifted version. The remarkable part is that the same operator works for all possible input functions—it is universal in that sense. But because the input is infinite-dimensional (a full function), the operator must also handle infinite-dimensional output. You cannot describe a function using only ten numbers; you need it fully specified to capture all its details.

Now, how do you actually train a machine learning model on this? The practical trick is what the lecturer calls 'cheating.' Instead of trying to learn the operator on all possible functions (which is impossible), you restrict the problem. For instance, in aircraft wing design, you don't consider arbitrary wing shapes. Instead, you specify that any design is built by adjusting maybe twenty to fifty parameters—like thickness at different points along the wing—starting from a reference shape. Suddenly, your input becomes finite-dimensional: it is just those twenty to fifty numbers. Similarly, you can restrict your outputs: instead of predicting the full fluid flow everywhere, you might predict pressure at specific points or overall quantities like lift and drag. With this restriction, the problem transforms from 'infinite-to-infinite' into something like 'finite-to-finite,' and now you can use standard deep neural networks.

Once you have restricted the problem this way, the training procedure is straightforward. You randomly generate many design parameters within the allowed range (say, one thousand different wing designs). For each, you run an expensive simulation (perhaps an aerodynamic solver taking one to two minutes per run) and record the outputs. After you have collected this dataset—pairing each set of input parameters with its resulting solution—you train a neural network to predict the outputs given the inputs. The network learns the relationship by fitting to your data using standard stochastic gradient descent. From the mathematician's perspective, this works because universal approximation theorems guarantee that a neural network can learn any continuous mapping, given enough capacity and data. The map from finite-dimensional inputs to finite-dimensional outputs is a standard machine learning problem.

However, there is a price. Even though approximation error—the error from the network's inability to represent the true solution exactly—is not the main bottleneck (solutions to PDEs have useful structure and regularity that allows neural networks to learn them efficiently), the generalization error is. When your training data is drawn randomly, the gap between how well the network performs on seen data and unseen data is roughly inversely proportional to the square root of the number of samples. This square-root dependence is brutal when your single simulation takes minutes to hours. If you want 1% accuracy and your data varies over a range of, say, 100, then you need the square-root of your sample size to be 100, meaning you need 10,000 samples. If each sample costs 2 minutes of computation, that is 20,000 minutes—more than two weeks of continuous computing. In three-dimensional problems, a single simulation can take hours or even days, making this completely infeasible.

This is the core challenge the lecture poses: we live in a data-poor regime. Unlike the big-data success stories of modern machine learning (where billions of images or text samples are available), scientific computing offers perhaps hundreds of simulations—not thousands or millions. The 'cheating' approach breaks down precisely because you cannot afford to generate enough training data. The gap between what the theory says you need (10,000 samples) and what you can realistically afford (maybe 100 or 1,000) is the chasm that the rest of the course will address. The question becomes: how do you use machine learning when data is expensive and scarce, not abundant?

Understanding the operator perspective is the entry point to this challenge. By recognizing that PDEs are input-output transformations operating on functions, we can think clearly about what it means to approximate them. The restriction to finite dimensions—the 'cheating'—makes the problem tractable in principle but reveals the real bottleneck: data efficiency. Moving forward, the course will explore ways to use physics-based constraints, symmetries, and other structural properties to learn operators from relatively few expensive simulations.

Key ideas in plain words

  • Operators are input-output transformations on infinite-dimensional spaces (functions): Unlike neural networks that map fixed-size numerical inputs to fixed-size numerical outputs, PDEs map full functions (defined everywhere in space) to other full functions. These transformations are called operators.
  • Solving a PDE is equivalent to learning the operator: Finding the solution to a PDE given some input parameters (material properties, initial conditions, etc.) is the same as learning the operator that transforms inputs to outputs. This reframes PDE solving as a machine learning task.
  • The finite-dimensional restriction or 'cheating': You make the problem tractable by assuming your inputs belong to a restricted class (parameterized by finitely many numbers), like wing designs defined by twenty parameters. This converts the infinite-dimensional operator learning problem into a standard finite-dimensional regression task that deep neural networks can handle.
  • Universal approximation provides a theoretical guarantee: Theorems guarantee that shallow neural networks can approximate any continuous mapping to arbitrary precision. This means that in principle, the network can learn to approximate the operator—but only if you have enough data and training capacity.
  • Sample difficulty and the square-root barrier: The generalization error (gap between training and test performance) scales roughly as inverse square-root of the number of samples. This means you need many samples to achieve high accuracy, which is catastrophic when each sample requires an expensive simulation—often 10,000+ samples when you can only afford 100 to 1,000.
  • Data poverty is the binding constraint: Science and engineering have the opposite problem from Internet-scale machine learning. You have scarce, expensive data (simulations taking minutes to hours each) rather than abundant cheap data (like photos). This regime requires fundamentally different strategies than standard deep learning.

Worked intuition: Imagine you are designing an airplane wing. A wing's shape is described by its profile at each position—but you could specify it using just twenty parameters (thickness here, curve there, angle elsewhere). Now, for a given wing (specified by those twenty numbers), you want to predict the air pressure distribution around it and ultimately the lift and drag. Running a fluid simulator once takes 2 minutes. You run it on, say, 200 random wing designs and collect 200 data points pairing each design (twenty numbers) with its pressure field and performance (twenty outputs, say: lift, drag, and eighteen pressure values at key points). Now you train a neural network: input the twenty design parameters, the network predicts the twenty outputs. The network learns the pattern from your 200 examples. Once trained, predicting a new design takes milliseconds instead of two minutes. This works because the network has learned a smooth approximation to the relationship between designs and their aerodynamic behavior. However, if you wanted higher accuracy (say, to predict 500 pressure values instead of 18), you would need a lot more training data—perhaps thousands of expensive simulations. This is the bottleneck: the operator (the true relationship between wing shape and airflow) requires many samples to learn accurately when data is costly.

Where it breaks down: The approach breaks down in three ways. First, if your restricted input space does not actually contain the solutions you care about (e.g., your wing design parameters cannot represent the optimal shape), the network cannot learn to find it, no matter how much data you have. Second, if you want high accuracy on the full field solution (not just a few summary numbers), the output becomes very high-dimensional, and you need even more data—the curse of dimensionality. Third, and most fundamentally, the data cost is prohibitive: achieving 1% error on a realistic aerodynamics problem might require 10,000 simulations; if each costs one hour, that is more than a year of computing. Scientific problems are data-poor by nature. The next lectures address this by using physics-based constraints and structure to learn operators with far fewer samples than the naive 'neural network on restricted inputs' approach requires.

Takeaway: Solving a PDE is fundamentally an operator learning problem: you are learning an input-output transformation on infinite-dimensional function spaces. The practical trick of restricting to finite dimensions lets you use standard neural networks, but it reveals the real constraint: you need expensive simulations, so your data is sparse. This incompatibility between the statistical sample difficulty required and the computational budget available is the core challenge that motivates data-efficient operator learning methods.
