First-Principles Walkthrough

What this lecture is really about: Learning operators with transformers: using attention to solve PDEs

The question it answers: How do we scale up neural networks to learn mathematical operators for PDEs when simpler convolutional architectures hit data-efficiency walls? What special trick lets transformers work on 2D and 3D problems despite their expensive all-to-all computations?

Something concrete to hold onto: Imagine you're trying to teach a neural network to predict how heat spreads through a material. You need thousands of training simulations—each one costing real money. Then someone invents a better "brain" (transformer with attention) that learns from fewer examples. But this brain is also expensive to run. The lecture shows you what attention does, why it works, and how to make it practical.

We start with a scaling problem: neural networks for PDEs (equations of physics) follow a known rule. Their error gets smaller as we add more training data, but only slowly—like the square root of the amount of data. This is actually a law of nature called the central limit theorem, not a bug we can fix. To get 1% error, you need roughly 10,000 samples. For expensive physics simulations, that's often $10 million to $30 million just to generate training data. This is why we need smarter architectures.

Previous architectures (FNO and CNO) use convolution—a local operation that mixes information from nearby points. They work reasonably well but all pay the same price for data. The question becomes: can we change the constants (make them better) rather than change the fundamental scaling rate? The answer comes from language models: they switched from RNNs to transformers and got a 5x efficiency gain on the same data-scaling curve.

Enter attention, the core of transformers. At each point in space, we want to update its value by collecting information from all other points. Unlike convolution, attention gathers signal from everywhere, but it's smart about which parts matter. For a point at location x, we compute 'weights' between it and every other point y: we transform each point's features through learnable matrices (called Query and Key), compute their similarity, apply softmax to turn it into a probability-like weight, and use those weights to aggregate values. This is a nonlinear kernel—it depends on the actual data values, not just distances.

The brilliance is that this weighting is computed via a soft softmax operation that turns dot products between transformed features into a valid probability distribution. We then take a weighted average of transformed values (through another learnable matrix, the Value matrix). All the learnable pieces—Query, Key, Value, Output matrices—are applied pointwise; they don't mix information spatially themselves. Only the weighting part (computed from comparing queries to keys) creates global coupling. Multi-head attention just runs this computation multiple times with different learnable parameters and concatenates the results.

Transformers aren't just attention, though. Attention alone is a gentle nonlinearity (softmax just normalizes). To approximate arbitrary operators, we also need strong pointwise nonlinearities. This comes from a feed-forward network (MLP) applied at every point: linear transformation to hidden features, activation function like ReLU, then back to the original dimension. Stacking attention and MLP blocks with layer normalization and skip connections gives universal approximation power. One transformer block does: layer norm → multi-head attention → skip connection → layer norm → MLP → skip connection. Stack many blocks.

There's a critical catch: transformers are permutation-invariant. If you shuffle the spatial order of all your points, the output doesn't change—because softmax over all pairs and summation don't care about order. But physics and images do care about position. If you shuffle all pixels in an image, the picture looks like chaos, not a rearrangement of the same image. So we need positional encodings: learnable vectors (or fixed sinusoidal patterns) that tell the network 'this is point number 47' or 'this point is 5 units from the reference'. These are added to each point's input before processing. Now the network knows where it is.

The final scaling problem: attention costs order of K-squared in compute, where K is the number of points. For 1D with 100 points, that's 10,000 ops per block—fine. For 2D (100×100 = 10,000 points), it's 100 million per block. For 3D (100×100×100 = 1 million points), it's a trillion—infeasible. The solution is learned local averaging via patching (also called patchification). Instead of attending to every point, divide the domain into patches (small cells), compute a weighted average over each patch to create one representative token, then run attention on the K/P-squared tokens, where P is patch size. A 100×100 image with 10×10 patches becomes 100 tokens; attention now costs only 10,000 ops. The trick is that patches compress information lossily but acceptably for many problems.

This patching strategy is the vision transformer design: input → patch embeddings (learned local averages with position info for each patch) → transformer blocks → output. The accuracy-vs-compute tradeoff is real: large patches reduce compute but lose fine detail; small patches preserve detail but blow up compute. Most practitioners find 8×8 patches the practical sweet spot for many PDE problems. In 3D, this becomes more delicate, but the idea stands: compress via learned aggregation, then use transformer attention on the compressed representation. The entire lecture builds to this: data-efficient learning via nonlinear weighting (attention) made practical via spatial compression (patching).

Key ideas in plain words

  • Operator learning via neural networks hits a square-root data-scaling wall (from probability theory), not improvable in general; we improve the constant instead.
  • Attention is a data-dependent nonlinear kernel integral operator: it aggregates information from all points, but the weights depend on feature similarity, not just spatial distance.
  • Softmax normalizes the weights to probabilities; pointwise MLPs provide universal approximation; layer norms and skip connections stabilize training.
  • Transformers are permutation-invariant by design, so positional encodings (learnable position indicators) are essential to tell the network where each point is.
  • Direct attention on dense grids is computationally infeasible in 2D+ (O(K²) difficulty), but patching (learned local averaging + coarse attention on patch tokens) makes it practical.
  • Vision transformers compress spatial detail via patches, reducing token count; you trade detail loss for compute. The patch size is the main dial: bigger patches → faster but less accurate; smaller patches → slower but finer.
  • The entire architecture (attention + MLP + norms + patches) is resolution-agnostic: a model trained on coarse grids can be applied to fine grids by recomputing patch embeddings on the new grid.

Worked intuition: Consider a simple 1D PDE: heat equation. You have 100 points in space. A FNO would convolve with neighbors (e.g., 5 points left/right). An attention-based operator computes, for every point i, a softmax-weighted sum of transformed values from all 100 points. The weights are learned: maybe point 47's value should strongly influence point 12 because they have correlated features, even if they're far apart. For a 1D sequence of 100 points, computing all pairwise similarities costs ~100×100 = 10K operations—very manageable. Now imagine a 2D air-temperature field on a 100×100 grid. Attention naively wants ~(10K)² = 100M ops. Instead, group the grid into 10×10 patches (100 patches total). For each patch, learn a weighted average of the 100 pixel values inside, producing a single token. Now apply attention to 100 tokens: ~100² = 10K ops again—feasible. You lose the ability to distinguish fine structure within patches, but for many PDE problems (especially coarse-grained ones), that detail isn't critical. If the ground-truth solution changes slowly spatially, patches capture it. If it has sharp corners at the pixel scale, patching fails.

Where it breaks down: The approach breaks when you need fine spatial resolution AND the physics cares about fine detail. High-frequency phenomena (sharp shocks, turbulence micro-scales) are averaged away by patching. On small domains or for 1D problems, patching offers no speedup and only loses information, so you'd use direct attention instead. Permutation-invariance (before positional encodings) means the raw attention mechanism cannot distinguish spatial structure; positional encodings are not learned automatically—they must be provided explicitly. With very small patch sizes (e.g., 2×2) in 3D, you're back to O(K²) difficulty. There's no universal patch size: a 16×16 patch works for low-resolution images but loses too much structure for high-resolution scientific data. Finally, vision transformers still require many samples to train well compared to, say, classical PDE solvers with physics constraints built in.

Takeaway: Transformers learn flexible, nonlinear operators via attention (all-to-all weighting of features), but the O(K²) cost is only practical with spatial compression (patching). Larger patches = faster, but less accurate. Smaller patches = slower, but finer. The choice of patch size is the critical dial balancing compute against information loss.
