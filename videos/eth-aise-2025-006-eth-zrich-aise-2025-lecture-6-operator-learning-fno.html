First-Principles Walkthrough

What this lecture is really about: Learning physical rules that work at any resolution with Fourier Neural Operators

The question it answers: How can we teach a neural network to learn the deep rules of a physical system (described by differential equations) in a way that works whether we sample it at 64 points or 128 points — or any other resolution?

Something concrete to hold onto: Imagine you have a video of a fluid swirling. A good prediction model shouldn't care if you show it a low-resolution video or a high-resolution video — it should know the actual physics of how fluids move, not just memorize a specific grid of numbers. That's the problem we're solving.

For the last two lectures, we tried teaching neural networks to solve differential equations directly using physics constraints. That failed because there are too many limitations. So we switched strategy: use real data and let the network learn from examples of input-to-output pairs. But we face a fundamental mismatch. A differential equation is an operator — a mapping from one infinite-dimensional function space to another. If I give it a different initial condition, I get a new solution. But standard neural networks only know how to map from finite vectors to finite vectors. If I train one on 256 numbers (a grid), it learns exactly that grid. Change the grid size to 512 or 128, and it breaks. This isn't just inefficiency — it means the network didn't actually learn the operator at all; it memorized a specific discrete representation.

The first idea was to use convolutional neural networks. Convolutions are clever: instead of a dense weight matrix connecting every input to every output, you use a small sliding kernel that moves across the domain. This kernel is the same everywhere you apply it. When you discretize a PDE on a grid, nearby points matter more than distant ones — fluids don't care about the exact grid spacing, only about relative positions. A CNN respects this locality. Better yet, you can train it on a 64×64 grid, then slide that same learned kernel across a 128×128 grid. Computation scales, and the model is actually shift-invariant — exactly what we want for a true operator. But when we tested this on Navier-Stokes flows, something terrible happened: train on 64×64 with 5% error, test on 32×32, and suddenly the error jumps to 25%. Change to 128×128, same explosion. The network hadn't learned the flow physics — it learned the discrete 64×64 representation. A PDE solution is a function, not a 4,096-dimensional vector. So our goal remains unsolved.

The real insight is to flip the problem: instead of discretizing the problem first (infinite → finite) then learning (finite domains), we do the opposite. Make the neural network itself infinite-dimensional from the start, then discretize only at the end for computation. This is called a neural operator. We extend each piece of a standard neural network to function spaces. Normally, a neural network layer is a matrix-vector multiply: output = A·input + b, where A is a learnable weight matrix and b is a bias vector. To lift this to functions, we replace the matrix-vector product with a kernel integral operator: output(x) = ∫ k(x,y) · input(y) dy + bias_function(x), where k is a learned kernel and the bias is now a learned function. The activation function is applied pointwise to the output at every location. This is mathematically clean and canonical — it's the obvious generalization of finite-dimensional neural networks to function spaces.

But here's the catch: computing those integrals naively is expensive. For each point x, you have to sum over all n points in the domain. That's n² operations per layer. With 10,000 points? 100 million operations per layer. With several layers, this becomes impossible. Around 2020, Zongyi Li and collaborators had a brilliant observation: physical systems have translation invariance. The laws of physics don't depend on where you stand. So the kernel k(x,y) only depends on the difference x−y, which means it's a convolution. Convolutions are expensive in physical space — but incredibly cheap in frequency space. In frequency space, convolution becomes multiplication. So here's the trick: take a Fourier transform of your input function to get its frequency content, multiply by a learned matrix in frequency space (O(n log n) with FFT), then take an inverse Fourier transform back to physical space. Because you only keep a fixed number of frequencies (say, 30 modes) — independent of grid resolution — the learnable part doesn't blow up when you change resolution. The Fourier transform itself is a fixed operation, not learned.

The full FNO layer works like this. You start with an input function sampled at n grid points. First, you lift it to a higher-dimensional feature space (channel mixing) by applying a learned matrix at each point independently — this is just a change of coordinates, not resolution-dependent. Then you take the discrete Fourier transform of these features, which produces a fixed number of frequency modes (e.g., 30, whether you have 64 points or 128). You multiply by a learnable weight matrix in frequency space, which mixes the frequencies together. You take the inverse Fourier transform to get back to the n points in physical space. Finally, you apply a pointwise activation function (ReLU or tanh). You repeat this Fourier layer several times, and at the end you project back down to your desired output channels. The magic is that the learnable matrix depends only on the number of frequency modes and channels — not the number of grid points. So you can apply the trained network to any resolution.

In principle, this solves the resolution problem: train on 64×64, test on 32×32, 128×128, or any size. But when the lecturer tried this on Navier-Stokes, something interesting appeared. At the training resolution (64×64), the error was 3.5%, excellent. But when going to higher resolution (super-resolution), the error crept up slightly. When going to lower resolution (sub-resolution), the error rose noticeably, though much less than with CNNs (which saw 25% jumps). Why doesn't it work perfectly? The reason is that the frequencies are cut off. A 64×64 grid can represent frequencies up to a limit; if the true solution has energy in frequencies beyond that cutoff, truncating them loses information. When you go to a finer grid, you can resolve those high frequencies, and the network has to make do without them. For smooth solutions of PDEs, high frequencies are naturally damped, so the error is small. But the network hasn't learned the true operator — it's learned a filtered, truncated version of it. This is an honest limitation, not a bug in the method.

FNO works well in practice because real PDEs naturally filter out high frequencies. Diffusion, viscosity, and other smoothing effects suppress noise and fine-scale wiggling. So even though theoretically the network sees a filtered problem, for physically realistic solutions the filter doesn't matter much. Mathematically, we can prove that FNO is a universal approximator of operators — just like standard neural networks are universal function approximators. If the true operator is continuous, FNO with enough layers and modes can approximate it arbitrarily well. But this is a theoretical guarantee; in practice, you still need to train on representative data, and you'll see the resolution-generalization issue for pathological operators (like random shuffling), even with FNO. The key insight is that FNO shifts the bottleneck from being resolution-dependent to being frequency-dependent, which is a huge practical win for physics-based learning.

Key ideas in plain words

  • Operator learning: Learn a mapping from one function space to another, not just from vectors to vectors. The learned rule should apply at any grid resolution.
  • Kernel integral operators: The infinite-dimensional analog of matrix-vector multiplication; convolve an input function with a learned kernel. Expensive naively, but manageable in frequency space.
  • Translation invariance: Physical laws don't depend on position, so the kernel only depends on differences. This turns expensive convolution into learnable multiplication in Fourier space.
  • Fixed frequency cutoff: FNO uses a fixed number of Fourier modes (e.g., 30) regardless of grid size. This makes the learnable parameters independent of resolution, enabling smooth evaluation at different grids.
  • FFT efficiency: Fourier transform of n points takes O(n log n) time with FFT. Naive quadratic kernel operations become linear in practice.
  • Residual learning: Training the difference between output and input (when they're in the same space) stabilizes learning and is applied throughout FNO.
  • Limitations and honesty: FNO works well for smooth, filtered solutions of PDEs where high frequencies don't matter. For pathological operators with full high-frequency content, resolution generalization still degrades. It's not magic, but a smart trade-off that matches the structure of physical problems.

Worked intuition: Consider the Navier-Stokes equation for a 2D fluid flow. You have an initial velocity field, and you want to predict the velocity at some later time. Normally, you'd sample the velocity on a 64×64 grid (4,096 numbers), feed it into an MLP that outputs 4,096 numbers at the next time step. If you then try a 128×128 grid, the MLP fails because it expects exactly 4,096 inputs. With FNO: (1) Sample the velocity on any grid, say 64×64. (2) Lift it to 16 channels per point (learning better coordinates). (3) Fourier transform each channel across space — you get 32 frequency modes (fixed, chosen once). (4) Multiply a learned 16×16 matrix that mixes the 32 modes at each frequency (learnable part). (5) Inverse Fourier transform back to 64 spatial points. (6) Apply ReLU pointwise. Repeat a few times. (7) Project back to 2 velocity components. Output is a velocity field on the 64×64 grid. Now test on 128×128: the first step gives you a lifted field at 128 points. The Fourier transform produces the same 32 frequency modes. The learned matrix still applies (it doesn't know or care about 64 vs 128). Inverse transform goes back to 128 spatial points. The activation and projection are pointwise, so they work at any grid size. The network literally doesn't see the difference in resolution — it only sees frequency modes and channels.

Where it breaks down: FNO is not truly resolution-invariant for all operators. The fixed frequency cutoff causes information loss when you evaluate at finer grids. High-frequency features that weren't present in the training data are ignored. For 'pathological' operators with no natural smoothing (like random permutations of points), FNO fails just as badly as CNNs when you change resolution. The theoretical guarantee of universal approximation doesn't guarantee that the network will *learn* the true operator — only that it *could* in principle if given enough layers, modes, and training. In practice, you need the operator to be 'nice' (e.g., smooth, with damped high frequencies) for the frequency truncation to not hurt generalization. Also, FNO is most natural on regular Cartesian grids. On irregular grids or non-Euclidean domains, you'd need to adapt the Fourier machinery significantly, or use other operator learning methods.

Takeaway: The real advance in FNO is making the learnable parameters independent of grid resolution by working in frequency space instead of physical space. You get a network that can be trained on one resolution and applied to any other, and it stays accurate when the underlying physics naturally suppresses high frequencies — which is almost all the PDEs we care about in science and engineering. It's not perfect operator learning, but it's close enough for real problems, and it's become the standard baseline.

Main Points Discussed

  • FNO learns an operator by moving field information through Fourier space.
  • The Fourier view helps carry large-scale field patterns without treating each point alone.
  • The method must still be tested when resolution, coefficients, forcing, or boundary conditions change.

First-principles point: A field has structure across space, so the model needs a way to carry information across the field.

Learner takeaway: Read FNO as a way to move information across a field, not as a formula to memorize.
