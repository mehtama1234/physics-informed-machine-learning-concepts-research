First-Principles Walkthrough

What this lecture is really about: Teaching machines to discover equations from data

The question it answers: Can AI automatically find the actual mathematical equations and physics laws that govern a system by looking at measurements and observations? Not just fit a curve, but discover the real formula?

Something concrete to hold onto: Imagine you observe a spring bouncing up and down over time. You measure its position at each moment. A neural network could memorize those bounces perfectly, but that doesn't tell you the underlying law. Symbolic regression tries to discover the actual equation—something like F = -kx—by searching through possible mathematical expressions to find which one matches your data.

Let's start with the core problem. You have real-world observations—maybe temperature readings, spring positions, or particle paths. You want to know the actual rule that produces those observations. There are two very different levels of understanding here: you could train a neural network to predict the next value in your sequence (function fitting), or you could discover the mathematical expression itself, like y = x·cos(π·x²). The second is what scientists care about because the formula is interpretable—you can understand *why* the system behaves that way, tweak parameters, and use it in new situations. But finding that formula is exponentially harder than just fitting.

Why is symbolic regression so difficult? First, the search space is absolutely enormous. If you think of a mathematical expression as a tree where each node is an operation (add, multiply, cosine, derivative) and the leaves are variables or constants, then with even a small library of operations, the number of possible trees grows like s^n—s operations and n depth, giving exponential combinations. With depth 10 and just three operations, you're already in the billions. Second, the search space is not smooth or continuous like the weights in a neural network. Change one operation symbol from multiply to divide, and the output changes drastically—there's no gradient to follow. Third, you'll always have multiple expressions that fit your finite data perfectly. If you have 10 measurements, you can always find a degree-9 polynomial that passes through all of them, but that won't generalize to new data. This is the classic overfitting problem on steroids.

The key insight is that you cannot search this exponential space by brute force. Instead, you must make assumptions (called priors) about what kinds of expressions to search for. One effective approach called AI Feynman looks for hidden simplicities in the target expression before searching. For example, every physical law has dimensional consistency—the units must work out on both sides. Newton's law F = G·m₁·m₂/r² only works because mass times mass divided by distance squared gives force. You can use dimensional analysis to transform a function of many variables into one of fewer variables automatically. Similarly, if a function is translationally symmetric (meaning it only depends on the difference between two positions, not the absolute positions), you can substitute that difference as a single new variable, again shrinking the search space. And if the function separates multiplicatively—like F equals one function of masses times another of distances—you can hunt for each part independently. By testing for these hidden simplifications using the actual data, you dramatically reduce what you need to search for.

Once you've pruned the search space with these tricks, you need a search algorithm. Genetic algorithms or evolutionary search are inspired by biology: you start with a random population of expression trees, score each one by how well it predicts your data, keep the best ones, mutate them (randomly change one operation), cross them with each other (swap subtrees between good candidates), remove the worst ones, and repeat. The heuristic is that if tree A is close to the true expression and you change just one operation, you might stumble onto the exact right operator. And if you take a good subtree from A and a good subtree from B and combine them, you might build something better than either parent. These operations don't guarantee finding the answer faster than brute force, but empirically they work well. The PySR library by Miles Krantz implements a sophisticated version: it runs the genetic algorithm on many parallel threads, periodically imports the best solutions into a shared population, uses tournaments to select parents, and randomly tries constant optimization (tuning numeric leaves) as well as mutations.

The final piece is handling finite data. Given n data points, there are always infinitely many expressions that fit perfectly—you could always add more and more difficulty. The solution mirrors what we do in deep learning: regularization. You assume the true expression is simple (Occam's Razor). This means you want short expressions, with few operations, simple constants, and few variables. You can encode this by adding a penalty term to your loss: score = (prediction error) + (penalty for difficulty). Then the search looks for expressions that fit well *and* stay simple. This balances the bias (assuming simple structure) with the variance (fitting the actual data).

Model discovery extends this to differential equations. If your dynamical system is described by dx/dt = F(x), and you have measurements of both the state x and its rate of change (velocity), then finding F is just symbolic regression with an extra operator: derivatives. The SINDy algorithm (Sparse Identification of Nonlinear Dynamics) makes a strong assumption: F is a sparse linear combination of basis functions. You pick a library—maybe {x, y, z, x², y·z, sin(x), ...}—compute all of those for your data, stack them into a matrix, and solve a linear regression problem with a sparsity penalty (like LASSO). This picks which library functions actually matter. For the Lorenz system, you might discover that dx/dt = σ(y - x), dy/dt = x(ρ - z) - y, dz/dt = xy - β·z. The linearity trick is effective: instead of searching over trees, you're just picking which terms to include. If you don't have direct access to the state—only video frames of a pendulum, say—you can learn an encoder neural network that translates images to state variables, then run SINDy on the latent state.

All of this rests on a fundamental recognition: no algorithm can search an exponential space exhaustively. Real success comes from encoding domain knowledge—simplicity, physical dimensions, symmetries, sparsity—as constraints and priors. The best algorithms blend multiple strategies: symbolic simplification tests (AI Feynman), evolutionary search with smart operators (genetic algorithms), structure assumptions (linear combinations with sparsity), and constant optimization. Different problems benefit from different combinations. What makes this field exciting is that it's not a competition between AI and human physicists—it's AI learning to ask the kinds of questions physicists have always asked: what is the simplest law that explains the observations?

Key ideas in plain words

  • Symbolic regression is discovering the actual mathematical formula from data, not just memorizing it. This is exponentially harder than function fitting because you're searching an combinatorial space of expression trees, not optimizing continuous weights.
  • The search space is enormous (roughly s^n possibilities for s operations and depth n) and not smooth—changing one symbol causes abrupt output changes. You cannot search by brute force; you must assume structure (priors) about which expressions to search.
  • Hidden simplicities like dimensional consistency, translational symmetry, and multiplicative separability let you automatically reduce the number of variables and terms—the AI Feynman approach tests for these using the data before committing to a full search.
  • Genetic or evolutionary algorithms are gradient-free search methods: mutate and cross-over promising expressions, keep the fittest (lowest error), repeat. Empirically effective even though no proof they're optimal; they encode the heuristic that similar expressions might work.
  • Regularization by expression difficulty (length, number of operations, constant size) is essential: without it, infinite expressions fit finite data perfectly. Balance fit with simplicity using a penalty term.
  • Model discovery for differential equations is often easier than general symbolic regression because of structure assumptions like sparsity: SINDy assumes the model is a sparse linear combination of basis functions, reducing the problem to sparse linear regression.
  • The takeaway for impact: successful algorithms blend domain knowledge (physics constraints, symmetries, sparsity) with clever search strategies. This is not human intuition replaced by AI, but AI learning to ask the structured questions that made human science effective.

Worked intuition: Take the function f(x) = x·cos(πx²) which the lecturer showed the class. A human observes the plot and sees oscillations that get tighter (frequency increasing) with amplitude growing linearly. You might hypothesize: oscillatory thing (cosine) with frequency growing (π times something with x), and amplitude growing (multiply by x). So you'd guess x·cos(something with x²). Fill in the blanks by fitting constants: x·cos(πx²). Now imagine a genetic algorithm starts with random trees like 'x + cos(x)' (wrong: frequency doesn't change). Fitness is low. It mutates to 'x · cos(x)' (better: now you have linear growth and oscillation). Still not quite right. It mutates the x inside cosine to x² (better: now frequency tightens). Someone else mutates to add π (now frequency is π·x²). Cross-over combines the best parts. Eventually, the population converges on the right answer. The algorithm never 'understands' what frequency means, but it scores expressions by error and rewards the small changes that reduce it.

Where it breaks down: Symbolic regression fails when the true expression is genuinely intricate—very deep trees, many variables, uncommon operations. It also struggles with high noise in data because the simplification tests (symmetry, dimensionality) become unreliable. If the true expression has no hidden structure (is not sparse, symmetric, or dimensionally clean), you're back to brute-force search. The genetic algorithm can also get stuck in local optima or explore the same bad regions. And fundamentally, with finite noisy data, many expressions may fit equally well, so the algorithm may discover a true solution but not *the* true solution. Finally, if you don't know or wrongly choose the operator library (e.g., you exclude 'tanh' and the real formula uses it), no amount of search will find the answer.

Takeaway: Symbolic regression is the problem of discovering actual equations from data—a challenge because the space of expressions is exponentially large and not smooth. Success requires encoding domain knowledge: assume simplicity, test for symmetries, use sparsity, build in physical constraints. Rather than brute force, use genetic algorithms or structure-aware methods like SINDy. The field shows that the most effective AI isn't raw search, but intelligent search guided by science.
