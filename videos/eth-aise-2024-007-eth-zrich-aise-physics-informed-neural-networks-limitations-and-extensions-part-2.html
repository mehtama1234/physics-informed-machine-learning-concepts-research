First-Principles Walkthrough

What this lecture is really about: Making Physics-Informed Neural Networks Actually Work: Three Hard Problems and Real Solutions

The question it answers: Physics-informed neural networks (PINNs) are effective, but standard ones are slow to train, struggle to converge, and choke on intricate problems. What can we actually do about it?

Something concrete to hold onto: Imagine you're trying to teach a neural network to simulate a seismic wave: it learns the starting condition fine but then gets stuck outputting zeros everywhere else—not because it's dumb, but because zeros satisfy the physics equation! Fixing this and scaling to real-world problems requires clever tricks.

Physics-informed neural networks sound great in theory: you give the network the differential equation (the mathematical rule describing how something evolves), and it learns to solve it without needing labeled data. But there are three big walls you hit in practice. First, standard PINNs are expensive to train because you have to compute derivatives of the network with respect to space and time at thousands of points for every training step. Second, they converge poorly—the optimizer gets stuck in bad local minima because the loss function has a fundamental tension: the boundary conditions (what happens at the edges) and the physics constraint (the differential equation itself) compete with each other, and the network often finds a 'trival' solution that makes one happy but breaks the other. Third, they don't scale: high-frequency solutions or multi-scale physics problems require the network to grow exponentially, and it still doesn't learn fast enough.

Let's dig into problem two first, since it's the most fundamental. A standard PINN loss function has two terms: one measuring how well the learned solution matches the boundary conditions, and another measuring how well it satisfies the differential equation (the residual). These are weighted by hand-chosen scalar values called lambdas. The problem is that there's a natural competition: a zero solution everywhere (except at boundaries) satisfies the physics residual perfectly across most of the domain, even if it doesn't match the true solution. The network gets pulled in two directions and often converges to the wrong place or moves very slowly. One fix is to use hard boundary conditions, a mathematical trick: instead of letting the network directly approximate the solution, you wrap it inside a custom-designed function (called an ansatz) that automatically satisfies the boundary conditions by construction. For example, if you multiply the network by a term that becomes zero at boundaries, then multiply by the initial condition, the network only has to minimize the physics loss—the boundary constraint vanishes from the loss function entirely, becoming a hard mathematical guarantee.

Another approach is adaptive lambda weighting. Instead of using the same weight for every point in space, you learn a separate lambda value for each training point, and you update these lambdas using gradient ascent (the opposite direction from weights). The key insight: the gradient of the loss with respect to lambda is just the residual itself, so high-residual regions automatically get higher weight during training. You're building an attention mask for the optimization landscape. A third technique is adaptive collocation point sampling: instead of sampling training points uniformly in space, you treat the current residual (the error in satisfying physics) as a probability distribution and sample more points where error is high. This is like mesh refinement in classical numerical methods but applied to neural networks.

Now for problem one—computational cost. A conditioning strategy works: add extra input channels to the network for problem parameters (like the location of an earthquake source). Train over many source locations at once. Once trained, a single network can generalize to new sources without retraining. Discretized PINNs take a different path: instead of the network outputting a solution at arbitrary coordinates, it predicts values on a fixed grid, and you use finite differences to compute derivatives. This lets you use convolutional architectures, which are faster, and reduces derivatives to simple grid arithmetic. The tradeoff is you lose the 'mesh-free' flexibility.

Problem three—scaling to intricate problems—hits a wall called spectral bias. Neural networks have an inbuilt preference: they learn low-frequency features quickly and high-frequency features slowly. When solving high-frequency waves or multi-scale phenomena, a standard network needs many more parameters, more collocation points, and much longer training, yet it still doesn't converge well. One solution is Fourier features: before feeding coordinates into the fully connected layers, transform them with sine and cosine functions at many frequencies, sampled from a normal distribution. This pre-processing gives the network an inductive bias toward periodic behavior and improves convergence on high-frequency problems—though you still have to guess which frequency range matters.

A more effective fix is finite basis PINNs: split the solution domain into overlapping subdomains and place a small neural network in each. Crucially, you sum these networks together with smooth window functions that taper them to zero outside their subdomain. This summation is mathematically guaranteed to be continuous everywhere, and you can express it as a single custom ansatz—just another neural network architecture. By learning high-frequency solutions locally (at a small scale), the network avoids spectral bias. Each subdomain network only has to model one cycle of oscillation, which the network sees as 'stretched out' due to coordinate normalization. The computational cost is lower because many small networks take fewer operations than one large network. And you can parallelize across subdomains on multiple GPUs.

Beyond these three main limitations, researchers have invented dozens more extensions. You can solve fractional or stochastic PDEs, not just standard ones. You can use variational forms (weak formulations) instead of strong forms, making PINNs look more like finite element methods. You can add Bayesian neural networks to estimate uncertainty in your solution and in your data. Custom architectures abound: adaptive activation functions, sine activations, LSTMs, wavelet layers that decompose the solution as a sum of localized wavelets. One striking example: for elastic wave equations (modeling both compression and shear waves), an encoder-decoder architecture with wavelets outperforms standard PINNs by learning the amplitude and width of wave packets rather than raw displacements. There are also spun-up optimization tricks using neural tangent kernel theory to design better optimizers.

The upshot: a standard PINN is just the first step. Modern work combines many of these extensions together—adaptive lambdas plus domain decomposition plus Fourier features plus custom architectures—chosen based on what you're trying to solve. There's an entire software ecosystem now (Nvidia's Modulus, DeepXDE, PyTorch implementations) that makes these easy to access. The field is still moving fast, so it's an active area of research.

Key ideas in plain words

  • Hard boundary conditions via ansatze: wrap the network inside a mathematical function that automatically satisfies boundary constraints, converting a constrained optimization problem into an unconstrained one and removing the tug-of-war between boundary and physics losses.
  • Spectral bias is a bottleneck: neural networks learn low-frequency features first and high-frequency ones slowly, which means high-frequency solutions require huge networks and long training; Fourier features and domain decomposition are the main workarounds.
  • Finite basis PINNs: split the domain into overlapping subdomains, place a small network in each, sum them with window functions, and let coordinate normalization 'stretch' high-frequency oscillations into low-frequency ones locally—faster training, parallelizable, naturally continuous.
  • Adaptive lambda weighting and adaptive sampling: instead of hand-tuning weights or using uniform grids, learn where the residual is high and focus computational effort there, mirroring classical adaptive mesh refinement.
  • Conditioning and discretization: conditioning on extra parameters (like problem variants) lets one trained network generalize; discretized PINNs use grids and convolutions, trading flexibility for speed.
  • Uncertainty and Bayesian PINNs: frame the problem probabilistically with Gaussian priors and likelihoods, and sample from the posterior distribution of weights to get credible intervals on the solution and on inferred parameters.
  • Custom architectures encode physics knowledge: wavelet layers for wave equations, encoder-decoder designs, and sine activations directly bake in expected solution structure rather than forcing the network to rediscover it.

Worked intuition: Consider the 1D Burgers equation (modeling viscous fluid flow). You want the solution to start as a sine wave at time zero, and to be zero at the domain boundaries. A naive PIN loss has two competing terms: boundary loss and physics residual. Early in training, the network might just learn 'output zero everywhere'—this trivially satisfies the physics residual across most of the domain (zero derivatives are easy!) even though it violates the true initial condition. Hard boundary conditions fix this: you rewrite the solution as u(x,t) = (t-0)(x+1)(x-1)·NN(x,t) - sin(πx). When you plug in x = ±1 or t = 0, the bracketed terms become zero, so the whole expression automatically equals -sin(πx), exactly matching the boundary and initial conditions. Now the only loss term is the physics residual. The network can't cheat by outputting zeros—it must actually learn the dynamics.

Where it breaks down: Hard boundary conditions only work when you can write down a closed-form ansatz (a formula) that captures the boundary structure. For intricate geometries (flow around an airplane wing) this becomes tedious or impossible. Hard constraints also require you to know the boundary values in advance. Fourier features and domain decomposition don't cure spectral bias fundamentally—they just make it easier for the network to express what you tell it matters. You still have to guess or know ahead of time which frequencies are important. Finite basis PINNs require choosing subdomain sizes and overlap; poor choices hurt convergence. Adaptive sampling helps but increases computational overhead. Bayesian PINNs add significant cost (MCMC sampling). Most modern PINNs work best when you can combine multiple extensions intelligently for your specific problem—there's no universal plug-and-play solution.

Takeaway: Standard PINNs fail at scale because they pit boundary conditions against physics, they inherit neural networks' spectral bias, and they scale poorly; but none of these are show-stoppers. Hard constraints, adaptive weighting, domain decomposition, Fourier preprocessing, and custom architectures each solve pieces of the puzzle. Modern scientific machine learning is about mixing and matching these tools based on your problem. PINNs aren't a magic bullet—they're a toolkit that, used wisely, can solve large-scale scientific problems where classical numerics struggles.
