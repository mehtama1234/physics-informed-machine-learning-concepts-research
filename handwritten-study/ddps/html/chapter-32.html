Narrative chapter

Do Not Force Every New Problem Into An Image Network

Read This Chapter As One Claim

A neural network operation is a claim about how information should move. Convolutions worked for images because local pixel neighborhoods mattered, but scientific data may need graph, Fourier, mesh, sequence, or other movement rules.

Everyday problem A PDE field, protein structure, lattice, or material design is treated like an image because CNNs are familiar.
Shared promise Search over broader structured operations so the model can learn a data movement rule closer to the task.
Hidden danger Old architecture search can only rearrange a fixed menu, so it cannot discover the missing operation a new domain needs.
First rejection test Reject the architecture if it only wins on familiar image assumptions and fails resolution, structure, cost, or domain-transfer tests.

This chapter uses video 35, Misha Khodak's DDPS talk on automatic architecture design for emerging machine learning tasks. The talk asks a simple question: if deep learning worked well for images and text because people designed the right network moves for those domains, what do we do for scientific tasks where the right moves are not obvious yet?

The first-principles point is that a neural network is not only a pile of numbers. It is a chosen way of moving information. In an image network, a convolution says, "nearby pixels matter together." That is a useful assumption for pictures. But a PDE field, a protein graph, a music sequence, or a plasma measurement may not obey the same neighborhood story.

image pixels have local neighborhoods
PDE fields may need global modes
graphs follow edges
proteins and sequences have other structure

Why Architecture Matters

A neural architecture is the wiring plan of the model. It says which blocks are connected, what operation sits on each connection, and how signals are combined. The weights are learned during training, but the architecture decides what kinds of patterns are easy or hard to learn.

Convolutions helped vision because they reused small local filters across an image. Residual connections helped deep networks because they let information skip around blocks instead of being forced through every transformation. Transformers helped text and protein work because they let different parts of a sequence attend to each other. These were not just parameter choices. They were new ways to move information.

operation on an edge
which edges exist
how branches combine
what patterns become easy

The Old Search Was Too Narrow

Classical neural architecture search often starts with a small menu of known operations. Pick a three-by-three convolution here, a five-by-five convolution there, maybe pooling, identity, or no connection. This can improve image networks, because the menu already contains image-friendly operations.

But this is weak automation for new scientific domains. If the right operation is not on the menu, the search cannot discover it. It can only rearrange old ingredients. That is like asking a cook to invent a new cuisine but giving them only bread, cheese, and tomato sauce.

known operation menu
search where to place each one
works when menu fits domain
fails when the needed move is missing

The Talk Separates Topology From Operations

Topology means the shape of the network graph: which nodes connect, which skip links exist, which blocks repeat. Operation means the actual calculation on an edge: convolution, graph convolution, Fourier operator, pooling, identity, or something else.

The talk argues that many emerging tasks do not mainly need another way to connect the same old operations. They need a broader way to search for the operation itself. Once a useful operation is found, topology search can still matter. But first the model needs an operation family broad enough to include non-image behavior.

topology: where wires go
operation: what each wire does
old NAS mostly rewires known moves
XD searches for broader moves

The XD Idea In Plain Words

The proposed search space is called XD, for expressive diagonalization. The details use structured matrices, Fourier transforms, and kaleidoscope matrices. The simple picture is this: many useful linear operations can be written as "change coordinates, scale or mix in that coordinate system, then change back."

A convolution has this kind of hidden structure. Fourier neural operators also fit this picture. Some graph convolutions can fit because multiplying by a graph adjacency matrix is sparse. XD takes this pattern and makes the coordinate-changing pieces trainable, while keeping them structured enough to remain much cheaper than an arbitrary dense matrix.

change view of the data
apply a simple structured action
change back
train the operation family

Why This Is Not Just Another Big Matrix

If we allowed every operation to be a completely arbitrary matrix, the model would be too expensive and too unconstrained. It could memorize and become hard to train. XD uses structured matrices called K matrices. They are inspired by the fast Fourier transform's pattern of many small structured steps.

The point is to get a large search space without losing all discipline. The search space can include ordinary convolutions, dilated convolutions, some graph convolutions, and Fourier-neural-operator-like moves. It does not include everything. It does not directly include nonlinear activations, max pooling, or self-attention. But it is wider than a small hand-built convolution menu.

arbitrary dense matrix is too large
K matrix keeps fast structure
many linear operations fit
nonlinear operations need other tools

How The Model Is Trained

The practical pipeline is deliberately simple. Start with a normal convolutional network. Replace each convolution with an XD operation initialized to behave like that convolution. Then train both the usual model weights and the XD architecture parameters together.

This is different from many architecture-search methods that use a separate outer search loop or discrete choices. In this work, the architecture parameters are continuous. There is no final step where the method must round a soft choice into a hard operation. The network is trained as the operation changes.

start with CNN
replace convolutions with XD
warm-start as convolution
train weights and operation together

The PDE Example Shows Why This Matters

The PDE setting in the talk is operator learning from solver data. Sample many initial conditions, run a classical solver to get later states, and train a neural network to map the initial state to the later state. This can help when many similar PDE solves are needed, or when inverse problems need many forward predictions.

Ordinary CNNs can struggle here. As the grid resolution increases, the CNN error can get worse. That is a warning that "image-like local filters" are not automatically the right operation for physical fields. Fourier neural operators were designed for this kind of task and perform much better. The striking result in the talk is that XD, starting from convolutional structure, can learn operations that perform well across Burgers, Darcy flow, and Navier-Stokes benchmarks, sometimes slightly better than the custom Fourier neural operator baseline.

sample initial field
solver creates training answer
network predicts later field
operation must match physics data

Resolution Is A Stress Test

A useful scientific model should not collapse just because the grid gets finer. The talk shows CNN performance worsening as resolution increases on some PDE benchmarks. That makes sense from first principles: a fixed local image filter may not capture the right long-range or frequency behavior as the grid changes.

Fourier-style and XD-style operations are better suited to this because they can represent patterns in a transformed view of the field. For PDEs, waves, smooth modes, and global interactions can be easier to express in such views than with local image filters alone.

coarse grid may hide weakness
finer grid exposes operation mismatch
CNN error can rise
XD stays more consistent

Where It Helps And Where It Does Not

The talk is careful about scope. XD improves over CNN baselines on several emerging or less-studied tasks: PDE solving, protein distance prediction, permuted images, music modeling, and some sequence or time-series problems. It does not clearly improve ordinary image classification or audio classification, where convolutions already work well.

That is exactly the expected pattern if the method is doing something meaningful. In a mature domain, humans have already found strong operations. In a less mature domain, the operation search has more room to find a better move.

PDEs
proteins and graphs
unusual sequences
less gain on mature image tasks

The Cost Warning

XD is broader than a convolution, and that costs memory and time. The talk reports slower training and inference than CNNs or Fourier neural operators. This matters especially for large PDE data. A method that finds better operations but is too expensive may still be impractical.

The Q&A returns to this point. Possible fixes include better structured-matrix software, GPU-friendly alternatives, truncation, and search spaces that include Fourier neural operators more directly without carrying every convolutional possibility. The honest status is: the idea opens a useful direction, but large-scale scientific use still needs efficiency work.

broader operation family
more memory
slower training
needs faster implementation

How This Connects To Earlier Chapters

Earlier chapters asked how a model should respect physics, locality, nonlocality, topology, and moving fields. This chapter asks the matching architecture question. If the data lives on a grid, graph, sequence, frequency space, or physical mesh, what operation should the network use to move information?

For topology and material design, this matters because the input may not be a normal picture. A design can be a graph of components, a density field, a mesh, a lattice, or a set of constraints. Using a plain CNN because it is familiar may work as a baseline, but it may also force the problem into the wrong shape. Architecture design is the attempt to let the network operation match the data's natural structure.

physical mesh
graph or lattice
field or sequence
choose operation that fits

The Chapter In One Chain

First, deep learning succeeded in images and text partly because people found operations that fit those domains. Second, emerging scientific tasks often do not have such mature operations. Third, old architecture search mostly chooses from a small menu of known image-friendly operations. Fourth, that cannot discover a missing operation. Fifth, the talk separates network topology from the operation on each edge. Sixth, XD creates a broader continuous search space for linear operations using structured matrices. Seventh, it starts from convolutions but lets the operation move away during training. Eighth, this helps on PDE operator-learning tasks where CNNs can fail as resolution changes. Ninth, it also helps on several less-studied domains but not much on mature image/audio tasks. Tenth, the method is promising but must become faster and cheaper before it can handle the largest scientific workloads.

The chapter's core idea: do not assume the network move that worked for pictures is the right move for physics. The architecture should be allowed to learn a better way to move information for the data structure in front of it.
