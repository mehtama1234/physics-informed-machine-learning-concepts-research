Do Not Learn The Inverse Map Naked

Read This Chapter As One Claim

An inverse problem is already under pressure because sparse noisy measurements can point to many possible hidden causes. If the forward physics is known, the learned inverse map must use it as a check instead of guessing from data alone.

Everyday problem You see radar echoes, seismic traces, pollution readings, or temperature data and want the hidden object, source, or material.
Shared promise Use the known forward model to constrain the neural estimate and learn uncertainty around the answer.
Hidden danger Many hidden causes can match the same measurements, so a fast point estimate can be confidently wrong.
First rejection test Reject the inverse answer if pushing it through the forward model does not reproduce the measured data within stated uncertainty.

This chapter uses video 24, Tan Bui-Thanh's DDPS talk on model-constrained deep learning for inference, control, and uncertainty quantification. The main lesson is direct: inverse problems are already fragile, so a neural network should not be asked to solve them from data alone when a physical model is available.

An inverse problem runs the usual simulation story backward. In the forward problem, you know the object, source, material, or initial condition and predict measurements. In the inverse problem, you only have measurements and want to infer the hidden cause.

Forwardhidden cause -> predicted measurements
Inversemeasurements -> hidden cause

Why Inverse Problems Matter

The talk gives several examples. Radar measurements may be used to reconstruct an object. Seismic sensors may be used to infer earth material and fault structure. Pollution measurements at a few later times may be used to infer where contamination began. Temperature measurements may be used to infer material properties.

These are not academic puzzles. They are decision problems. If the inferred object, source, or material is wrong, the next decision can be wrong. That is why the talk cares not only about one best estimate, but also about uncertainty.

radar echo -> object shape
seismic motion -> earth interior
pollution readings -> source location
temperature data -> material property

The Ill-Posedness Problem

Inverse problems are often ill-posed. The hidden parameter can be a whole field with many degrees of freedom, while the observations are sparse and noisy. Many hidden causes may explain the same measurements. Small noise in the data can create large changes in the recovered answer.

Classical inverse methods add regularization or a prior. In everyday words, they say: among the many possible hidden causes, prefer ones that are not wild, not unstable, and not physically unreasonable.

large hidden field
few noisy measurements
many possible causes
regularization or prior

Why The Forward Solve Dominates Cost

A forward simulation is run once for one known input. An inverse solve calls the forward simulation many times while searching for the hidden input. If one forward solve is expensive, the inverse problem can become impractical.

This is where machine learning becomes tempting. If a trained model can replace repeated forward solves or learn a direct inverse map, inference could become much faster. But speed alone is not enough. A fast wrong inverse map is not useful.

one forward solve
many forward solves inside inverse search
learned surrogate can reduce repeated cost

The Data-Only Attempt

The first approach in the talk is deliberately simple: train a neural network to map observations directly to parameters. This is the naked inverse map. It can produce answers, especially when the training set is huge and synthetic data is plentiful.

But the speaker's warning is important. The result is hard to interpret, data hungry, and sometimes behaves differently depending on architecture choices that are not physically transparent. In higher dimensions, the error can become much worse with the same amount of data.

observations
neural inverse map
hidden parameter estimate
data hungry and hard to interpret

The Autoencoder Version

The talk then considers an autoencoder-like structure. The observation is encoded into the parameter, and the parameter is decoded back to the observation. The latent variable is not arbitrary. It is forced to be the physical parameter.

This is better than a completely free latent space because the middle of the network has physical meaning. But it is still mostly data driven unless the actual forward model is imposed.

observation
encoder
physical parameter
decoder
reconstructed observation

Reduced Model Plus Neural Error Correction

The second main approach combines reduced-order modeling with deep learning. A reduced model keeps the physics but may have error because it uses a small basis. Instead of replacing the reduced model, the neural network learns a correction to the reduced-model error.

This is a powerful compromise. The reduced model is fast and physically structured. The neural correction improves accuracy. The talk shows heat conduction and neutron-transport examples where this hybrid gives better inverse estimates than a reduced model alone and better behavior than purely data-driven learning with the same data.

full model too slow
ROM fast but imperfect
neural net learns ROM error
fast corrected inverse solve

Model-Constrained Deep Learning

The third approach puts the actual forward model into training as a constraint or regularizer. If the network maps observations to a parameter, then pushing that parameter through the known forward model should reproduce the observations.

That is the central idea. The network is not judged only by whether it matches training parameters. It is also judged by whether its answer survives the physics check.

observation
network estimates parameter
known forward model
predicted observation
must match measured data

For linear inverse problems with linear neural networks, the talk shows that this model-constrained training connects back to traditional regularized inverse solutions. That matters because it makes the learned answer interpretable. It is not just a fitted machine; it behaves like a known inverse method in the simple case.

Equivalent Does Not Mean Identical

The talk introduces a useful idea for inverse problems. An estimated parameter can be considered equivalent if, when passed through the forward model, it produces the same observations as the true parameter. This is natural because inverse problems may not have a unique hidden cause.

The model-constrained approach can be analyzed in those terms. The point is not always to recover the one exact hidden field, especially when the data cannot determine it. The point is to recover a hidden field that is consistent with the physics and the observations.

true hidden cause
estimated hidden cause
same forward observations

Uncertainty: The Answer Needs A Width

The last major part of the talk moves to a variational Bayesian view. Instead of returning only one parameter estimate, the method learns an approximate posterior distribution: a mean and a covariance. In plain words, it tries to say both "here is the answer" and "here is how uncertain we are."

The key modification is that the variational autoencoder is model constrained. The network produces an approximate posterior, samples from it, pushes samples through the known forward model, and checks whether the predicted observations match the data. This adds a physics term that ordinary data-only variational learning would not have.

observation
network outputs mean and covariance
sample possible parameters
forward model checks data fit
answer plus uncertainty

Machine Learning Is Useful Only When Reused

The Q&A makes an important practical point. Training can be slow. If you only need one forward solve, machine learning is not worth it. It becomes useful when the trained map is reused many times: many inverse solves, many uncertainty samples, many control decisions, many parameter queries.

This is another version of the offline-online trade. Pay training cost once, then use the trained constrained map repeatedly. But this only makes sense if the error and uncertainty are acceptable for the decision.

expensive training
many future queries
worth it only if reused and trusted

Extrapolation Is Still Dangerous

The speaker is explicit that machine learning is weak for extrapolation. If the new case is outside the training regime, a data-only network can fail badly. Adding the mathematical model helps because the network has to satisfy more than interpolation through examples, but it does not make extrapolation automatically safe.

This is why uncertainty matters. A serious inverse model should not only give a point estimate. It should also say when the estimate is uncertain or when the data do not constrain the answer enough.

inside training family
physics constraint helps
outside family still needs caution

Why This Matters For Control And Design

Control and design often need hidden state estimates before deciding what to do next. Where is the contaminant source? What is the material property? What is the interior field? What is the uncertainty? A controller or optimizer that acts on a bad inverse estimate can make the wrong decision confidently.

For topology and design, the lesson is clear. If the design loop uses learned inverse or surrogate models, those models must be constrained by the physics and must expose uncertainty. Otherwise the optimizer may exploit a learned inverse map that looks fast but is not trustworthy.

measure
infer hidden state or parameter
quantify uncertainty
control or redesign

The Chapter In One Chain

First, inverse problems infer hidden causes from limited noisy measurements. Second, they are ill-posed because many hidden causes can explain the same data. Third, classical methods use regularization or priors to stabilize the answer. Fourth, direct data-only neural inverse maps are hard to interpret and need large data. Fifth, reduced models plus neural error correction keep physics while improving speed and accuracy. Sixth, model-constrained learning checks the network's estimate through the known forward model. Seventh, variational model-constrained learning adds uncertainty, which is essential for inference, control, and design decisions.

The chapter's core idea: if you know the forward physics, use it to constrain the learned inverse map; otherwise the network is guessing from fragile data alone.

How To Test Whether You Understood This Chapter

Explain why inverse is hard few noisy observations can be explained by many hidden causes, so the answer needs regularization, priors, or physics checks.
Explain the model constraint the network estimates a hidden parameter, the forward model predicts measurements from it, and training punishes disagreement with real measurements.
Reject the shortcut do not trust a learned inverse map unless it reports uncertainty and says where extrapolation or non-uniqueness can break the decision.
