Control The Equation While Learning What It Is

This chapter uses video 132, Alessandro Alla's DDPS talk on data-driven algorithms for online identification and control of partial differential equations. The plain problem is easy to state: you want to steer a physical system, but you do not fully know the equation that drives it.

That is different from the usual classroom control problem. In the usual version, the equation is given first. Then you design a control signal that pushes the state toward the target. Here the controller is partly blind. It can touch the system, watch the response, and update its guess. The talk asks whether identification and control can happen together instead of as two separate projects.

Read This Chapter As One Claim

The controller is not allowed to pretend it knows the whole equation. It must act, watch, learn, and act again. If the possible physics terms are known, it can estimate their coefficients while controlling the state. If the full problem is too incomplete for a normal solver, a PINN can combine sparse observations, residual structure, and boundary clues. The shared idea is that data should change the next control action, not merely explain the experiment afterward.

The Everyday Version

Imagine trying to drive a strange rental car down a steep road. You do not know how strong the brakes are. You do not know how much the steering lags. You do not know how the car reacts on wet pavement. A reckless driver would pretend the car is familiar. A careful driver presses the brake gently, watches the response, updates their sense of the car, and then chooses the next action.

This talk is the mathematical version of that careful behavior. The system is not a car but a PDE: heat spreading, fluid moving, a Burgers shock sharpening, or an Allen-Cahn state choosing between stable shapes. The control is not a foot on a pedal but a forcing term placed into the equation. The lesson is not "learn a model someday, then control it later." The lesson is "use each controlled motion as evidence about the equation, then improve the next control."

What Control Means Here

A PDE state is a changing field. It is not one number. It may be temperature along a rod, velocity over a region, concentration in a reactor, or displacement across a structure. To control it means to push that field toward a desired behavior. In the talk, the desired behavior is usually simple: drive the state toward zero, keep it stable, or make it follow a target.

The cost function is the scorekeeper. It penalizes a state that stays far from the target and a control that is too large. This is why the problem is not "use the strongest possible force." Strong control may fix the state but waste energy or damage the system. Weak control may be cheap but fail to move the state. The controller has to trade these against each other.

state is far from target
control can push it back
large control has a cost
best action balances both

The First Route: Known Menu, Unknown Amounts

The first half of the talk uses a sparse-identification idea. This is not discovery from nothing. The speaker assumes a library of possible PDE terms is known. The missing part is the coefficient in front of each term. In simple words, you know the possible ingredients but not the recipe amounts.

For example, the true equation may contain diffusion, advection, a Burgers nonlinear term, a third derivative term, or a polynomial reaction term. The method is allowed to choose how much of each term is present. If diffusion is present, its coefficient should become nonzero. If a candidate term is not part of the real equation, its coefficient should move near zero.

candidate terms are known
true coefficients are hidden
trajectory gives evidence
regression updates the coefficients

This matters because control needs the equation. If the controller thinks the system is mostly diffusive, it will act differently than if the system is dominated by advection or a nonlinear shock-forming term. A wrong coefficient can create a wrong control. The talk's first route says: do not wait for a perfect model offline. Keep estimating the coefficients while the system is being controlled.

The Online Loop

The loop has four steps. First, choose an initial guess for the unknown coefficients. Second, compute a feedback control from that guessed model. Third, apply the control and observe the actual trajectory. Fourth, use the observed trajectory to solve a regression problem for the coefficients. Then repeat until the coefficient estimate stops changing much.

The transcript connects this to a reinforcement-learning style assumption: the model is not fully known, but the system can be observed after an input is applied. The difference is that this method is not trying to collect many episodes before acting. It is trying to learn on the fly, from the trajectory it is already producing.

guess coefficients
solve state-dependent Riccati control
observe controlled trajectory
fit better coefficients

Why Riccati Equations Enter The Story

For linear systems with a quadratic cost, the linear quadratic regulator gives a clean feedback law. It comes from a Riccati equation. The talk starts there because it is the control workhorse: if the model is known and the cost is quadratic, the Riccati solution tells you how to turn the current state into a control action.

The PDE examples are nonlinear, so the speaker uses a state-dependent Riccati idea. At the current state, freeze the nonlinear system into a local form, solve a Riccati-like problem there, and use the resulting feedback control. This is suboptimal, not magic. It assumes that the value function looks locally quadratic. But it gives a practical controller for large nonlinear systems.

linear quadratic control has a Riccati recipe
nonlinear PDE has no one fixed matrix
freeze the current state locally
compute a usable feedback action

The computational pain is also clear. A discretized PDE can have thousands or tens of thousands of state variables. A Riccati equation over that state can become enormous. The talk mentions large dimensions and the need for efficient solvers such as Jacobian-free Newton-Krylov methods and, in related work, model reduction.

Concrete Case: Burgers-Type Dynamics

The viscous Burgers example is a good first mental picture. Burgers dynamics can create steep fronts, so it is not just smooth heat spreading. In the talk's first-part experiment, the method knows the possible terms but not their coefficients. It observes a trajectory, identifies that low diffusion and the Burgers nonlinearity are the active pieces, and keeps the other candidate terms near zero.

Then it compares three situations: uncontrolled motion, controlled motion when the equation is known, and controlled motion while the equation is being identified. The uncontrolled state behaves differently because no one is steering it. The controlled state with known dynamics is the best reference. The online identification-control result follows it closely after the early guess improves.

uncontrolled state keeps its natural motion
known model gives reference control
online method learns active terms
learned control nearly tracks reference

The First Route Breaks If The Menu Is Wrong

The question period makes the most important limit explicit. Sparse regression can only choose from the library it is given. If an essential term is missing from that library, the method may not recover the real equation. The speaker agrees with this. The method is not pure equation discovery from a blank page. It works in a setting where the structure is partly known and the coefficients are unknown.

That limit is not a small footnote. It is the first-principles boundary of the method. A controller can only be as honest as the model class it is allowed to use. If the real physical effect is absent from the candidate terms, the regression may fit the observations with the wrong explanation, and the control law may be trustworthy only inside the observed regime.

true physics includes a missing term
library cannot represent it
regression picks a misleading substitute
control may fail when conditions change

The Second Route: PINNs When The Problem Is Incomplete

The second half changes approach. Instead of the online sparse library loop, it uses physics-informed neural networks for identification and control. The speaker's reason is practical: sometimes the usual numerical method cannot even be set up because the problem description is incomplete. You may not know the boundary condition, the initial condition, the final condition, or a coefficient in the state equation.

A PINN is useful here because its loss can combine several weak pieces of information. It can fit sparse data, reduce the PDE residual, and match boundary observations if they exist. In the talk, the network is used not just to approximate a state but to identify an unknown parameter and then solve an optimal-control problem.

few observations are available
some problem data is missing
PDE residual adds structure
network estimates state, parameter, and control

The Two-Stage PINN Design

The PINN part uses two stages. In the first stage, the method uses data from the uncontrolled problem to identify the unknown part of the dynamics. This is more realistic because controlled data may not exist yet. In the second stage, after the coefficient is estimated, a new network is trained for the control problem. Its outputs include the state, the control, and the adjoint variable from the optimality system.

The adjoint is the backward-looking variable that tells the optimizer how changing the state affects the final cost. You do not need to treat it as mysterious. It is bookkeeping for blame. If the final error is too large, the adjoint carries information backward through the equation so the optimizer can adjust the control.

stage one: learn unknown coefficient from uncontrolled data
stage two: train state, control, and adjoint
compare against full numerical solution
test the PINN control inside the real solver

Concrete PINN Cases

The talk tests viscous Burgers and Allen-Cahn problems. In Burgers, the unknown parameter is the diffusion. Two regimes matter: a more diffusive case and an advection-dominated case. The advection-dominated case is harder because information moves and steepens instead of simply smoothing out. The method uses very few data points, no full initial condition, sparse boundary observations, and residual points inside the domain.

In Allen-Cahn, the uncontrolled system can settle toward stable states such as plus one or minus one. The control problem tries to push the state toward zero instead. That is a useful example because it shows control fighting the natural preference of the system. The network again identifies the unknown diffusion and learns a control that roughly matches the known-problem numerical reference.

Burgers: diffusion versus advection
Allen-Cahn: stable natural states
few data and sparse boundary points
control drives the state toward zero

The Speaker's Honest Warning About PINNs

The most useful part of the talk may be the caution. The speaker says that if the full PDE problem is known, classical numerical methods are usually better on speed and accuracy. PINNs do not automatically beat solvers. In his experiments, errors around 10 to the minus 2 or 10 to the minus 3 were acceptable for the study, but that is not the same as high-accuracy numerical simulation.

So the reason to use a PINN here is not fashion. The reason is that the ordinary solver needs a complete mathematical problem. If you do not know enough to give that complete problem, a PINN can fuse scattered clues: a few state measurements, a residual formula, partial boundary information, and an unknown parameter. When the full problem is known, use the solver. When the full problem is not known, the PINN may be the only workable starting point.

known full PDE: numerical solver wins
missing data: solver may not start
PINN combines partial evidence
validate before trusting the control

The Robotics Question

The Q and A asks whether the first approach could apply to robotics. The answer stays consistent with the rest of the talk. The hard part is not writing a feedback controller after a model has been chosen. The hard part is choosing a library of candidate dynamics. If robotic equations can be put into a useful state-dependent form and the candidate terms are sensible, the sparse-identification route may be doable. If the library is unknown, the method loses its foundation.

This is a good general lesson for design fields. Whether the system is a robot arm, a thermal device, a soft structure, a building flow path, or a topology-optimized material, the learning method needs a vocabulary. It must know what kinds of causes are allowed. A poor vocabulary can make the learned controller look confident while hiding the real cause.

The Design And Topology Connection

Topology and design problems often ask for control under uncertainty. You may change a channel network, a porous material, a heat-sink layout, a soft-robot body, or an actuator placement. Each change alters how signals move through the domain. The controller then needs to know which physical terms matter in that new shape.

The first route says: if you know the possible terms, learn the coefficients while steering. That could help when the geometry changes the strength of diffusion, transport, reaction, damping, or coupling. The second route says: if the geometry or experiment gives only partial observations, use sparse data plus residual structure to infer enough of the problem to control it. Both routes are about the same bigger need: design loops should not only predict what a shape does; they should learn how to act on that shape when the model is incomplete.

How This Connects To Earlier Chapters

This chapter connects directly to equation discovery, PINNs, reduced models, and control. It connects to Chapter 100 and Chapter 124 because it uses data to identify equations. It connects to the PINN chapters because it uses residuals and sparse observations when the problem is incomplete. It connects to the reduced-control chapters because full Riccati control for a discretized PDE can become too large unless efficient solvers or reduced models are used.

The new idea is the timing. Earlier chapters often separate learning and use: first build a surrogate, then deploy it. Here the system is being controlled while it is still being learned. That is why the word online matters. The model is not a static report. It is part of the act of steering.

The Boundary Of The Claim

The claim is not that the method can control any unknown PDE. It cannot. The sparse route needs a good candidate library. The state-dependent Riccati route is suboptimal and can be expensive. The PINN route can struggle with convergence, optimizer choice, cost, and accuracy. The transcript even discusses optimizer difficulties and suggestions such as alternatives to Adam or Adam plus LBFGS.

The honest claim is narrower and more useful: if the unknown part of the dynamics has a learnable form, and if the system can be observed while being acted on, then identification and control can be coupled. If the complete PDE problem is missing but partial data and residual structure exist, a PINN can help build a control solution where a standard solver has too little information.

not discovery from a blank page
not guaranteed optimal control
not a replacement for known solvers
use when missing dynamics blocks control

What You Should Remember

The heart of the lecture is simple: control requires a model, but sometimes the model is partly unknown. One answer is to learn the missing coefficients while the system is running. Another answer is to use a PINN when the PDE problem is too incomplete for a normal solver. Both answers treat data as something that should change the controller, not just decorate a paper after the fact.

If you remember only one sentence, remember this: do not steer a system as if you know the equation when the experiment is still telling you what the equation is. Watch, identify, control, recheck, and respect the limits of the model class you chose.
