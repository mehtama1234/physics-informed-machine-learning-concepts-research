Narrative chapter

Make The Network Learn The Detail It Missed

This chapter uses video 117, Qing-Yao Lai's DDPS talk on machine-precision neural networks for multiscale dynamics. The talk starts from a very concrete failure: neural networks can learn the smooth, large part of a physical field while missing the small, sharp, fast-changing detail. In weather, flow, and PDE problems, that missing detail is not cosmetic. It can grow during time rollout and make the model unstable or wrong.

The talk's main idea is simple enough to say without jargon. Do not force one neural network to learn everything at once. Let the first network learn the big easy part. Look at what it missed. Then train another network to learn that leftover error. Then repeat. Each stage is a repair job for the previous stage. With the right scaling, those repairs can push the error close to machine precision.

Read This Chapter As One Claim

Picture a weather map, a turbulent flow, or a stress field in a thin structure. The broad shape may be easy to see, but the small ripples, sharp gradients, and local hot spots can decide what happens next. A neural network often learns the broad smooth part first and leaves the fine part behind. This chapter says to stop treating that leftover as harmless noise. Measure what the first model missed, rescale it so the next model can actually see it, and keep adding focused correction stages until the small physical detail is no longer buried.

The Big Failure Is Blurry Physics

Machine-learning weather models can be impressive. After expensive training, they can forecast quickly and capture the large-scale wind pattern. But the speaker shows a problem in the spectrum: the model can match the low wave numbers while losing high wave numbers. In plain terms, it gets the broad shapes and loses the fine texture.

That matters because a physical field is not only its outline. In weather, small structures can affect later evolution. In turbulence, small scales can carry gradients and dissipation. In waves, a small phase or frequency error can grow. If a learned emulator is rolled forward step after step, each small missed detail becomes part of the next input. The model is then not merely blurry. It can drift, blow up, or become physically useless.

large weather pattern looks right
fine scales are smoothed out
rollout reuses its own errors
forecast can drift or blow up

Spectral Bias Means The Network Learns Low Frequencies First

The talk names the root difficulty as spectral bias. The everyday version is this: a neural network tends to learn slow, smooth variation before it learns fast wiggles. If the target function has both a broad hill and a tight ripple, the broad hill is usually learned first. The ripple takes much longer and may never be represented accurately enough in practical training.

The speaker gives a simple reason. During gradient descent, the learning signal for high frequencies can become very small. If the gradient is tiny, the optimizer has little push in the direction needed to learn those details. So adding more training steps or a bigger network is not automatically enough. The bottleneck is the way the network learns, not only the number of parameters it owns.

smooth part gives strong learning signal
fine wiggle gives weak signal
training appears stuck
high-frequency error remains

Scaling The Input Helps The Network See Finer Detail

One fix is to rescale the first layer weights with a factor the talk calls kappa. You can think of kappa as a zoom control for the input. If the network is trying to learn a high-frequency feature, the input needs to be scaled so the optimizer can feel that feature strongly enough.

This is related to Fourier features, but the implementation in the talk does not need to add cosine features in the same way. It uses a scaling factor and, in the strongest examples, a sine activation. The warning is important: larger kappa is not always better. Too much scaling can make the network overfit the training points and create false wiggles between them. There is an effective range, and it is connected to the dominant frequency in the thing being learned.

feature is too fine
increase input scaling
optimizer sees the detail
too much scaling makes false wiggles

The Multi-Stage Trick Is Error Peeling

The main algorithm is a multi-stage neural network. The first network gives a leading approximation. It may be wrong by about ten to the minus four. Instead of asking that same network to grind forever, the method computes the residual error and trains a second network on that error. The combined answer becomes first network plus a small correction from the second network.

Then the same thing happens again. The third network learns what the first two still missed. In the one-dimensional examples, the error drops from around ten to the minus four to ten to the minus eight, then ten to the minus eleven, then near ten to the minus thirteen. The later errors tend to have higher dominant frequency. So the stages behave like peeling: remove the big smooth layer first, then expose and learn the finer remaining layer.

stage 1 learns main function
stage 2 learns first residual
stage 3 learns smaller residual
combined error approaches machine precision

Why A Small Error Needs Its Own Scale

A later-stage error may be tiny in magnitude. If the neural network is asked to learn that tiny function directly, the training signal can be weak. The method therefore writes the correction as a small number times an order-one function. The small number carries the size of the correction, while the network learns a normal-sized shape.

This is the perturbation-theory flavor of the method. In first-principles language, it separates "how big is the correction?" from "what shape is the correction?" That separation makes the next network's job easier. It does not have to notice a tiny signal buried in the full solution. It is told to focus on the leftover shape at its own scale.

leftover error is tiny
estimate its size
learn a normal-sized shape
multiply back by the small scale

The Flow Snapshot Example Shows The Same Problem In Two Dimensions

The talk then moves from a one-dimensional toy function to a two-dimensional incompressible flow. The network takes coordinates as input and outputs a stream function. The first network already gives a good-looking field, but the error picture contains wiggles. In the spectrum, the usual pattern appears: low wave numbers are captured, high wave numbers are wrong.

After the second and third stages, the field error drops dramatically, and the energy spectrum of the neural representation lines up with the target spectrum much better. This is the key physical point: matching the picture by eye is not enough. A field can look right at large scale while having the wrong spectrum. The multi-stage method is trying to make the representation faithful across scales.

PINNs Have A Harder Version Of The Same Problem

The second major part asks whether this can help physics-informed neural networks. A PINN tries to represent a PDE solution with a neural network. It computes the PDE residual using automatic differentiation and trains the network so the residual and boundary errors are small.

The hard part is that, in a PDE solve, we usually do not know the true solution. In ordinary data fitting, the second stage can train on the known error: target minus prediction. For a PDE, there may be no target function. The talk's move is to use the previous stage's PDE residual as the source of information for the next stage. The equation itself tells us what the first network failed to satisfy.

true solution is unknown
first PINN leaves PDE residual
residual defines next correction problem
next stage reduces equation error

The Residual Gives Both Size And Frequency

The talk walks through simple ODE and PDE examples to show why the residual is enough to guide the next stage. The residual has a dominant frequency. That frequency is close to the dominant frequency of the solution error. The residual also has a magnitude. By balancing the dominant terms in the equation, the method estimates the size of the next correction.

For higher derivatives, the same idea changes by the derivative order. For nonlinear equations, the higher-stage correction can often be treated with a linearized equation because the correction is small. This does not mean nonlinear physics disappears. It means the leftover correction around the current approximation can be small enough that the next repair problem is effectively linear at leading order.

measure residual size
find residual frequency
estimate correction scale
train next-stage PDE correction

Why This Is Not A Replacement For Every Solver

The speaker is explicit that PINNs are usually more attractive for inverse problems than for ordinary forward solves. If all you need is a standard diffusion equation solved once, a classical numerical method will usually be faster and more reliable. The talk uses simple forward examples because they have exact solutions, which makes it possible to validate the method.

The real target is harder: problems where high precision matters, the unknown is not just a state but also a parameter or profile, and deriving a classical adjoint or solver workflow may be difficult. In those cases, a high-precision neural representation can be useful because it gives a smooth differentiable object while driving the equation residual very low.

The Euler Blow-Up Example Shows Why Precision Matters

The most ambitious example concerns the Euler equations, which are the Navier-Stokes equations with zero viscosity. A long-standing question is whether smooth finite-energy initial data can form a singularity in finite time. Near a possible blow-up, the smallest and largest length scales can span many orders of magnitude. That makes the problem extremely hard for direct numerical simulation.

The group reduces the problem into a self-similar domain and uses a multi-stage PINN to search for solution profiles and an unknown parameter. This is an inverse problem, not a normal time-forward solve. The speaker reports that the neural network found approximate smooth self-similar solutions showing singular behavior, with accuracy checked by substituting the result back into the equations and measuring the residual.

The Q&A Draws The Practical Boundaries

The Q&A keeps the method grounded. One question asks whether measuring error with stronger norms, such as including gradient error, might naturally emphasize high frequencies. The speaker says that is a good direction and that the current work mostly uses simpler error measures, with related gradient-enhanced PINN losses in some examples.

Another question asks whether simply adding many more parameters lets a network capture more frequencies. The speaker's answer is essentially no, not reliably. The architecture may have enough capacity, but the optimization path still controls what gets learned. Another question asks about collocation points in PINNs. The answer is that each stage still needs enough points; otherwise the limiting error comes from undersampling rather than from the network's spectral learning problem.

The stopping rule is another boundary. Many quantities can be automated, including estimating kappa from the previous residual. But deciding when to stop a stage is still partly manual in the current work. That matters for honest use: the algorithm is powerful, but it is not a push-button guarantee for every problem.

error norm changes what is emphasized
more parameters do not fix learning alone
collocation points must be dense enough
stage stopping still needs care

How This Connects To Topology And Design

Topology optimization often creates multiscale fields. A material-density field may have broad regions, thin members, holes, boundary layers, stress concentrations, or small flow features. If a surrogate smooths away those details, the optimizer may learn the wrong design lesson. It may remove a small structure that carries load, miss a small hot spot, or trust a flow prediction whose fine-scale spectrum is wrong.

The lesson from this talk is to inspect what the model misses, not just what it predicts. A first surrogate may get the broad response right. A second stage may need to learn the residual stress, residual temperature, residual pressure, or residual equation violation. In design, this could mean using staged networks to preserve small but important features, especially when the surrogate will be rolled forward, differentiated, or used inside an optimizer.

The warning is equally important. If the design problem is routine and a classical solver is cheap enough, use the solver. The staged neural method earns its place when the field is multiscale, high precision matters, inverse parameters are involved, and ordinary methods are too expensive or hard to differentiate through.

First, neural emulators can look right at large scale while missing fine-scale physical detail. Second, this happens because neural networks tend to learn low frequencies before high frequencies. Third, small missed details can grow during time rollout and make an emulator unstable or inaccurate. Fourth, input scaling through kappa helps the optimizer learn higher-frequency features, but too much scaling can overfit. Fifth, sine activations and scaling can improve high-frequency fitting. Sixth, a multi-stage network lets the first model learn the main function and later models learn the residual errors. Seventh, each residual is treated at its own size scale, so the later network learns a normal-sized correction rather than a tiny buried signal. Eighth, two-dimensional flow examples show that the method repairs high-wave-number spectral errors, not just visual errors. Ninth, for PINNs, the true solution is unavailable, so the previous PDE residual becomes the teacher for the next correction. Tenth, the residual provides both a dominant frequency and an estimated correction size. Eleventh, nonlinear equations can often yield a leading-order linear correction problem because the correction is small. Twelfth, the method is most useful for difficult inverse PDE problems, not routine forward solves. Thirteenth, the Euler example shows how high-precision neural representations can help search for multiscale singular solutions. Fourteenth, for topology and design, the practical lesson is to make the surrogate learn the detail it missed before trusting it inside an optimizer.

The chapter's core idea: when a neural network misses the fine physical detail, do not only make it bigger. Find the leftover error, scale it so it can be learned, and train the next stage to repair exactly what the previous stage failed to capture.
