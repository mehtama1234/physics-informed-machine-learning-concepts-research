Narrative chapter

Teach The Surrogate Its Slopes

Read This Chapter As One Claim

Start with a cheap surrogate placed inside a real decision loop. If the surrogate only says what the answer is, that may be enough for a dashboard. But if the surrogate is used to choose a better shape, infer a hidden field, place a sensor, or reduce risk, the decision algorithm asks a deeper question: which way should I move? That question is answered by derivatives. This chapter says a decision surrogate must learn both the value and the direction of change.

Everyday problem A fast PDE surrogate can predict outputs reasonably while still giving the wrong direction for optimization or inference.
Shared promise Train the neural operator on values and Jacobians so it knows how outputs change when input fields, sensors, controls, or designs change.
Hidden danger Small value error can hide a bad slope, and a bad slope can send a design optimizer or inverse solver toward the wrong answer.
First rejection test Use the surrogate inside the actual MAP, sensor-placement, or design loop; reject it if the chosen decision is worse than its value error suggested.

This chapter uses video 82, Peng Chen's DDPS talk on derivative-informed neural operators. The talk is about fast surrogate models for large PDE problems where uncertainty, inference, sensor placement, and optimization all depend on how outputs change when inputs change.

The first-principles question is this: if a cheap neural operator is going to replace an expensive PDE solver inside a decision loop, is it enough for it to predict the output accurately?

The lecture's answer is no. For many scientific decisions, the slope matters. An optimizer asks which direction improves the design. An inverse problem asks which parameter change would better match data. A sensor-placement rule asks which measurements reduce uncertainty. A surrogate that gets values roughly right but gives bad derivatives can send the whole decision process in the wrong direction.

expensive PDE model
learn fast surrogate
also learn derivatives
guide decisions

The Applications Are Decision Problems

The talk starts with three examples. In Antarctic ice-sheet inference, we want to infer an unknown basal sliding field from surface velocity observations. In tsunami warning, we want to choose where to place sensors so they reveal as much as possible about an earthquake and the resulting wave. In directed self-assembly of materials, we want to design substrates or guide posts so uncertain materials form a desired pattern instead of a defective one.

These are not one-shot prediction problems. They are decision problems under uncertainty. Each asks us to change a parameter, a sensor layout, or a design, then understand how the PDE-governed system responds.

infer ice sliding
place tsunami sensors
design material guides
make uncertain decision

The Same Pattern Sits Under All Three

Each example has a high-dimensional uncertain input. It might be a random field under an ice sheet, a fault slip process under the ocean, or uncertain material conditions. The PDE maps that input to a state, and then the state maps to a quantity we care about.

The repeated computational problem is that this map is expensive. If inference, experimental design, or optimization needs thousands of evaluations, the direct PDE solve becomes the bottleneck. A neural operator is a way to learn this map once and evaluate it quickly afterward.

uncertain input field
PDE solve
quantity of interest
decision loop

Projection Finds The Few Directions That Matter

The raw input and output spaces can be enormous. An input field may have thousands or millions of discrete values. But the map from input to output may depend strongly on only a smaller set of directions.

The talk uses reduced-basis architecture. The input is projected down before entering the neural network, and the output is represented in a reduced basis. For input projection, active subspaces use derivative information to find directions in parameter space where the output changes most. For output projection, POD or SVD finds dominant output shapes from snapshots.

huge input field
active input directions
small neural network
rebuild output field

Active Subspaces Are Not Just Compression

A plain PCA or Karhunen-Loeve basis can compress where the input field has large variance. But variance is not the same as influence. A direction can vary a lot and matter little to the output, or vary modestly and matter a great deal.

Active subspaces look at how the output changes with respect to the input. They use Jacobian information to identify directions that actually move the quantity of interest. That is why the lecture shows active-subspace projection outperforming ordinary input projection in the Helmholtz example.

input varies
output responds
Jacobian reveals influence
keep active directions

For Inference, The Slope Enters The Optimizer

Bayesian inference asks which parameter field best explains the data while staying consistent with the prior. The maximum a posteriori point is found by solving an optimization problem. That optimization uses gradients and often Hessian-like information.

If the neural operator replaces the PDE map, then its derivative replaces the PDE derivative. That derivative decides the step direction in the optimizer. Chen's derivative-informed neural operator adds a Jacobian term to the training loss so the surrogate learns not only the observable map but also its sensitivity.

data misfit
prior penalty
optimize MAP point
needs accurate Jacobian

Training On Values Alone Can Miss The Decision

The inference example shows the danger. A neural operator trained only on values can approximate the forward map, but its reduced Jacobian and resulting MAP point can be much less accurate. Adding Jacobian training improves the MAP result by a large margin in the example.

This is the practical lesson: the best surrogate for a decision task is not always the surrogate with the smallest value error. It is the surrogate whose errors are small in the quantities the decision algorithm uses.

value looks accurate
slope is wrong
optimizer follows bad direction
decision becomes inaccurate

Sensor Placement Needs Posterior Uncertainty

Optimal experimental design asks where sensors should go. In the tsunami example, that means choosing a small number of sensor locations from many candidates. A good sensor layout should reduce uncertainty as much as possible.

The uncertainty after observing data is summarized through posterior covariance. Computing that covariance uses Hessian or Gauss-Newton information, which again depends on Jacobians. So sensor placement is another place where the surrogate's slope matters.

many candidate sensors
choose a few
reduce posterior uncertainty
requires Jacobian

The Jacobian Is Harder To Compress

In the Q&A, Chen says derivative compression is usually harder than state compression. A state field is one object. A Jacobian is a large table of how many outputs change with respect to many inputs. It can carry more complicated structure.

The Jacobian neural operator therefore uses a two-layer compression idea. First, it projects input directions using an active subspace. Then it vectorizes the reduced Jacobian and applies another SVD-type compression. The point is to make a very large derivative object small enough to learn and reconstruct.

large derivative matrix
active input projection
SVD on Jacobian snapshots
learn compact derivative

Different Quantities May Need Different Bases

The talk makes a subtle point: the basis that is good for one task may not be good for another. For reconstructing the MAP point, PCA-like prior bases can work better. For reconstructing the Jacobian, active-subspace bases can work better.

This matters because "reduce the dimension" is not one universal operation. We must ask what quantity we are trying to preserve: the parameter itself, the output, the derivative, the trace of posterior covariance, or a determinant. Each may prefer a different projection.

rebuild parameter
approximate output
approximate derivative
choose basis by task

Optimization Under Uncertainty Needs Risk, Not Just Mean

The final application is stochastic optimization. The objective is uncertain because the input field is uncertain. The talk uses conditional value at risk, or CVaR, as a conservative risk measure. Instead of optimizing only the average outcome, CVaR cares about the bad tail of outcomes beyond a chosen quantile.

In plain words, a design is not judged only by what usually happens. It is also judged by what happens in the worse cases that are still plausible. That is crucial for engineering design, where rare failures may matter more than average performance.

uncertain objective
find bad tail
average tail loss
risk-aware design

The Flow-Control Example Shows The Payoff

In the Navier-Stokes flow-control example, the uncertain input is an inlet velocity field, and the design variable controls boundary velocity around a body. The objectives include reducing viscous dissipation or tracking a target velocity.

The derivative-informed neural operator is trained offline using PDE solves and Jacobian data. After training, it evaluates much faster than the PDE solver and can solve the optimization-under-uncertainty problem with far fewer total PDE solves. The lecture reports large speedups, especially in the 3D Navier-Stokes case where a single PDE solve is expensive.

expensive flow solve
train value and Jacobian
evaluate surrogate fast
optimize under uncertainty

Training Derivatives Costs Extra, But Not Too Much

A natural worry is that generating Jacobian data will be too expensive. The lecture explains that for the tested PDE problems, derivative data can be generated efficiently using linearized forward or adjoint solves. The same linearized operator can be factorized once and reused.

That means Jacobian training adds cost, but the added cost can be modest compared with the total benefit. Most of the offline cost still comes from generating PDE data, while training in the reduced space is relatively cheap.

solve PDE samples
linearized derivative solves
reuse factorization
cheap online decisions

Time-Dependent Problems Are Still Harder

In the Q&A, Chen notes that the presented examples are mainly steady input-output maps. Time-dependent problems are harder, especially wave propagation where low-dimensional reduced bases may not work as cleanly.

That boundary is important. A derivative-informed operator is powerful, but it is not finished for every case. If the output changes over time with moving fronts or waves, the reduced representation and the neural operator architecture may need different choices.

steady maps work well
waves move over time
basis may fail
new architecture needed

Why This Matters For Design And Topology

Design and topology optimization are full of derivative questions. If we move material here, change a boundary there, shift a sensor, move a guide post, or alter a shape, how does the objective change? A surrogate that cannot answer that question reliably is dangerous inside a design loop.

The directed self-assembly example is already topology-like. Guide posts and substrates are arranged so a material forms a target morphology. Because uncertainty can push the material into defective states, the design must account for risk, not only the best-looking deterministic outcome.

The broader lesson is that topology surrogates should be trained for the job they perform. If they are used only for fast visualization, value accuracy may be enough. If they are used to choose geometry, place sensors, infer hidden fields, or minimize risk, they must learn the relevant derivatives too.

predict objective

The Chapter In One Chain

First, large PDE problems appear inside inference, sensor placement, and optimization under uncertainty. Second, direct PDE solves are too expensive when the decision loop needs many evaluations. Third, neural operators can learn fast input-output maps. Fourth, high-dimensional inputs and outputs are projected to low-dimensional bases so the network can be small and trainable. Fifth, active subspaces use derivative information to keep input directions that matter to the output. Sixth, Bayesian inference needs accurate Jacobians because MAP optimization follows gradients and Hessian-like information. Seventh, value-only training can give a worse inferred parameter even when output errors look acceptable. Eighth, sensor placement needs posterior covariance, which also depends on Jacobians. Ninth, Jacobians are harder to compress than states, so a separate Jacobian neural operator uses layered compression. Tenth, different decision quantities may need different bases. Eleventh, optimization under uncertainty uses risk measures such as CVaR to protect against bad-tail outcomes. Twelfth, derivative-informed training improves flow-control optimization because it teaches the surrogate the directions the optimizer follows. Thirteenth, derivative data costs extra offline but can be generated efficiently with linearized solves. Fourteenth, time-dependent PDEs remain a harder extension. Fifteenth, topology and design need these tools because changing shape, layout, sensors, or controls is fundamentally a derivative-guided decision.

The chapter's core idea: a surrogate used for decisions must know more than the answer. It must know how the answer changes. Derivative-informed neural operators train the cheap model on both values and slopes so inverse problems, sensor choices, and design optimizers follow useful directions instead of polished but misleading predictions.

How To Test Whether You Understood This Chapter

Explain why values are not enough A value prediction answers "what happens here." A derivative answers "what changes if I move." Inference, sensor placement, and design optimization need the second answer.
Explain active subspaces Active subspaces keep input directions that actually change the output. They are different from ordinary variance compression because a direction can vary a lot while barely influencing the decision.
Explain why Jacobians are costly A Jacobian is a large table of how many outputs change with respect to many inputs. It is harder to store and learn than one state field, so it needs its own compression strategy.
Connect this to topology and design Topology optimization changes material layout, shape, sensors, or controls and follows gradients to improve the objective. A surrogate used there must learn the derivative directions that guide those changes, not only the displayed field values.
