Narrative chapter

Theory Is A Trouble Light

Read This Chapter As One Claim

Theory matters because "the neural method failed" is too vague to fix. A scientific model can fail because the model family cannot express the answer, the data do not identify it, or training never finds it. Each failure needs a different repair.

Everyday problem A physics-informed neural method looks reasonable, but the answer is wrong and nobody knows which part to blame.
Shared promise Use theory to separate model capacity, data coverage, boundary control, regularity control, and optimization behavior.
Hidden danger A small loss at sampled points can hide wild behavior between points, leaking boundary error, or stalled ReLU training.
First rejection test Reject the explanation if it says only "add physics" without saying whether approximation, estimation, or optimization is the bottleneck.

This chapter uses video 26, Yan Zhang Shin's DDPS talk on mathematical understanding of modern machine learning. The talk is theoretical, but the practical message is simple: when a neural method works or fails, we should be able to say which part failed.

That matters for this course because physics-informed machine learning is often sold as if adding an equation to a loss makes the method trustworthy. This talk pushes back. A method can have the right equation, the right data, and the right network size, and still fail because the training procedure gets stuck. Theory is the trouble light that says where to look.

model choice
data coverage
training path
theory tells which part is failing

The Black Box Problem

The talk begins from the modern success of machine learning: image models, AlphaGo, AlphaFold, scientific machine learning, digital twins, and physics-informed neural networks. But success alone is not understanding. If a model is going to help with cars, medical decisions, physical design, or engineering systems, trial and error is not enough.

The speaker's goal is not to remove experiments. The goal is to know why an experiment worked. If the model fails, did the chosen neural network lack the right shape? Did the data miss the important region? Did gradient descent stop in a bad place? These are different problems, and they need different fixes.

network could not represent the answer
finite data did not identify the answer
optimizer did not find the answer

Three Errors, Three Questions

The talk gives a clean way to split the problem. Imagine there is a true function you want: a PDE solution, a classifier, a forecast rule, or a physical response map. You choose a family of models, such as neural networks. Even before data appear, there is a question: can this family express the true function well? The leftover gap is approximation error.

Then data appear. You only see finitely many input-output examples or finitely many physics points. Even if the model family is good, limited data may point you toward the wrong member of the family. That is estimation error.

Finally, training happens. Gradient descent or another optimizer gives you the model it actually found. It may not find the best model allowed by the data and architecture. That is optimization error.

ApproximationCan this model family hold the answer?
EstimationDid the available data identify it?
OptimizationDid training actually reach it?

Why This Helps A Beginner

Without this split, every failure sounds the same: the neural network did not work. With the split, the failure becomes diagnosable. If approximation is the problem, use a richer model or a better representation. If estimation is the problem, collect better data, better physics points, or better coverage. If optimization is the problem, change training, initialization, architecture, or the solver used inside training.

This is the first-principles lesson. A machine learning method is not one object. It is a model class, a loss, data, and an optimizer glued together. A good course should teach those pieces separately before mixing them.

bad model family -> change representation
bad data coverage -> sample better
bad training path -> change optimization

PINNs Need A Convergence Question

The first technical part of the talk is about physics-informed neural networks. In a PINN, the network is trained so its output matches the PDE inside the domain and matches boundary data on the boundary. In plain words, the network is punished when it violates the equation and when it violates the edge conditions.

The natural question is: as we use more and more training points, do the trained PINNs converge to the real PDE solution? This is not a cosmetic question. If more data do not move the method toward the true solution, then the method is not reliable as a solver.

PDE rule inside the domain
boundary rule on the edge
more sampled points
should approach the real solution

The Hidden Word Is Control

The talk proves a convergence result for a regularized PINN loss. The details use mathematical tools, but the everyday meaning is control. It is not enough to make the loss small at sampled points. The method also needs a way to stop the network from wiggling wildly between those points.

That is what the regularization is doing. It keeps the learned function from behaving nicely at the checked points while becoming unreasonable elsewhere. The theorem says that under the right assumptions, with enough points and this kind of control, the learned PINN can converge to the PDE solution.

sampled point fits
regularization fence
behavior between points stays controlled

The Boundary Cannot Be Hand-Waved

A boundary condition says what happens on the edge of the domain: fixed temperature, fixed displacement, no-flow wall, known pressure, or another edge rule. Many classical numerical methods build boundary conditions directly into the approximation. A PINN may only penalize boundary mismatch in the loss.

That difference matters. If the boundary is not enforced exactly, the theory needs a way to control how boundary error affects the inside solution. The talk uses PDE tools for this. The beginner version is: if the edge rules leak, the inside answer can leak too.

edge rule
not exactly enforced
inside solution can drift

Optimization Is A Separate Battle

The second half of the talk moves from whether a good PINN exists to whether training can find it. This is the part beginners often miss. A neural network may be capable of representing the solution, and the data may be enough, but the training path may still stall.

The speaker studies gradient descent in simple ReLU networks. A ReLU is a bend: below a threshold it is flat, above a threshold it grows like a line. A network made of many such bends can approximate complicated shapes. But the bends have positions, and training changes those positions slowly or sometimes not at all.

line segment
bend
another line segment
training moves the bends

Why Training Looks Flat

The talk explains a plateau phenomenon. During training, the loss may drop quickly, then sit almost flat for a very long time, then suddenly drop again. A user may think training is finished during the flat part, but it may only be waiting for the network's activation pattern to change.

An activation pattern says which data points fall into which side of which ReLU bends. If the pattern is fixed, part of the error can shrink quickly, but another part cannot move. The model waits until a bend crosses a data region and changes the pattern. That change can open a new path for the loss to drop.

flat does not always mean finished

The Fix: Move The Useful Bends

From that explanation, the talk proposes active neuron least squares. The idea is not to wait forever for gradient descent to slowly change the activation pattern. Instead, generate candidate bend positions, solve the easy least-squares part for each candidate, and keep the candidate that gives the smallest loss.

This is not a generic training trick pulled from nowhere. It comes directly from the diagnosis. If the plateau happens because the activation pattern is not changing, then change the activation pattern deliberately and solve the simple part exactly.

current bend pattern
try nearby patterns
solve least squares
keep the better fit

Dying ReLUs Are Different

The last technical problem is the dying ReLU. A ReLU neuron can become a constant zero on all the data. If that happens, its gradient is zero, so gradient descent has no signal to move it back into usefulness. The neuron is present in the architecture, but it is not doing work.

The talk shows that deep and narrow ReLU networks are more likely to suffer this problem under common symmetric random initialization. Wide networks are less likely to die in this way. This helps explain why a network that is theoretically able to represent a simple function can still fail in training.

data lie on flat side
output stays constant
gradient is zero
training cannot revive it

Architecture Is A Training Choice Too

A beginner may think architecture only controls what the network can represent. This talk adds a second meaning: architecture also changes the chance that training works. Depth, width, activation function, initialization, residual connections, and normalization can all change whether the optimizer has a useful path.

In the Q&A, the speaker gives a practical rule of thumb. Deep networks can be helpful for sharp changes, such as shocks, but deep narrow ReLU networks can be harder to train. Smooth behavior may not need the same depth. The point is not that one architecture is always best. The point is that architecture changes both representation and trainability.

sharp behavior may need depth
smooth behavior may not
narrow deep networks can stall
initialization matters

What This Means For The Course

This chapter connects backward to the first PINN chapter. There we learned that adding physics to the loss can create training imbalance and failure. Here we learn the broader map. A physics-informed method needs approximation power, data coverage, regularity control, boundary control, and a training path that actually moves.

It also connects forward to reduced models, operators, graph networks, inverse problems, and design loops. Any learned scientific model can fail in one of these ways. A reduced model can have approximation error if the basis is too small. An operator learner can have estimation error if the training functions are too narrow. A graph simulator can have optimization error if training rollouts are unstable. A topology optimizer can exploit any of these errors if the learned model becomes the judge.

PINN: physics loss and boundary control
ROM: basis and projection limits
operator model: training family coverage
design loop: optimizer can exploit model error

The Chapter In One Chain

First, modern machine learning succeeds in many places, but success does not explain why it works. Second, a learned method has several possible failure sources: model family, finite data, and optimizer. Third, PINNs need convergence theory because more sampled physics points should move the network toward the real PDE solution. Fourth, regularization controls what happens between sampled points. Fifth, boundary conditions matter because edge error can affect the whole solution. Sixth, training can stall when activation patterns stop changing. Seventh, a targeted algorithm can improve training by changing those patterns deliberately. Eighth, ReLU neurons can die when they become flat on the data. Ninth, architecture and initialization are not cosmetic choices; they affect whether training can use the model's theoretical power.

The chapter's core idea: theory is useful because it separates "the model could not express it," "the data did not identify it," and "training did not find it." Those are different failures, and scientific machine learning needs to know the difference.

How To Test Whether You Understood This Chapter

Name the three errors approximation asks whether the model family can hold the answer, estimation asks whether finite data identify it, and optimization asks whether training found it.
Explain PINN control more sampled physics points are not enough unless regularization and boundary handling control what happens between and at the edges.
