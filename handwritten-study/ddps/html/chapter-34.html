Make Machine Learning Respect The Scientific Contract

Read This Chapter As One Claim

A scientific ML model is not finished when it gets low test error or includes a physics term in the loss. If it claims to represent a physical process, it must pass the contract of that process: constraints, stability, time behavior, refinement, and robustness.

Everyday problem A neural model looks accurate on sampled data but violates the rule that makes the scientific result usable.
Shared promise Use scientific structure to shape training: hard or explicit constraints, continuation, time marching, and convergence checks.
Hidden danger A soft penalty can make physics look present while the optimizer still ignores, weakens, or fails to satisfy it.
First rejection test Reject the model if it only works at one sampled grid, time step, parameter value, or penalty weight.

This chapter uses video 37, Michael Mahoney's DDPS talk on combining principled scientific models with principled machine learning models. The talk is not a sales pitch for one method. It is a warning about a deeper mismatch. Machine learning and scientific computing often judge success by different contracts.

In ordinary machine learning, a constraint is often a soft preference. It nudges the model. If it is not perfectly satisfied, the model may still be considered good if the test error is low. In scientific computing, some constraints are not suggestions. Conservation, stability, boundary conditions, time-step behavior, and continuity can decide whether the result is physically usable.

machine learning: low test error
science: respect structure
constraints may be hard
both standards must meet

The Two-Way Question

The talk starts with a useful reversal. Scientists often ask, "How can machine learning help my scientific problem?" Mahoney asks the other half too: "How can the scientific problem help machine learning?" If ML is treated only as a tool buried in a methods section, ML researchers may move on to images, language, or recommendation systems.

The deeper opportunity is two-way. Scientific problems force ML to handle space, time, constraints, continuous limits, robustness, and model structure in ways that ordinary benchmark problems often avoid. If those issues are solved well, they help science and also improve machine learning itself.

science gives hard problems
ML gives flexible methods
shared questions improve both
avoid one-way tool use

Space And Time Are Not Just Features

Many ML workflows treat data as rows and columns. Space and time may appear as inputs, but they are not always first-class parts of the method. Scientific problems are different. A flow field has spatial geometry. A dynamical system has time. A PDE solution must behave correctly as space and time are refined.

This is why scientific ML cannot only ask whether a model fits training and test points. It must ask whether the model behaves like the kind of object it claims to represent. If it claims to represent a physical process, it should pass tests that physical and numerical models are expected to pass.

space has geometry
time has order
refinement should make sense
test error is not enough

PINNs As A Simple Test Case

Physics-informed neural networks are a useful place to study this mismatch. A PINN usually has two parts in its loss. One part fits observed data. Another part penalizes violation of a differential equation or boundary condition. In plain words, it tells the network: match the measurements, and also try to satisfy this physics equation.

That sounds reasonable. The problem is that this setup turns physics into a soft penalty. A soft penalty is not the same as a solved constraint. For many scientific problems, the difference matters. A small constraint violation can grow, destabilize a simulation, or produce a result that looks good in a plot but fails the physical job.

fit data points
penalize PDE residual
choose penalty weight
physics may still be weakly enforced

Why The Penalty Weight Is Dangerous

In ML, a penalty weight is often treated like a tuning knob. Put more or less weight on the regularizer until validation looks good. But when the regularizer is a physical equation, the meaning changes. The equation may represent the main structure, not a mild preference.

The talk points out that writing the loss one way can make the data term feel primary and physics secondary. In many physical problems, it should be the other way around. The physics may be the thing that must be respected, with data correcting or completing it.

small weight: physics ignored
large weight: hard optimization
data-first mindset can mislead
constraint meaning must be explicit

The Optimizer Can Choke

The talk studies simple PDE cases such as convection, reaction, and reaction-diffusion. These are simple enough to know the correct answer, but still reveal failure modes. For easy parameter values, the PINN can learn. As the physical parameter gets harder, the error can suddenly get much worse.

This is not only a neural-network expressivity problem. The network may be capable of representing the solution. The failure can come from optimization. Adding a differential-equation penalty can make the loss landscape rougher, not smoother. That is different from the usual ML intuition that regularization often makes optimization nicer.

easy parameter
network learns solution
harder parameter
optimizer loses the physics

Curriculum Is The Scientific Obvious Thing

One fix is curriculum regularization. Start with an easy physical parameter, train there, then gradually move to harder values. In ML language, this is a curriculum. In scientific computing language, it looks like continuation or annealing: solve the easy problem first, then use that solution to approach the hard problem.

This is a good example of the two fields seeing the same move differently. To a scientist, it may seem obvious. To ML theory, it changes the data distribution during training and raises nontrivial questions. The method works better because it does not ask the optimizer to jump straight into the hardest loss landscape.

start easy
train stable behavior
increase difficulty
reach hard physics more reliably

Sequence-To-Sequence Is Also Natural

Another fix is to stop asking the model to predict the whole space-time solution at once. Instead, march the solution forward in pieces. This is sequence-to-sequence learning in ML language, and time marching in numerical-method language.

The point is not that one vocabulary is better. The point is that scientific structure suggests a training protocol. If information physically propagates through time, the model should be trained in a way that respects that propagation rather than flattening the whole problem into one large fit.

predict all at once
can fail to propagate
march in time
respect physical information flow

Learning A Continuous Model Is A Different Claim

The second main topic asks what it means for a neural network to learn a continuous dynamical system. A ResNet block looks a little like an Euler time step: future state equals current state plus an update. But a resemblance in notation does not prove the network has learned a continuous process.

Here is the plain test. If the model really represents a continuous process, then changing the time step should behave predictably. In numerical analysis, when a time step is refined, the error should shrink in a known way. If a learned model works only at the exact time step it was trained on, it may have learned the discretization, not the process.

fit one time step
halve the time step
check convergence
learn process, not only grid

The Convergence Test

The talk borrows a familiar scientific-computing idea: convergence under refinement. Train a learned time-step model. Freeze it. Then test what happens when the step size changes. A meaningful continuous model should improve or behave consistently as the step is refined. Different integrator-inspired architectures, such as Euler, midpoint, or RK4, should approach the same underlying solution at their expected rates.

The key result is that a learned model can look good at the training step and fail badly when the step changes. That is a different failure than ordinary test error. It says the model is not a trustworthy continuous model even if it is a good discrete predictor at one chosen step.

train at one step
freeze learned update
test smaller steps
detect discretization overfit

Why This Matters Beyond Physics

The talk even connects this to ordinary ML tasks such as image classification. If a model should behave gracefully as depth, memory, or compute budget changes, continuous-in-depth thinking can help. A model that improves smoothly as layers are added is easier to deploy across different hardware budgets than a model that suddenly gets worse at some depths.

This is the argument for why scientific ML can help ML itself. Scientific computing has spent decades thinking about refinement, stability, discretization, and convergence. Those ideas can become useful diagnostics and design tools for general machine learning too.

vary depth or memory
model should degrade gracefully
scientific convergence ideas help
science informs ML design

Time Needs Better Treatment

The closing part points to time-series and sequential models. RNNs, continuous-time recurrent units, noisy recurrent models, and multi-scale memory models can be viewed through dynamical-system ideas. This matters because time is often added onto ML methods after the fact, while in scientific problems time is part of the structure.

Noise is another example. ML often adds noise as a training trick. Scientific modeling can interpret certain noise injections as stochastic differential equation ideas or as regularization in model space. That interpretation can lead to more robust models, not just different training curves.

hidden state evolves
noise can regularize
multiple time scales matter
robustness is part of the model

How This Connects To Earlier Chapters

This chapter explains why many earlier methods can fail if we only judge them by surface performance. A PINN is not automatically good because its loss contains a PDE. A neural operator is not automatically physical because it maps fields to fields. A time-step network is not automatically continuous because its block resembles a numerical integrator.

The practical question is always: what scientific contract did the model promise, and how did we test that contract? Conservation, stability, hard constraints, time-step refinement, extrapolation, uncertainty, and robustness are not decorative add-ons. They are part of whether the model can be trusted in a design or simulation loop.

constraint check
stability check
refinement check
robustness check

The Chapter In One Chain

First, scientific ML must satisfy both ML standards and scientific-computing standards. Second, space, time, constraints, and continuity are central in science but not always central in ordinary ML workflows. Third, PINNs are a useful test case because they attach a PDE penalty to a data-fitting loss. Fourth, a soft penalty is not the same as a hard scientific constraint. Fifth, PINNs can fail suddenly as physical parameters become harder because the optimizer and loss landscape do not match the scientific structure. Sixth, curriculum training and sequence-to-sequence training work better because they respect how scientists already approach hard PDE problems. Seventh, a learned time-step model can fit one step while failing to represent a continuous process. Eighth, convergence tests expose that failure by changing the step size after training. Ninth, these scientific diagnostics can help ordinary ML too, for example when model depth or compute budget changes. Tenth, the larger goal is not to bolt ML onto science, but to build methods that both communities can defend.

The chapter's core idea: scientific machine learning is not finished when a neural network fits data and includes a physics word in the loss. It must pass the scientific contract it claims to satisfy.
