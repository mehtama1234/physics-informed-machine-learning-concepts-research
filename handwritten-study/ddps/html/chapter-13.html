Put The Grid Inside The Network

Read This Chapter As One Claim

The point is not to make a neural network sound more physical after training. The point is to put the grid's real decision problem inside training, so the model learns from the cost, safety, and privacy consequences of that decision.

Everyday problem A power forecast can look accurate on paper but still cause an expensive or unsafe dispatch choice.
Shared promise Use an implicit layer so the network must pass through the grid constraint or optimization problem.
Hidden danger If the solve, constraint, or gradient is wrong, the network learns from a distorted version of the real grid decision.
First rejection test Reject the method if it only improves prediction error and cannot show the downstream decision got better or safer.

This chapter uses video 16. The talk is about incorporating power-system physics into deep learning with implicit layers. In plain words: instead of asking a neural network to guess an answer and then checking later whether the answer respects the power grid, put the grid's decision problem inside the network.

The first principle is that a neural network is a chain of differentiable functions. A normal layer may be a simple formula. An implicit layer is different: its output is defined as the solution of an equation, an equilibrium condition, or an optimization problem. If we can differentiate through that solution, the layer can sit inside a deep network.

That change matters because power systems are constraint-heavy. Electricity supply and demand must balance at every moment. Generators have limits. Lines have limits. Generator output cannot always jump instantly from one level to another. A forecast that looks numerically accurate may still produce a bad operating decision.

The Power Grid Problem

The grid has generators producing electricity and loads consuming it. Weather changes solar and wind. People change demand. The operator must choose generation so that production, demand, losses, and network limits fit together.

A central optimization problem is AC optimal power flow. It tries to minimize generation cost while satisfying grid constraints. The difficult part is the power-flow constraint: what flows into and out of each node must obey the electrical equations. This constraint is nonlinear and nonconvex, which makes the problem hard.

Implicit Layer In Plain Words

An explicit layer says: here is the formula, plug in the input, get the output. An implicit layer says: find the output that makes this relationship true. For power systems, the layer can be an optimization solve: given a demand prediction, solve the grid scheduling problem and return the dispatch decision.

Training then flows through the decision. The network does not only learn whether its forecast matched the future demand. It learns whether the forecast caused a cheap, safe, useful grid decision.

Explicit layer direct formula from input to output
Implicit layer output is whatever solves a constraint or optimization problem

Application 1: Forecast For The Decision

The first application is demand forecasting. A normal forecast model is trained to reduce forecast error. If the true demand is x, then predicting x plus 10 and x minus 10 may look equally wrong by a symmetric accuracy metric.

But the grid may not care symmetrically. Overpredicting demand may waste power or money. Underpredicting demand may leave the operator short and force expensive last-minute action. The two errors have the same size but different consequences.

Overpredict extra generation may be wasted
Underpredict shortage can force urgent correction

Decision-driven forecasting trains on the cost of the resulting decision. The forecast goes into the power-flow or dispatch layer. The layer schedules generation. The schedule is judged against what actually happened. That cost is backpropagated into the forecast network.

The surprising result in the talk is that the decision-driven model can have worse standard forecast accuracy and still produce lower grid operating cost. That is not a contradiction. It means the training target finally matches the job.

Application 2: Public Data Can Leak Private Data

The second application asks whether hidden grid information can be reverse engineered from public outputs. Power prices and generation may be public for market transparency or emissions reporting. Generator bids and grid topology may be private because they affect markets or cybersecurity.

The relationship between these quantities is not arbitrary. They are linked by the grid optimization problem. If a guessed private parameter, such as a bid curve or grid structure, is placed inside an optimal power flow model and produces public outputs close to the observed ones, then the guess may reveal something private.

guess hidden bids or grid structure
run differentiable power-flow layer
compare public prices and generation
update the hidden guess

The transcript reports that bidding parameters were easier to recover in the small simulated case than grid structure. That distinction matters. Some private variables strongly affect the public outputs; others may be harder to identify. The main lesson is that differentiable physics can become an inference tool, not only a prediction tool.

Application 3: Safe Learning For Control

The third application connects deep reinforcement learning with robust control. Reinforcement learning can learn expressive actions, but may make unsafe moves while exploring or under stress. Robust control gives safety guarantees, but often uses simpler policies that leave performance on the table.

The implicit-layer idea is to put a safety projection at the end of the neural policy. The neural network proposes an action. The projection layer moves that action onto a set of actions known to keep the system stable. Then the whole policy can still be trained end to end.

The practical goal is a compromise: better average performance than very conservative robust control, while avoiding the catastrophic instability of non-robust learning under adversarial disturbances.

The Price Of This Power

Implicit layers are powerful because they enforce structure strongly. But they depend on being able to solve the forward problem and differentiate through it. If the optimization problem is nonconvex, discrete, too large, or only approximately solved, the backward pass becomes more delicate.

The talk is careful about this. AC optimal power flow is nonconvex, so the implementation uses iterative approximation and differentiates through a final quadratic program. Unit commitment and buy/build decisions involve discrete choices, and those are harder. Scale also matters, though sparse solvers and existing grid optimization tools can help.

Forward solvemust be reliable enough to define the layer output.
Backward solvemust provide useful gradients through the decision.
Discrete choicesare harder than continuous dispatch.

Why This Matters For The Course

This chapter extends the solver-in-the-loop idea from Chapter 8. There, the simulator taught the neural network by passing gradient information backward. Here, an optimization problem teaches the neural network by making the downstream decision visible during training.

It also connects to hybrid twins from Chapter 12. A grid operator does not need an abstractly accurate model. The operator needs a decision that respects the physical system. The same applies in topology optimization, design, and control: the learning target should include the physical decision problem, not only a generic prediction error.

The chapter's core idea: an implicit layer lets a neural network train through a physical constraint or optimization problem, so the model learns what makes the downstream decision good, safe, or revealing.
