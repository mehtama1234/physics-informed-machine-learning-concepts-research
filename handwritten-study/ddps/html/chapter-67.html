Narrative chapter

Choose The Next Expensive Experiment

Read This Chapter As One Claim

Start with a lab, factory, controller, or simulator where every trial costs real time. You cannot try every temperature, shape, recipe, controller setting, or species mixture. So the main question is not "how do I know the whole map perfectly?" The main question is "which next trial is most worth paying for?" This chapter is about using a model, its uncertainty, and any cheap physics hint to choose the next expensive experiment.

Everyday problem Each run is expensive, the best setting is unknown, and a blind sweep wastes the limited experiments you can afford.
Shared promise Use feedback: try one or more settings, measure performance, update the model, then choose the next trial where it can help most.
Hidden danger A model can become accurate in places that do not matter for the final decision, while still failing to find the best usable setting.
First rejection test If the next experiment cannot be explained as either testing a promising region or reducing important uncertainty, the loop is not making a decision-aware choice.

This chapter uses video 70, Victor Zavala's DDPS talk on Bayesian optimization, machine-learning models, physics, and high-throughput experiments. The talk is about how to choose experiments when each run is expensive and the performance landscape is unknown.

The first-principles question is this: if we can only afford a limited number of experiments or simulations, how should each new run be chosen so it either improves the best design or teaches us where the model is still uncertain?

choose experiment
measure performance
update model
choose better next run

The Problem Is Closed-Loop Experimental Design

Bayesian optimization is a feedback loop. An oracle proposes a design setting. The experiment or simulation returns a performance number. A model is updated from all data so far. Then the oracle proposes the next setting.

The performance number can be many things: reactor yield, yearly energy cost, controller error, carbon emissions, hardware energy use, or neural-network validation loss. The common feature is that the function is expensive and not known as a clean formula.

unknown black-box function
expensive response
history of tried points
feedback guides search

Do Not Confuse Model Accuracy With Decision Performance

Classical open-loop design often chooses experiments to build the most accurate model over a region. Bayesian optimization asks a different question: what experiments help find the best performance fastest?

Those goals are not the same. A model can be inaccurate in unimportant places and still guide the search to a good operating point. The talk emphasizes that optimizing performance may require fewer experiments than learning the whole landscape perfectly.

accurate model everywhere
can be expensive
good decision may need less
optimize performance directly

Explore And Exploit Are Both Necessary

The acquisition function chooses the next experiment. It balances exploitation and exploration. Exploitation asks: where does the current model predict high performance? Exploration asks: where is the model uncertain enough that a measurement could change our mind?

If we only exploit, we may get stuck near a wrong early guess. If we only explore, we may waste experiments learning unimportant areas. Bayesian optimization is the attempt to make that tradeoff explicit.

trust current best
risk getting stuck
sample uncertain region
balance both pressures

Parametric Models Put Uncertainty In The Parameters

A parametric model has a chosen form with parameters: linear regression, nonlinear regression, a neural network, a physics-informed model, or a differential-equation model. The uncertainty lives in those parameters.

This is flexible because physics can be embedded in the model form. The cost is that uncertainty calculations can become hard when the parameter count is large. A neural network with millions of weights makes the Fisher-information-style matrices difficult to handle directly.

choose model form
fit parameters
estimate parameter uncertainty
use physics flexibly

Gaussian Processes Put Uncertainty In The Function

Nonparametric Bayesian optimization often uses Gaussian processes. Instead of choosing a fixed formula for the performance function, it places a distribution over possible functions. From the data, it predicts a mean and uncertainty at new points.

This is why Gaussian-process Bayesian optimization became popular. It gives a natural uncertainty estimate and often works well as a black-box tool. But it scales poorly with many observations and is naturally sequential, often proposing one experiment at a time.

distribution over functions
predict mean and variance
works well with small data
hard for many observations

High-Throughput Experiments Need More Than One Point

Many laboratories can run batches of experiments. If a system can test many candidate conditions in parallel, an algorithm that proposes one next point wastes capacity.

The talk discusses ways to use this throughput. One way is to run several Bayesian optimizers with different exploration-exploitation weights. Another is to partition the design space so several agents search different regions while sharing information.

many wells or runs available
one point wastes throughput
parallel agents search
shared model learns faster

A Reference Physics Model Can Guide The Search

The talk's key idea is to use prior knowledge. Suppose a cheap physics model, low-resolution simulation, or coarse reference model gives a rough performance prediction. It is not exact, but it captures broad shape.

Instead of learning the full performance from scratch, learn the residual: the difference between measured performance and the reference model. The reference model points the search toward useful regions, while the learned residual corrects its errors.

cheap reference model
captures coarse trend
measure residual error
learn correction from data

Level Sets Partition The Search Space

A reference model can do more than initialize the search. Its level sets can partition the design space into regions of similar predicted performance. Then separate Bayesian optimizers can search those regions in parallel.

This is different from cutting the design box into equal rectangles. The partition follows the shape suggested by the physics model. Even if the reference optimum is not exactly right, the level-set shape can still guide useful parallel search.

reference performance surface
draw level-set regions
search regions in parallel
share global model

HVAC Control Shows Performance Is Money

The first case study is tuning model predictive control for heating, ventilation, and air-conditioning plants. The controller has tuning parameters such as prediction horizon and constraint settings. One yearly simulation can take hours.

The performance is yearly operating cost. A low-resolution simulation acts as the reference model. It does not need to be perfect; it only needs to point the Bayesian optimizer toward better regions faster than blind search.

controller tuning parameters
year-long simulation
cost is performance
reference model speeds search

The Reactor Example Uses Parallel Partitions

The second case study is a sequence of two chemical reactors. The design variables include temperatures. The real performance surface is nonlinear. A simplified physics model is wrong in detail but still captures enough shape to partition the search.

With level-set partitions, multiple Bayesian optimization agents search at the same time and communicate through a shared model. This converges faster than standard sequential Bayesian optimization in the shown example.

two reactor temperatures
simplified physics model
level-set agents search
faster optimum discovery

Microbial Communities Need Dynamic Models

The final case study is microbial-community design. Different bacterial species can compete or cooperate. The experimental design chooses which species and concentrations to include, while the response may be metabolite production or community stability.

The system is dynamic, so the group uses recurrent neural networks with physical constraints. For example, concentrations cannot go negative, and once a species has gone to zero it cannot magically revive. The model does not have to predict every detail perfectly; it must be good enough near the search path to guide the next experiment.

choose species and amounts
community evolves over time
RNN respects constraints
guide next wet-lab batch

Feedback Means The Model Only Needs To Be Useful Locally

A major lesson from the talk is that closed-loop optimization does not need the world's most accurate model. Like Newton's method using a local linearization, Bayesian optimization can work if the model is accurate enough in the neighborhood where the search is moving.

This is why feedback matters. Each new experiment corrects the model. The method can tolerate a rough model if the loop keeps checking it against real measurements or high-fidelity simulations.

model is imperfect
local guidance is enough
experiment corrects it
feedback drives optimum

Why This Also Matters For Design

Design and topology optimization often have the same structure. The design space is large, each high-fidelity simulation is expensive, and the objective may include performance, cost, failure risk, emissions, or manufacturability.

This chapter gives a design strategy: use cheap physics or low-fidelity models as reference maps, learn residual corrections from expensive evaluations, run parallel searches when hardware allows it, and stop trying to learn the whole landscape when the decision only needs the best region.

large design space
expensive simulations
cheap physics guides search
choose better designs sooner

The Chapter In One Chain

First, Bayesian optimization is closed-loop experimental design. Second, each run measures a performance number, not necessarily model accuracy. Third, the acquisition function balances exploiting likely good regions with exploring uncertain regions. Fourth, parametric models can include physics but may have hard parameter uncertainty calculations. Fifth, Gaussian-process models give natural function uncertainty but are often sequential and observation-limited. Sixth, high-throughput experiments need batch or parallel search. Seventh, a cheap reference model can guide the search even when it is imperfect. Eighth, learning the residual against that reference model is easier than learning the whole objective from scratch. Ninth, reference-model level sets can partition the design space for parallel agents. Tenth, HVAC control shows this for yearly operating cost. Eleventh, reactor optimization shows level-set partitioning. Twelfth, microbial communities show dynamic neural models with physical constraints. Thirteenth, design workflows should use feedback and cheap physics to choose the next expensive simulation wisely.

The chapter's core idea: the goal is not to know the whole expensive function perfectly. The goal is to spend each experiment where it most improves the decision.

How To Test Whether You Understood This Chapter

Explain the loop without buzzwords You pick a setting, run the experiment or simulation, see the performance, update your belief about the unknown function, and use that updated belief to choose the next setting.
Explain explore versus exploit Exploit means try where the current model thinks performance is good. Explore means try where the uncertainty is large enough that the result could change the search. The acquisition rule is the tradeoff between those two reasons.
Explain why cheap physics helps A rough physics model can point toward the broad shape of the landscape. Bayesian optimization can then learn the correction between that rough model and expensive measurements instead of learning everything from scratch.
Connect this to topology and design In topology optimization, each high-fidelity shape evaluation can be expensive. A good search loop uses cheap physics, surrogate uncertainty, and feedback to choose the next shape to test, rather than filling the entire design space evenly.
