Teach The Operator Where Extrapolation Breaks

This chapter uses video 89, Lu Lu's DDPS talk on deep neural operators with reliable extrapolation for multiphysics and multiscale problems. The talk is about DeepONet, multiple-input operators, Fourier-enhanced operator networks, carbon storage, seismic inversion, multifidelity learning, and a practical way to decide when extrapolation is likely to fail.

The first-principles question is this: if a model learns maps between whole functions, how can it stay useful when the next function is different from the kind of function it was trained on?

The lecture's answer has two parts. First, build operator networks that can take functions as inputs and return functions as outputs. Second, do not pretend every new input is equally safe. Measure whether the new input lives near the training function space, and repair hard cases with physics or a small amount of new data.

Read This Chapter As One Claim

Start with the everyday problem. A slow simulator is like a careful expert who can answer one hard case, but only after a long wait. A neural operator is an attempt to learn the expert's whole habit: if you give it one complete input field, such as a permeability map, a wave signal, a material layout, or a weather map, it gives back another complete field, such as pressure, velocity, heat flow, or temperature. That is useful only if the next input is not too different from the examples used to teach it. The whole chapter is about this missing safety question. The model is not just asked, "What is your answer?" It must also be asked, "Have you seen this kind of input before, is this new one simpler, or is it rougher and more dangerous?" If the new case is dangerous, the honest fix is not a prettier plot or a confident number. The fix is to add physics, add a small amount of new data, or run a better simulation for the case that matters.

Function Learning Is Not Yet Operator Learning

A usual neural network learns a map from one list of numbers to another list of numbers. An image classifier might take pixel values and return a class label. A physics-informed neural network might take a coordinate and return the value of one particular solution at that coordinate.

Operator learning asks for something larger. The input is not one number list describing one case. The input is a function, such as an initial condition, boundary condition, forcing field, permeability field, or sensor waveform. The output is another function, such as the full solution of a PDE.

ordinary network
numbers to numbers
operator network
function to function

The Derivative Example Gives The Plain Idea

A derivative is an operator. If the input is a time signal, the output is another time signal: its rate of change. An integral is also an operator. If the input is a curve, the output can be the accumulated area up to each point.

PDE solvers are more complicated versions of the same idea. Give the solver an initial condition, boundary condition, material field, or source term. The solver returns the solution field. Deep neural operators try to learn that solver-like map.

input signal
derivative or integral
PDE solver
output field

DeepONet Splits The Job Into Two Questions

DeepONet uses two main pieces. The branch net reads the input function after it has been sampled or represented by coefficients. The trunk net reads the output coordinate where we want the answer. The two pieces combine to predict the output value at that coordinate.

In plain words, the branch net asks, "Which problem did you give me?" The trunk net asks, "Where do you want the answer?" The final dot product combines those answers into the predicted solution value.

branch net reads input function
trunk net reads location
combine hidden values
predict solution there

Mesh-Free Output Is The Practical Advantage

The output function does not have to be predicted only on a fixed grid. Because the trunk net takes a coordinate, the model can be asked for the solution at arbitrary locations. This matters for irregular geometries, unstructured data, and PDE residuals where derivatives with respect to coordinates are needed.

This is why the architecture connects to PINN-style thinking. Coordinates are part of the input, and automatic differentiation can compute derivatives with respect to those coordinates. The operator network still depends on the full input function, but it can answer point by point.

input function sampled once
ask at any coordinate
predict value there
differentiate by coordinates

POD Gives The Network A Useful Starting Basis

The talk then connects neural operators to a classical reduced-model idea: proper orthogonal decomposition. POD finds important modes from training solution data. Instead of making the trunk net learn every basis function from scratch, POD-DeepONet uses those computed modes as part of the representation.

The simple lesson is familiar from earlier chapters. If scientific computing already has a good structure, use it. A learned model often improves when it starts from a useful numerical basis instead of pretending no prior work exists.

training solution snapshots
POD extracts modes

better accuracy and efficiency

Many Real Problems Have Many Input Functions

A PDE case may depend on more than one input. It can depend on an initial condition, a boundary condition, a source, material coefficients, geometry parameters, and scalar operating conditions all at once. A single-branch operator is not enough for this full setup.

The lecture extends DeepONet to multiple inputs with multiple branch nets. Each branch net reads one input function or parameter group. Their outputs are combined with the trunk representation. A low-rank tensor idea keeps the combination affordable.

initial condition
material fields
scalar parameters
multi-input operator

Carbon Storage Shows Why Cost Matters

The first large application is geological carbon storage. Carbon dioxide is injected underground, and the model predicts gas saturation and pressure over many years. The inputs include horizontal permeability, vertical permeability, porosity, injection rate, temperature, initial pressure, and injection location.

A direct high-fidelity simulator for multiphase porous flow across large spatial and time scales can be expensive. The operator network learns the map from those subsurface fields and scalar settings to the future pressure or saturation field.

permeability and porosity fields
injection settings
30-year flow prediction
pressure and saturation fields

Fourier Layers Help Keep Space Detail

A plain multi-input DeepONet can be efficient, but its simple merge step may miss fine spatial structure. The talk combines the multi-input operator idea with Fourier-style layers. The trunk still handles time, while the Fourier part helps handle two-dimensional spatial fields.

The result is a Fourier multi-input operator network with many fewer parameters and lower memory cost than a heavier Fourier neural operator setup in the example, while still keeping high accuracy. The deeper point is that architecture is not decoration. The merge operation decides what details the network can express.

many input fields
time handled by trunk
Fourier layers handle space
accurate lower-cost prediction

Continuous Time Is A Real Advantage

In the carbon-storage example, the training data has only selected time snapshots. A network that treats each snapshot as a separate grid can do well at trained times and poorly at unseen times. The Fourier multi-input operator keeps time as a coordinate input.

That means the predicted solution changes continuously with time. It can be asked for times between training snapshots. This is not magic physics knowledge, but it builds in a basic expectation: nearby times should usually have nearby solutions.

few expensive snapshots

Seismic Inversion Tests Robustness

The second geoscience example is full waveform inversion. The goal is to infer a subsurface velocity map from wave signals measured by receivers on the surface. Several source locations send waves through the ground, and the recorded waveforms carry information about the hidden structure.

The talk tests whether the operator can still work when the input waveforms are messy: Gaussian noise, noisy source wavelets, and missing receiver traces. The Fourier-DeepONet-style model remains much more robust in the shown cases than the baseline networks.

sources send waves
surface receivers record signals
noise or missing traces
predict velocity map

Multifidelity Learning Uses Cheap Data Without Worshiping It

High-fidelity data is accurate but expensive. Low-fidelity data is cheaper and larger but less accurate. Multifidelity learning uses both. First, a low-fidelity DeepONet learns the broad cheap map. Then a high-fidelity network learns the correction from cheap prediction to accurate prediction.

The talk uses the Boltzmann transport equation for nanostructured material as an example. Different pore layouts change the heat flux. The low-fidelity data alone is not accurate enough, and high-fidelity-only training needs many expensive samples. Combining both gives better accuracy when high-fidelity data is scarce.

many cheap simulations
few accurate simulations
learn correction
better scarce-data prediction

Extrapolation Has Two Directions

The title's main issue is extrapolation. The lecture uses Gaussian random fields to make this concrete. Some input functions are smooth. Others wiggle much more. A model trained only on smooth inputs may fail badly on wiggly inputs because it has never seen that level of complexity.

The reverse can be easier. If the model was trained on complex, wiggly functions, then testing on smoother functions can still work. The talk calls the easy direction extrapolation-minus and the hard direction extrapolation-plus. The names matter less than the idea: not all out-of-training cases are equally dangerous.

Distance Between Function Spaces Becomes A Warning Light

The talk then asks how to quantify the danger. It uses a Wasserstein-style distance between the training input space and the new input space. In the examples, extrapolation error scales with this distance, so the distance can act like a warning light.

This is important because a deployed operator should not only produce an answer. It should also help decide whether the answer is in a familiar region, a mildly safer extrapolation region, or a dangerous extrapolation-plus region.

training function space
new input function space
measure distance
warn about likely error

Hard Extrapolation Needs More Than Confidence

If the new input is interpolation or extrapolation-minus, the pretrained prediction may be usable directly. If it is extrapolation-plus, the lecture does not say to trust harder. It says to add information.

That information can be physics, such as governing equations used for fine-tuning. Or it can be a small new data set from the new case. The small data can be used directly for fine-tuning or combined with the old prediction through a multifidelity idea, where the old operator becomes the low-fidelity guide and the new data corrects it.

detect hard extrapolation
add physics if known
add small new data
fine-tune or correct

Climate Prediction Shows The Repair Pattern

The final example uses daily surface air temperature and pressure from 1950 to 2021. The operator is trained only on the first five years and then asked to predict later years. Because climate relationships shift over decades, later years become an extrapolation problem.

For a hard later case, the talk adds measurements at 100 weather locations. Those few new measurements correct the prediction over the globe. This is the simple deployment lesson: when the world shifts, a small amount of current evidence can rescue a stale operator better than pretending the old training years still cover everything.

train on 1950-1955
predict later climate years
add 100 current stations
correct global field

Why This Matters For Design And Topology

Design and topology work often asks a surrogate to evaluate shapes, materials, fields, pores, or layouts that differ from the training set. A topology optimizer may gradually create rougher material patterns. A reservoir or carbon-storage study may change permeability fields. A seismic inversion workflow may face noisy or missing field data. A climate or infrastructure model may face a shifted regime.

This lecture gives a disciplined way to think about that danger. The operator is useful because it learns maps between whole fields, not only one fixed simulation. But the operator still has a training world. If the new design is smoother or simpler than that world, it may be safer. If it is more detailed, rough, or shifted, it may need physics or new data before its answer should guide a decision.

For topology, the warning is direct. A learned operator can speed up search, but search is exactly the process that finds strange cases. A good design loop should therefore carry an extrapolation check, a repair path, and a rule for when to ask for new high-fidelity evidence.

The Chapter In One Chain

First, ordinary neural networks map numbers to numbers, while operator networks map functions to functions. Second, derivatives, integrals, and PDE solvers are all examples of operators. Third, DeepONet splits the problem into a branch net that reads the input function and a trunk net that reads the output coordinate. Fourth, this makes mesh-free pointwise output possible. Fifth, POD-DeepONet uses classical modes so the network does not learn every basis from scratch. Sixth, multiple-input operators handle initial conditions, material fields, boundary data, sources, and scalar parameters together. Seventh, carbon-storage prediction shows why this matters for expensive multiphysics and multiscale porous-flow simulations. Eighth, Fourier layers help preserve spatial detail while keeping the multi-input operator efficient. Ninth, treating time as a coordinate supports prediction at unseen time snapshots. Tenth, waveform inversion shows robustness to noisy data, source noise, and missing traces. Eleventh, multifidelity DeepONet uses cheap low-fidelity data plus scarce accurate data to learn corrections. Twelfth, extrapolation is not one thing: training on complex inputs and testing on smoother inputs can be safer than the reverse. Thirteenth, extrapolation-plus happens when the new input is more complex than the training space and may create large error. Fourteenth, a distance between function spaces can warn how dangerous a new input may be. Fifteenth, dangerous extrapolation should be repaired with physics, new data, fine-tuning, or multifidelity correction. Sixteenth, the climate example shows an old operator corrected by a small number of current measurements. Seventeenth, topology and design loops need this because optimizers naturally push surrogates toward unfamiliar field patterns.

The chapter's core idea: a neural operator is powerful because it learns a whole solver-like map, but it still has a home territory. Before using it in a design loop, ask whether the new function is inside that territory, simpler than it, or rougher and more dangerous. If it is dangerous, do not trust louder; add physics or new data.
