Narrative chapter

Choose The Step In Function Space First

This chapter uses video 118, Marius Zeinhofer's DDPS talk on infinite-dimensional optimization for scientific machine learning. The talk is about a hidden reason many physics-informed learning methods train badly. The problem is not only the neural network. It is also the optimizer. If the loss contains a PDE, the loss carries geometry from the equation, and a plain first-order optimizer may take steps that look reasonable in parameter space but are poor steps for the function we are trying to learn.

The speaker's main proposal is: first think in function space. Ask what update the ideal function should take if there were no neural network parameterization yet. Then, after that ideal update is clear, project it into the space of changes the neural network can actually make. This reverses the usual habit. Instead of starting with millions of weights and asking Adam to move them, start with the PDE problem itself and ask what the mathematically right motion should be.

Read This Chapter As One Claim

Imagine you are trying to fix a wrong temperature field, pressure field, stress field, or wave function. The physical equation tells you what kind of correction would actually reduce the error. But a neural network optimizer usually sees only millions of weight knobs. It may turn knobs in a way that barely moves the physical field in the useful direction. This chapter says to reverse the order. First ask what correction the physical function wants. Then ask which weight change can best imitate that correction. The network is only the tool; the field is the thing being fixed.

The Failure Is Slow, Stuck Training

The talk begins with examples where scientific machine learning is painfully expensive. Some neural-network wave-function methods for electron problems can require thousands of GPU hours for one solve. Even a simple two-dimensional Poisson equation, written as a PINN, can take many iterations and still stagnate at a mediocre error.

This is a warning against a common assumption. A PDE loss may be easy to write down, but that does not mean it is easy to optimize. Once derivatives, boundary penalties, residuals, and high-dimensional fields enter the objective, the loss surface is shaped by the equation. If the optimizer ignores that structure, it can spend a long time making small unhelpful parameter moves.

Do Not Start With The Network

The usual workflow starts with an ansatz: choose a neural network, choose its parameters, define a loss, and train. The talk says to step back. Before choosing the finite parameter object, write the continuous problem. What function space does the solution live in? What energy or residual are we minimizing? What are the mathematical properties of that objective?

That sounds abstract, but the everyday idea is simple. If you want to fix a bent metal rod, first ask how the rod should move, not how one knob in a complicated machine should turn. The function is the physical object. The parameters are only the knobs we happen to use to produce that function. The method chooses the physically meaningful function update first.

Poisson Shows The Idea In The Cleanest Way

The speaker uses Poisson's equation as the simplest example. The PDE is linear, and the loss is an L2 squared residual plus boundary terms. That makes the function-space objective quadratic. For a quadratic objective, Newton's method is the natural tool because Newton builds and minimizes a quadratic model.

In exact function space, Newton can converge in one step for this idealized quadratic problem. Of course, we cannot directly compute with all possible functions. So after deriving the function-space Newton step, the method chooses an ansatz, such as a neural network, and projects the ideal update into the network's tangent space. The tangent space is the set of function changes produced by small changes in the network parameters.

The Tangent Space Is What The Network Can Actually Change

A neural network cannot move in every possible function direction. If you slightly change its weights, the output function changes in a specific family of directions. Those directions form the tangent space at the current network. Projecting the ideal function update into that tangent space asks: among the changes this network can make right now, which one best matches the update the PDE wants?

This is the key bridge between clean mathematics and trainable models. The method does not pretend the network is the whole function space. It uses the function-space update as the target direction, then finds the closest parameter update the current network can express. That is why the resulting update contains a matrix built from derivatives of the network output with respect to parameters and derivatives from the PDE residual.

Why This Resembles Natural Gradient

The speaker explains that the group first arrived from a natural-gradient viewpoint. Natural gradient changes the notion of distance so that a step is measured in a more meaningful geometry than plain Euclidean parameter distance. In this setting, the PDE-induced object can act like a metric: it tells the optimizer what counts as a meaningful change in function behavior.

The function-space viewpoint is broader. When the operator used to map gradients back into update directions is symmetric and acts like an inner product, the method can be read as a natural-gradient or Riemannian-gradient method. But some problems, such as saddle-point or constrained formulations, do not fit a symmetric metric story. The function-space formulation still covers them.

Nonlinear PDEs Need A More Robust Step

For nonlinear equations such as Navier-Stokes, the residual loss is no longer convex. Full Newton can become unsafe because the Hessian may be indefinite, so the step may not be a descent direction. The talk's practical choice is Gauss-Newton in function space. Gauss-Newton is designed for nonlinear least-squares problems and is more robust because it linearizes the residual.

The speaker reports this difference in experiments. Full Newton in function space can work near a minimizer, but away from the minimizer it may step the wrong way. Gauss-Newton gives a more stable descent direction. The same framework applies: choose the right function-space algorithm, then discretize it through the neural network tangent space.

The Projection Theory Says What Is Being Mimicked

The talk then gives a theory statement. If the function-space update has the right continuity and coercivity properties, the parameter-space method follows the function-space dynamics up to a projection and a step-size error. In plain words: the network update is not arbitrary. It is the best available shadow of the ideal function update, seen through the current network's tangent space.

The visual example makes this intuitive. For Poisson at initialization, the exact function-space Newton direction points almost directly to the solution. The projected function-space method matches that direction well. Ordinary Newton in parameter space and gradient descent do not. For a flow example, the same pattern appears: the function-space Gauss-Newton direction looks like the desired correction, while the plain parameter updates are much less aligned.

The Price Is A Difficult Matrix

The method works well because it uses more information than a first-order optimizer. That information has a cost. Each step requires assembling or applying a matrix related to the PDE residual and the neural network tangent directions. For nonlocal neural network ansatzes, the matrix is dense. It can be rank deficient and ill-conditioned. Small networks can use direct or regularized solves. Large networks cannot.

This is the practical turning point in the talk. A beautiful function-space optimizer is not enough if it only works on toy networks. To make it useful, the matrix solve must scale. The speaker discusses two strategies: matrix-free methods using conjugate gradient and cheap-to-invert approximations. Matrix-free methods can scale but may iterate slowly if the matrix is ill-conditioned. The rest of the talk focuses on a Kronecker-factored approximation.

K-FAC Makes The Big Matrix Smaller

K-FAC means Kronecker-factored approximation. The rough idea is to replace a huge layer matrix with a product of two smaller matrices. Instead of inverting one enormous block, you invert smaller factors. This gives a dramatic speedup for linear layers because the derivative structure of a layer has a natural Kronecker form.

The talk is honest that this is an aggressive approximation. It drops cross-layer interactions and approximates each layer block as a Kronecker product. But the approximation has been useful in deep learning, and here it is adapted to the PDE-aware matrix coming from the function-space optimizer. The implementation is technical, using forward-mode or Taylor-mode automatic differentiation to expose derivative structure through the network.

huge layer block

The Experiments Show The Scaling Tradeoff

On small Poisson examples, the dense function-space method can be the best because it keeps the full matrix information. But as the network grows, the dense method becomes impractical. The K-FAC version remains among the best-performing methods while scaling to larger networks.

The talk then moves to higher-dimensional examples, including a heat equation in four spatial dimensions plus time, and a high-dimensional Poisson-style case with up to around a million parameters. The claim is not that the approximation is effortless. The speaker says there is hyperparameter work, trust-region step choices, moving averages for K-FAC matrices, and update schedules. The important point is that the PDE-aware idea can survive beyond tiny demonstrations.

What This Means For Scientific ML Practice

The practical message is not "always use this optimizer." The message is sharper: when a scientific ML loss contains a PDE, do not assume a general-purpose optimizer understands the equation. The PDE creates a natural notion of error and correction. A good optimizer should exploit that structure.

For PINNs, Deep Ritz methods, operator learning, inverse problems, wave-function learning, and other PDE-loss methods, the same diagnostic question applies. What would the right update be if we optimized the function itself? If the parameter update is not a good projection of that, it may waste effort. This gives a first-principles way to judge optimizers instead of choosing them only by habit.

How This Connects To Topology And Design

Topology optimization is full of PDE-constrained learning problems. A design changes a material layout, geometry, or control field. The physics may be elasticity, heat, flow, acoustics, or coupled multiphysics. If a neural surrogate or PINN is trained with a residual loss, the optimizer should not treat the problem like ordinary curve fitting. The residual contains the equation's geometry.

The chapter's lesson for topology is this: before asking how to update network weights, ask what physical field correction the PDE wants. In structural design, that might mean a correction shaped by equilibrium and boundary loads. In thermal design, it might mean a correction shaped by diffusion. In flow design, it might mean a correction shaped by incompressibility, convection, and pressure. The function-space view forces the optimizer to respect those differences.

The Q&A also gives a realism check. Bigger ansatz classes can represent harder solutions, but they create bigger matrices. Smaller networks may be enough for smooth problems. Highly complex multiphysics or many-electron problems need approximations such as K-FAC, matrix-free solves, or preconditioning. There is no free lunch; the contribution is a disciplined way to spend optimization effort where the PDE says it matters.

Where The Method Should Not Be Overclaimed

The method asks for more mathematical and implementation work than Adam or L-BFGS. The K-FAC approximation is not trivial to set up. Hyperparameters still matter. Dense matrix methods may fail to scale. K-FAC drops information. Matrix-free solves can be slow. Neural operators are not fully settled in this framework, and the speaker says that case needs more work.

The most honest use is therefore not as a magic replacement optimizer, but as a design principle. If a PDE-loss method is stuck, ask whether the optimizer is following the correct function-space dynamics. If not, derive the function-space update, project it through the ansatz, and then decide how much of that geometry can be afforded computationally.
