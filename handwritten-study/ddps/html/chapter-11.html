Narrative chapter

Build Only What The Search Needs

Read This Chapter As One Claim

A reduced model is not automatically cheap just because each reduced solve is fast. If building it requires expensive full simulations in places the optimizer never uses, the method has solved the wrong problem.

Everyday problem You are searching for a better design, but each honest physics solve is costly.
Shared promise Use a reduced model so the search can move without waiting hours at every step.
Hidden danger The offline training stage can waste full simulations across a huge design map the search never visits.
First rejection test Do not trust the shortcut unless an error check says the local model is good enough for the next design move.

This chapter uses video 13. Video 14 does not currently have a cleaned transcript in this folder, so the handwritten course continues with the next transcript-backed talk.

The talk is about a hidden cost in reduced modeling. A reduced model can make each simulation fast after it exists. But building that reduced model may require many expensive full simulations first. If the real job is optimization, that can waste effort, because the optimizer may only visit a small path through parameter space.

The speaker's answer is adaptive enrichment. Do not build one reduced model for everywhere before the search begins. Start where the optimizer starts. Build a local reduced model that is accurate enough nearby. Let the optimizer move. Then enrich only where the search actually goes.

Core move enrich the reduced space near the search path, not across the whole map.

The Battery Problem

The motivating physical example is lithium-ion battery degradation. The speaker focuses on resolved porous electrode geometry. That means the model is not just a smooth average of the battery. It looks inside the porous structure where local current varies from place to place.

That local detail matters because degradation can start where currents become intense. One example is lithium plating, where lithium moves into a metallic phase and begins to grow in damaging ways. A homogenized model can miss the local current distribution that causes this.

hot local current

Why detail matters: degradation is driven by local behavior inside the electrode, not only by the average battery state.

The classical reduced-basis method works well here once the reduced model is built. The transcript gives the scale clearly: a high-dimensional battery simulation can take hours, while the reduced model can answer in seconds with small relative error. That is the attractive side of reduced modeling.

The Expensive Part Before The Fast Part

The catch is the offline stage. To build a reduced basis, the classical method runs high-dimensional simulations at selected parameter values, stores trajectories, uses error estimates to find where the current basis is weak, and adds new information. For time-dependent problems, a POD-greedy procedure is a standard way to do this.

That is reasonable when the reduced model will be reused across the whole parameter range many times. But for one optimization run, building a globally good reduced model can be too much. The optimizer does not need the whole map. It only needs enough accuracy near the route it takes from the starting guess to the final design.

Classical route pay many full solves first build a global reduced model then run fast online queries
Adaptive route start with the optimizer enrich near the current point reuse the model as the search moves

Trust Region In Plain Words

A trust region is a local promise. The method says: "I trust this reduced model only inside this nearby ball around the current parameter." Inside that ball, the optimizer can solve a smaller subproblem. When it proposes a new point, the method checks whether the reduced model is accurate enough there. If not, it enriches the basis.

This is careful and practical. The reduced model is not allowed to make global claims it has not earned. It gets a region where its error estimate says it is reliable. If the model improves, the trust region can grow. If the model is weak, the region shrinks or the model is enriched.

Why The Adjoint And The Gradient Matter

Optimization needs direction. To improve a design parameter, the method needs to know how the objective changes when the parameter changes. In PDE-constrained optimization, that usually means solving the state equation and also a dual, or adjoint, equation. The adjoint is a way to compute gradient information without separately perturbing every parameter.

The talk explains that the reduced model must approximate more than the state. It also needs reliable reduced versions of the dual problem, sensitivities, and gradient information. Otherwise the optimizer may move in the wrong direction.

One technical issue in the talk is non-conformity: the reduced space for the primal state and the reduced space for the dual state may not be the same. If the objective is evaluated naively, an important residual correction can be missed. The speaker shows that adding this correction improves convergence and gives better error behavior.

Error Estimates Are The Steering Wheel

Error estimates are not decoration in this talk. They are the steering wheel. They decide where the reduced basis is weak, whether the trust region is valid, whether the reduced objective is accurate enough, and whether the gradient can be trusted.

The battery example also uses hierarchical error estimation. Instead of relying only on a residual estimate, it compares a reduced simulation with a richer reduced simulation and uses that difference as a practical indicator. The larger lesson is simple: a reduced model needs a way to know when it is not good enough.

Error small: trust the reduced solve.

Error large: enrich the basis before moving on.

Localized Enrichment

The final part of the talk pushes the idea further. Why enrich the whole computational domain if only some subdomains need more information? Localized model order reduction splits the domain into pieces and builds local reduced spaces.

That means a local error estimate can say which pieces of the domain need enrichment. Some subdomains may need many basis functions. Others may need very few. In the optimization example discussed in the transcript, the method solves many local subproblems but avoids ever solving the full global high-dimensional problem.

Why This Matters For Design And Topology

This chapter matters for topology optimization because topology problems are search problems. You are not evaluating one fixed design. You are changing material layout, geometry, boundary conditions, or controls again and again. A globally trained surrogate can spend a huge amount of effort covering designs the optimizer will never visit.

Adaptive enrichment suggests a more disciplined route. Let the optimizer expose what it needs. Build or enrich the reduced model near the current design. Use error estimates to decide whether the model is trustworthy. Move only when the local model is good enough.

The Larger Lesson

Chapter 10 said a reduced model must survive hard physics. Chapter 11 adds that a reduced model must also be built economically. The fastest online model may still be a bad deal if the offline stage is too expensive for the job.

The first principle is: match the reduced model to the work being done. If the work is broad reuse, a global offline model may be worth the cost. If the work is one optimization path, build locally and adaptively. If the weakness is spatially local, enrich locally. The method should spend high-fidelity effort only where it buys trust.

The chapter's core idea: adaptive enrichment builds the reduced model along the optimization path, using error estimates to decide when and where more full-order information is needed.
