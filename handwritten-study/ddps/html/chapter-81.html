Keep The Energy Rule While Learning The Missing Part

Read This Chapter As One Claim

Start with a robot, actuator, pendulum, or soft mechanism that mostly follows known physics but still surprises us because of contact, friction, wind, soft material, or hidden excitation. A pure physics model can be too incomplete. A pure learned model can be too unconstrained. This chapter says to keep the energy bookkeeping that makes the system physically meaningful, then use learning to fill the missing part and report uncertainty where the data is thin.

Everyday problem A controller may trust a model that misses friction, contact, soft ground, or hidden forcing, and that missing piece can make the real system fail.
Shared promise Use Gaussian processes to learn unknown functions while Port-Hamiltonian structure preserves energy flow, dissipation, and input-output behavior.
Hidden danger If learning replaces the whole dynamics freely, it may predict paths that fit nearby data but violate energy or become untrustworthy away from observations.
First rejection test Remove actuation, roll forward, or move away from training data; reject the model if energy grows when it should dissipate or uncertainty stays falsely confident.

This chapter uses video 84, Thomas Beckers' DDPS talk on physics-enhanced Gaussian processes for learning electromechanical systems. The lecture sits at the boundary between modeling and control: before a robot can be safely controlled, it needs a model that is accurate enough, physically sensible enough, and honest about what it does not know.

The first-principles question is this: if a robot or electromechanical device has some physics we know and some behavior we cannot model well, how do we learn the missing part without throwing away the physics that keeps the model safe?

The answer is to keep the physical structure as the frame and use learning inside that frame. Beckers uses Gaussian processes because they can learn from sparse data and produce uncertainty. He then puts them inside energy-based Port-Hamiltonian structure so the learned models obey basic physical rules such as energy flow and dissipation.

Robots Fail Where The Model Is Missing Something

The talk begins with electromechanical systems such as humanoid robots, drones, bio-inspired robots, and soft or contact-rich machines. These systems can be controlled impressively when the model is good enough, but failures happen when the model misses soft ground, wind, contact, friction, or complex material behavior.

This is not because Newton's laws stopped working. It is because writing every relevant detail into a usable control model is too hard or too slow. The missing detail can still matter enough to crash the controller.

Pure Physics And Pure Learning Each Miss Something

A hand-built physics model generalizes well and can support stability guarantees, but it may be time-consuming and incomplete. A black-box learned model is flexible and easy to fit, but it may generalize poorly and may not say when it is unsure.

Safe learning-based control needs both sides. It needs enough physics to preserve structure and enough learning to capture effects such as friction, contact, and unmodeled nonlinearities. It also needs uncertainty, because a controller must know when a prediction is not trustworthy.

physics gives guarantees
physics misses complexity
learning captures data
uncertainty tells trust

A Gaussian Process Is A Distribution Over Functions

A Gaussian process is a way to say: before seeing data, many functions are possible; after seeing data, some functions become more likely than others. The model gives a mean prediction and an uncertainty band.

Near data, uncertainty usually shrinks. Far from data, uncertainty grows. That is why Gaussian processes are attractive for sparse-data control problems. They do not only predict; they also warn when the model is reaching beyond what the data supports.

possible functions
observe sparse data
update prediction

The Kernel Defines What Functions Are Allowed

In a Gaussian process, the kernel or covariance function says how related two input points are. But it does more than that. It defines the type of functions the model prefers: linear, smooth, once differentiable, twice differentiable, and so on.

This gives two places to inject prior knowledge. The mean function can include a rough physical model. The kernel can restrict the class of possible learned functions. Beckers' main move is to put physical structure into the kernel so the learned functions are not arbitrary.

mean guides prediction
kernel defines function class
encode physical structure
learn within allowed class

Port-Hamiltonian Systems Track Energy Flow

A Hamiltonian is an energy-like quantity. In a mechanical system, it can include kinetic energy and potential energy. A Port-Hamiltonian system extends this idea to systems with inputs, outputs, interconnections, and dissipation.

This is useful for electromechanical systems because electrical and mechanical parts can both be described through energy. The interconnection matrix says how energy moves inside the system. The dissipation matrix says how energy is lost, for example through friction. The input matrix says how outside actuation injects energy.

Hamiltonian energy
internal energy flow
dissipation and friction
input-output ports

The GP Learns The Energy, Not A Free-Form Force

The first method puts a Gaussian process prior on the Hamiltonian itself. In plain terms, the model learns the energy landscape from data. The Port-Hamiltonian formula then turns that energy into dynamics.

This is different from learning any arbitrary right-hand side for the ODE. Each sampled model still has the Port-Hamiltonian structure. So even when the data is sparse and the samples disagree, each sample remains physically meaningful in the energy-flow sense.

Sparse Data Gives Many Physical Possibilities

The magnetic ball and coil example shows the idea. A ball rolls near a coil. Turning on the coil creates a magnetic field and attracts the ball, so the mechanical state and electrical actuation interact.

With few data points, the GP samples produce different trajectories. That is the uncertainty. But the samples still respect the energy rule: when the coil is off and no external energy is added, the Hamiltonian should stay constant or decrease. More data narrows the spread of possible models.

Switching Systems Need Mode Awareness

Some systems change their equations depending on contact or operating mode. A hopping robot has one mode when it is in the air and another mode when it touches the ground.

The extension uses a Gaussian process classifier to decide which mode the system is in, together with Port-Hamiltonian Gaussian process models for the dynamics. The first-principles point is that contact is not just noise. It changes the rule, so the model must know which rule is active.

Friction Can Be Learned As A Function

The early Port-Hamiltonian GP can learn parameters in the structure matrices. But friction may not be a simple parameter. It may be a nonlinear function of state, speed, contact, or environment.

The extension puts another Gaussian process inside the dissipation or interconnection structure. That allows the model to learn nonlinear friction while still enforcing the required signs or symmetries that keep the physics meaningful. This requires approximate inference because multiplying GP objects breaks the simple closed-form Gaussian property.

The Water-Bowl Pendulum Shows Dissipation Learning

The pendulum-through-water example makes this concrete. A pendulum swings through a water bowl, so it experiences nonlinear drag only when it passes through the water. The true friction law depends on shape, water properties, and motion.

The learned model tracks the trajectory and shows higher uncertainty away from the collected data. The energy decreases over time, which is the physical rule for a dissipative system. Again, the model can be uncertain while still respecting the direction energy is allowed to move.

Video Data Needs A Latent State

The second part of the talk changes the input. Instead of measuring position and velocity directly, suppose we only have video. A video frame is high-dimensional, but the physical state behind it may be low-dimensional. A pendulum video might hide a two-state angle-and-velocity system. A car video might hide wheel position and body position.

The method uses a variational autoencoder to compress video frames into a low-dimensional latent state. Because it is variational, the latent state is a distribution, not just one point. That keeps uncertainty in the representation.

video frames
encoder compresses
latent state distribution
decoder reconstructs video

The Latent Motion Should Follow Dynamics

A vanilla autoencoder can learn a compact representation, but it may not make the latent state obey the physical motion. Beckers adds a Gaussian process over time in the latent space, with a physics-inspired kernel.

For linear dynamics, the solution over time can be written through a Green's function acting on an input. That structure can be placed into the kernel. The result is a latent trajectory prior that says: possible latent motions are not arbitrary; they should look like solutions of the assumed dynamics with unknown excitation.

latent positions over time
known dynamics structure
unknown excitation
physics-shaped trajectory

The Particle Video Shows Better Extrapolation

The particle video example uses mass-spring-damper dynamics with unknown excitation. The model sees videos of a moving particle, compresses frames to latent position, and learns the latent trajectory with the physics-enhanced GP prior.

Compared with a vanilla GP, the physics-enhanced version predicts better after the training time window. The reason is simple: without physics, uncertainty explodes away from data; with the dynamics prior, the model knows what kinds of paths are plausible.

Why This Matters For Design And Topology

Design and topology work often needs control of systems with unknown contact, friction, compliance, damping, actuation, or human interaction. A robot gripper, soft actuator, compliant mechanism, vehicle suspension, or morphing structure may have physics we know and effects we cannot write cleanly.

This lecture gives a useful rule for those cases: do not let learning erase the conservation and dissipation story. If the design changes geometry or material layout, the learned model should still know how energy is allowed to move. If the only data is video or images, the latent representation should still carry a physically meaningful state.

For topology optimization, this matters whenever the design is used in a controller or a dynamic environment. A shape is not good only because it looks efficient in one simulation. It must behave safely under uncertainty, and the model should say when it is unsure.

unknown friction or contact
preserve energy rules
control with uncertainty

The Chapter In One Chain

First, electromechanical systems fail when the control model misses contact, wind, friction, soft material, or other nonlinear effects. Second, pure physics models give structure but are hard to complete. Third, pure learned models are flexible but can be untrustworthy away from data. Fourth, Gaussian processes are useful for sparse data because they predict both a mean and uncertainty. Fifth, the GP kernel defines what functions are allowed, so it is a natural place to encode physics. Sixth, Port-Hamiltonian systems describe energy, interconnection, dissipation, and input-output exchange. Seventh, putting a GP prior on the Hamiltonian lets the model learn the energy while preserving the physical structure. Eighth, sparse data creates many possible models, but each sampled model can still obey the energy rule. Ninth, switching systems such as hopping robots need mode awareness because contact changes the dynamics. Tenth, nonlinear friction can be learned as a function inside the dissipation structure. Eleventh, video data requires a low-dimensional latent state learned by a variational autoencoder. Twelfth, the latent state should evolve according to a dynamics-informed GP, not arbitrary image compression. Thirteenth, physics-shaped latent dynamics extrapolate better beyond the training window. Fourteenth, design and topology need this because controlled mechanisms must learn what is missing while keeping the physical rules that make safety arguments possible.

The chapter's core idea: learning is safest when it fills the gap instead of replacing the whole physical story. Keep the energy structure, learn the unknown friction or excitation, and keep uncertainty visible so a controller or designer knows when the model should not be trusted blindly.
