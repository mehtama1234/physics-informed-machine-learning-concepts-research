Let Reasoning Guide What Learning Tries Next

This chapter uses video 107, Yexiang Xue's DDPS talk on vertical reasoning enhanced learning, generation, and scientific discovery. The talk is about joining two old AI traditions. One tradition learns from data. The other reasons with rules, constraints, logic, and counting. The lecture argues that many hard problems need both.

The first-principles idea is simple. Learning is good at seeing patterns in rich data. Reasoning is good at checking whether a proposed answer obeys rules. If we only learn, we may get beautiful outputs that ignore requirements. If we only reason, we may not know how to handle messy images, scientific observations, or uncertain data. The useful system lets learning propose and reasoning guide, filter, count, or correct.

Read This Chapter As One Claim

Start with the simplest division of labor. Learning is the part that looks at messy data and says, "this pattern seems likely." Reasoning is the part that says, "does that answer obey the rules?" A kitchen generator may make a pretty appliance, but reasoning checks whether it is actually left of the oven and below the sink. A symbolic discovery system may fit a table, but reasoning can choose smaller controlled cases so the law is found one piece at a time. A probabilistic solver may face too many possible worlds, but counting logic can turn the probability question into SAT-style checks. The chapter's claim is that hard discovery should not be a blind search over everything at once. Let learning propose useful pieces, and let reasoning decide what is valid, what experiment should come next, and what constraint cannot be broken.

Learning And Reasoning Solve Different Parts

The talk describes machine learning as a bottom-up approach. It learns predictive models from data. That can work very well, but it can be hard to give formal guarantees, and learned models may violate constraints in new situations.

Automatic reasoning is a top-down approach. It starts from a problem description, rules, mathematical programs, satisfiability constraints, or convex programs. That can give stronger guarantees, but it can be rigid and hard to adapt to raw data distributions. The lecture's thesis is that AI needs the two systems integrated, not isolated.

bottom-up learning
top-down reasoning

combine them

The Kitchen Example Shows Why Pure Generation Fails

The first example is kitchen remodeling. The input is an existing kitchen image and instructions such as adding a blue microwave to the right of the oven and a green toaster left of the oven and below the sink.

This task has two different jobs. First, perception must find the sink, oven, cabinets, counter, and existing objects in the image. Machine learning is good at that. Second, the system must place new objects so the spatial instructions are satisfied. The toaster should not float in the air. The microwave should not ignore the oven. This is reasoning over relations and constraints.

find existing objects
read user constraints
choose valid boxes
generate edited kitchen

Reasoning Filters The Neural Choices

The presented pipeline has three steps. A perception module locates existing objects. A spatial reasoning module chooses bounding boxes for new objects. A visual generator fills those boxes with the requested appliances.

The important middle step is neuro-symbolic. A recursive neural network proposes coordinates step by step. A symbolic reasoning engine checks whether those coordinate choices violate the user specification. If a proposal violates the rules, the reasoning engine tells the neural network to choose the other direction. This lets the final image satisfy instructions while still looking natural.

Scientific Discovery Should Not Search Blindly

The second part moves to scientific discovery. Many symbolic regression methods search horizontally. They start with a guessed equation and mutate it through many candidates until something fits. That can work, but the space of possible equations becomes huge when many variables interact.

The lecture proposes a vertical path. Instead of searching the whole equation at once, hold most variables constant, let one or two variables vary, discover a small relationship, then add another variable and expand the expression. This is closer to how many scientists run controlled experiments.

hold variables fixed
learn small relation
add one variable
grow full law

The Toy Table Explains The Trick

The talk gives a table with inputs X1, X2, X3 and output y. If all rows are shown at once, the hidden equation is harder to see. But if we look only at rows where X2 is held fixed, the relationship becomes simpler.

When X2 is 1, the table can reveal y as X1 plus X3. When X2 is minus 1, it can reveal y as minus X1 plus X3. From those two controlled views, the full equation becomes clear: X1 times X2 plus X3. The small views are stepping stones to the whole law.

fix X2
discover X1 term
compare constants
recover full equation

Genetic Programming Searches Each Step

The implementation uses genetic programming in the symbolic regression step. Genetic programming keeps a population of candidate equations, mutates them, combines pieces of them, and keeps formulas that fit better.

Vertical discovery makes that search easier because each stage has fewer variables. In the next stage, the algorithm does not throw away the earlier equation. It freezes the useful structure and expands only the parts that now need to depend on the newly introduced variable.

Bacon Is The Historical Neighbor

The talk connects this idea to Pat Langley's Bacon systems from the 1970s. Bacon discovered empirical laws by finding regularities at one level, summarizing them into new variables, and then finding regularities among those new variables.

The ideal gas law example explains the relationship. First discover how pressure and volume relate when other variables are held fixed. Summarize that relation. Then discover how the summary changes with temperature. Then discover how that next summary changes with the number of gas molecules. The final law appears by substituting the summaries back.

pressure-volume relation

add temperature and amount
ideal gas law

The Difference Is Data Efficiency

The speaker says the vertical symbolic regression approach is related to Bacon but can require less than a complete factorial experimental design. Bacon-style discovery may need many combinations of variable settings. The newer approach treats the problem as prediction and expands intermediate equation forms directly.

In everyday words, it tries to avoid testing every combination when earlier structure already tells us where the next search should focus. That is the benefit of reasoning about the intermediate forms instead of treating the dataset as one flat table.

not every combination
use found structure

faster discovery

The Snowflake Example Uses Vertical Learning For PDEs

The lecture then moves beyond algebraic equations to PDE discovery. The example is dendritic solidification, a model related to snowflake-like growth. The full model has many parameters and spatial-temporal dynamics.

The vertical learning experiment splits parameters into groups. First, train on data where one group of parameters does not affect the spatial-temporal dynamics, so the model can learn the other group. Then train on data where both groups matter. Learning all parameters at once produced the wrong number of snowflake branches in the shown example, while vertical learning recovered the ground-truth behavior.

freeze one parameter group

recover snowflake pattern

The Deep Point Is Experiment Choice

Traditional symbolic regression is often treated as a pure learning task: data in, equation out. The speaker argues that reasoning should help decide which intermediate hypotheses and which experiments can serve as stepping stones.

That is an important change. The system is not only fitting a fixed dataset. It is asking what simpler dataset or controlled setting would make the next piece of the law easier to discover. This is where the method starts to look more like a scientist planning experiments.

The Third Part Adds Probabilistic Reasoning

The final technical part is about satisfiability modulo counting. The motivation comes from problems where logical constraints and probabilistic inference are tangled together. Examples include Markov random fields, stochastic optimization, and leader-follower games under uncertainty.

The problem is that probabilistic inference can involve summing over exponentially many scenarios. Logical satisfiability solvers are powerful, but they do not directly handle those probability sums. The talk introduces a language where some Boolean truth values are determined by model counting or probabilistic inference.

logical constraints
probability sums
model counting
decision with guarantees

The Hotel Example Makes Counting Concrete

The example is choosing a hotel so the expected travel time to an AI venue and to one of two cafes is no more than thirty minutes. This sounds simple, but the word expected matters. To check it, the system must reason over possible travel-time scenarios and probabilities.

So the decision is partly symbolic and partly statistical. Symbolic reasoning handles the "and" and "or" structure of the requirement. Statistical reasoning estimates the expected travel times. Satisfiability modulo counting is a way to make those two parts speak to each other.

hotel choice
AI venue
cafe options
expected time limit

XOR Constraints Turn Counting Into SAT Checks

The key trick is randomized XOR constraints. Imagine a formula has many satisfying solutions. Adding one random XOR constraint tends to cut the number of satisfying solutions roughly in half. Add several such constraints, and the number of remaining solutions shrinks predictably in expectation.

This lets the method replace a hard counting question with satisfiability checks. If solutions remain after enough random filters, the original count was probably large enough. If no solution remains, the original count was probably too small. This gives probabilistic approximation guarantees while using modern SAT solvers.

The Q And A Names The Boundaries

In Q&A, scaling comes up. The speaker says reasoning methods may not currently run end-to-end on GPUs like pure neural systems, but that is not a reason to stop exploring them. The hope is to build reasoning components that can eventually fit better into scalable computational frameworks.

Another question asks about non-experimental fields such as ecology, astronomy, sociology, and economics. Controlled experiments may be impossible there. The speaker points toward statistical and counterfactual reasoning, and notes that different scales in the data may still provide structure for vertical discovery. Noise also comes up: measurement noise makes discovery harder, but experiments show vertical discovery can still outperform flatter approaches in noisy settings.

How This Connects To Design And Topology

Design and topology problems often mix perception, generation, constraints, and scientific laws. A model may propose a geometry, but the geometry must obey manufacturing limits, boundary conditions, material rules, symmetries, load paths, or placement constraints. Pure generation can create attractive but invalid designs.

Vertical reasoning is useful when the full design law is too hard to learn at once. Hold some variables fixed. Learn how one geometry feature affects stress, flow, heat, cost, or manufacturability. Then add another feature. Build from simple controlled subproblems toward the full design rule.

For topology, this is especially relevant because many design variables interact. A flat search over all possible layouts can be enormous. A vertical approach would ask for smaller stepping stones: what happens if only porosity changes, then if channel width changes, then if boundary placement changes, then if all interact? Reasoning chooses the order and rejects designs that violate hard constraints.

The Chapter In One Chain

First, learning and reasoning are two different AI strengths. Second, learning handles messy data but can violate constraints. Third, reasoning checks rules but can be rigid when raw data are complex. Fourth, the kitchen example shows why image generation needs perception plus spatial constraints. Fifth, a neural system can propose object locations while a symbolic engine rejects rule-breaking choices. Sixth, scientific discovery should not always search the whole equation space at once. Seventh, vertical symbolic regression holds variables fixed, discovers a small relationship, then adds variables one at a time. Eighth, the toy equation shows how controlled rows reveal a full law. Ninth, genetic programming can search each reduced step more easily than the full problem. Tenth, Bacon-style systems are a historical neighbor because they summarize lower-level regularities into higher-level variables. Eleventh, the newer vertical approach can be more data efficient than complete factorial exploration. Twelfth, the snowflake PDE example shows that staged parameter learning can recover dynamics missed by learning all parameters at once. Thirteenth, the broader point is that reasoning should help choose intermediate experiments and hypotheses. Fourteenth, satisfiability modulo counting combines logical constraints with probabilistic inference. Fifteenth, randomized XOR constraints let hard counting questions be approximated through SAT checks with guarantees. Sixteenth, design and topology can use vertical reasoning to grow reliable design laws from smaller constrained subproblems instead of searching every variable at once.

The chapter's core idea: learning should not wander blindly through a huge space. Reasoning can choose smaller steps, check hard rules, and turn discovery into a guided climb from simple truths to bigger laws.
