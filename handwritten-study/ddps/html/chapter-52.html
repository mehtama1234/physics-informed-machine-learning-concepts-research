Narrative chapter

Keep The Rule The System Cannot Break

Read This Chapter As One Claim

Trustworthy learning starts by asking which rule the system is not allowed to break. If long mechanical motion must preserve its structure, or an optimizer must keep basis directions orthogonal, the method should make violation impossible rather than merely penalized.

Everyday problem A learned step can look accurate once, then slowly drift into impossible physics or collapsed search directions after being reused many times.
Shared promise Build the hard rule into the map or optimizer: generating functions for mechanical motion, and manifold-preserving steps for orthogonal-column constraints.
Hidden danger A soft loss can reduce rule-breaking on training examples while still allowing drift during long prediction, discrete stepping, or repeated optimization.
First rejection test Reject the shortcut if it cannot prove the hard rule survives each learned step, each rollout step, and each optimizer update.

This chapter uses video 55, Molei Tao's DDPS talk on trustworthy learning of mechanical systems and Stiefel optimization. The talk has two halves, but both halves answer the same simple question: when a system has a rule it is not allowed to break, should learning merely be encouraged to respect that rule, or should the method be built so breaking the rule is impossible?

The answer is strict. If a planet-like system preserves its mechanical structure, the learned predictor should preserve that structure exactly. If an optimization problem needs columns to stay orthogonal, the optimizer should move without losing orthogonality. Trust comes from keeping the hard rule, not from hoping the model remembers it.

system has a hard rule
ordinary learning may drift
build the rule into the method
long use becomes more trustworthy

The Talk Is About Two Directions

The first direction uses machine learning to solve a dynamics problem. We observe a moving mechanical system at several times and want to predict where it will go much later.

The second direction uses dynamics to design better machine learning algorithms. Instead of treating optimization as a blind search, the talk borrows ideas from mechanics, especially momentum, to move faster while staying on the allowed shape.

learn motion from data
preserve mechanical structure
use motion ideas for optimization
stay on constrained spaces

Why Long Prediction Is Different From The Next Step

Imagine watching a planet from a few snapshots. You see red dots along an orbit and want to predict future green dots. Predicting the next dot is not the real test. The real test is whether the predicted path still looks like a possible orbit after many steps.

A tiny error can be harmless for one step and damaging after hundreds or thousands of steps. The model keeps feeding its own output back into itself. If it does not preserve the deeper mechanical rule, it can slowly invent motion that the real system would never allow.

snapshot data
learn next motion
repeat many times
small drift can become wrong physics

Learn The Step Map, Not A Fake Instant Equation

The talk contrasts two ways to learn motion. One way tries to learn a continuous-time equation. That requires estimating a derivative from spaced-out snapshots, fitting the equation, and then numerically integrating it. Each stage adds error.

The other way learns the step map directly: given the state now, predict the state at the next observed time. If the data arrive every hour, learn the one-hour move. If they arrive every day, learn the one-day move. This avoids pretending that the snapshots give perfect instant-speed information.

spaced snapshots
derivative estimate can be noisy
integration adds another error
learn the observed step directly

The Mechanical Rule Is Shape Preservation

Mechanical systems such as ideal planet motion preserve a special phase-space shape. The transcript uses the formal word symplecticity. In plain words, the motion is not allowed to squeeze, smear, or fold the position-and-momentum bookkeeping in an arbitrary way. The system may move somewhere new, but it must move in the mechanical way.

That rule is stronger than conserving one number such as energy. It is a rule about the whole motion map. If the learned map keeps this rule exactly, then even an imperfect learned model remains a mechanical map rather than an arbitrary black box.

position now
momentum now
mechanical move
allowed position and momentum later

Generating Functions Make The Rule Automatic

The method does not ask a neural network to predict every coordinate of the future directly. Instead, it learns a generating function. A generating function is a helper object that connects present and future variables. Once the helper function is chosen, the resulting motion map automatically has the mechanical structure.

This matters because the rule is exact even if the learned helper function is not perfect. A bad helper may produce a poor prediction, but it still produces a motion map of the right kind. The model can be wrong in fit, but it is not allowed to be wrong in type.

learn helper function
connect present and future
produce motion map
structure is exact

Trust Here Means Slower Error Growth

The talk's trust claim is not a vague feeling. The speaker says that preserving the exact mechanical structure lets the error bound grow roughly linearly with prediction time under the right conditions. That is far better than errors that can grow exponentially.

The point for a beginner is simple. If a learned model is used once, structure may look optional. If the same model is used again and again for a long rollout, structure becomes a guardrail. It stops the learned path from leaving the family of possible mechanical paths too easily.

ordinary learned rollout
errors may amplify fast
structure-preserving rollout
error growth can be controlled

The Examples Are Orbits And Chaotic Maps

The planet-orbit example shows the everyday meaning. We want the learned path to keep behaving like an orbit, not slowly spiral away because the predictor forgot the geometry of mechanics.

The standard-map example is harder because it is chaotic. The picture contains stable islands surrounded by chaotic regions. The structure-preserving method better captures the major stable islands. This is important because in chaotic systems the exact future point may be hard to predict, but the shape of the long-term behavior still matters.

planet orbit
long-time path
chaotic stable islands
preserve the behavior shape

The Second Half Starts With Orthogonal Columns

The second half of the talk moves from prediction to optimization. The space of interest is the Stiefel manifold. That name can sound remote, but the object is simple: take a tall matrix and require its columns to be unit length and mutually perpendicular.

That means each column is a clean direction, and no column repeats information already carried by another column. Many problems need this kind of basis. The danger is that ordinary optimization updates can nudge the matrix off the allowed space.

tall matrix
columns have length one
columns are perpendicular
basis stays clean

Eigenvectors Are The First Example

Suppose a huge matrix has a few dominant directions we care about. In vibration, flow, materials, or data analysis, those directions may describe the biggest patterns. If the full matrix is enormous, finding every direction is wasteful.

The optimization version asks for a small set of orthonormal basis vectors that captures the largest part of the matrix action. The orthogonality rule is not cosmetic. Without it, two vectors could chase the same direction and waste one of the slots.

huge matrix
only a few top directions matter
basis vectors must not duplicate
optimize on the allowed space

Wasserstein Distance Is The Second Example

The talk then discusses comparing two probability clouds. The Wasserstein idea asks how much work it takes to move one pile of probability mass into another. This is powerful but expensive in high dimension.

Projection-robust Wasserstein distance searches for a lower-dimensional view where the important difference is visible. That lower-dimensional view is described by orthonormal directions. Again, the columns must stay clean because the method is trying to find a meaningful subspace, not a tangled set of repeated directions.

two high-dimensional clouds
full transport is costly
choose a low-dimensional view
orthogonal directions define the view

Transformers Are The Third Example

The transformer example connects the math to modern deep learning. An attention head contains learned matrices that help decide how parts of an input relate to one another. Multiple heads are used because there can be several useful kinds of relationship.

The talk asks a direct question: if the heads are meant to capture different relationships, can orthogonality keep them from wasting attention on the same thing? The experiments impose orthogonality either within each head or across heads. The within-head version performs best in the reported vision-transformer tests.

many attention heads
each learns relationships
orthogonality reduces repetition
vision transformer improves

Momentum Means Do Not Crawl If You Can Roll

Plain gradient descent moves downhill using only the current slope. Momentum adds a memory of motion. It is like pushing a heavy object downhill: the object does not forget its direction at every instant, so it can move faster through gentle regions.

But momentum on a constrained space is delicate. If the matrix must stay on the Stiefel manifold, the optimizer cannot simply add a Euclidean momentum step and hope. The motion has to carry both the position and the momentum while keeping the columns orthonormal.

gradient descent crawls
momentum carries direction
ordinary step can leave constraint
structured step stays on manifold

The Variational Principle Is A Design Tool

The talk uses a mechanics idea called a variational principle. In everyday language, it is a way to define motion by saying which whole path is allowed, rather than only writing a local update rule.

For optimization, time dependence adds friction. Friction removes energy, so the motion can settle into a minimum instead of endlessly trading kinetic and potential energy. This connects accelerated optimization methods to mechanical motion with damping.

mechanical motion
add time-dependent damping
energy drains away
state settles near minimum

The Hard Part Is Discretizing Without Breaking The Rule

A continuous-time equation can preserve the Stiefel constraint exactly, but a computer needs discrete steps. A careless discrete step can slowly destroy orthogonality. Then the algorithm is no longer solving the intended problem.

The talk's optimizer is built so each discrete step remains on the manifold. It also avoids expensive operations such as full matrix exponentials. This matters when the matrix has many rows and only a small number of columns, which is common in large data and physics problems.

continuous rule is exact
computer uses steps
bad steps leak off the space
careful steps preserve the rule

Why This Matters For Design And Topology

Topology and design problems often search through shapes, materials, modes, and fields. Many of these searches use reduced bases, dominant directions, probability comparisons, or learned attention-like maps. If the search directions collapse into repeated information, the design loop wastes evaluations.

This chapter gives a general lesson for those applications: when the design variable is supposed to live on a special space, keep it there by construction. If modes must remain orthogonal, enforce that exactly. If a learned mechanical model must stay mechanical, enforce that exactly. The method should respect the shape of the problem before it claims speed.

design loop needs repeated search
basis or motion has a hard rule
preserve the rule exactly
speed without fake freedom

The Chapter In One Chain

First, long prediction is hard because small learned errors are repeated many times. Second, mechanical systems have a deeper motion rule, not just isolated numbers to conserve. Third, learning the observed step map avoids derivative and integration errors. Fourth, a generating function can make the learned map preserve the mechanical rule exactly. Fifth, this helps long-time prediction because the learned path stays in the right family of motions. Sixth, the same philosophy appears in optimization on the Stiefel manifold, where matrix columns must remain orthonormal. Seventh, eigenvector search, projection-robust Wasserstein distance, and transformer attention all use this kind of clean-direction constraint. Eighth, momentum can speed optimization, but only if the step keeps the variable on the allowed space. Ninth, careful discrete algorithms matter because computers move in steps. Tenth, for design and topology, the lesson is to preserve the rule the problem cannot break before trusting any learned shortcut.

The chapter's core idea: trust is not created by adding fancy words to a model. Trust is created when the learning or optimization method cannot violate the simple rule the physical or design problem depends on.

How To Test Whether You Understood This Chapter

Say the problem without geometry words

If the real system always follows a rule, a learned tool should not be free to forget that rule after many repeated steps.

Explain why hard rules beat soft wishes

A penalty only discourages breaking the rule. A structure-preserving map or manifold step makes the illegal move unavailable.

Connect it to topology and design

Design searches often use modes, bases, directions, or learned maps. If those directions stop being clean or the learned motion leaves the allowed space, the optimization spends effort on fake designs.

State the honest limit

Preserving the rule does not guarantee a perfect prediction or optimum. It guarantees the model stays the right kind of object while accuracy, cost, and long-time behavior still need testing.
