Add Physics As A Bias, Then Check The Bias

This chapter uses video 91, Alice Cicirello's DDPS talk on challenges and opportunities for integrating physics knowledge into machine learning strategies, with friction identification as the case study.

The first-principles question is this: if engineering data is noisy, sparse, incomplete, and safety-relevant, how do we use machine learning without letting it produce accurate-looking nonsense?

The lecture's answer is to treat physics as a bias that guides learning, not as a slogan. Physics can make learning more generalizable and interpretable, but only if the embedded physics is appropriate. Wrong physics can constrain the model toward the wrong answer while still fitting the measured data.

Read This Chapter As One Claim

Start with a simple engineering worry. A machine vibrates, a joint slips, a brake wears, or a structure rattles, and the part causing the trouble is hidden inside contact. You can measure motion outside the contact, but you cannot directly see the friction force without changing the thing you are trying to measure. Machine learning can fit the measured motion, but fitting motion is not the same as finding the hidden law. Physics helps by narrowing the possible answers: contacts can stick or slip, forces have signs, energy is lost, and regimes switch. But that help is only useful if the chosen physics matches the real system. The chapter's main claim is therefore strict: add physics as a guide, then test the guide. A wrong physical assumption can make the model look clean while quietly teaching it the wrong law.

Data Must Become Information

The talk starts from engineering systems such as satellites, bridges, friction brakes, and turbine components. These systems are complex, loaded over broad frequency ranges, made from many parts, and affected by uncertainty and nonlinear behavior.

Raw data is not enough. Data must be informative, accurate, and reliable. Informative means it contains the signal needed to answer the question. Accurate means it is close to the true value. Reliable means repeated measurements under the same condition would agree. Engineering data often fails one or more of these tests.

Engineering Usually Lives In The Middle

If there is lots of useful data and very little physics knowledge, ordinary machine learning may be reasonable. If there is lots of physics knowledge and little data, physics modeling may dominate. Most engineering problems sit between those extremes.

That middle region is where physics-enhanced machine learning matters. We have some equations, some domain knowledge, some tests, some noisy measurements, some simulations, and some uncertainty. The job is to integrate them without pretending any one source is complete.

not data-only
not physics-only
partial evidence from both
integration challenge

Accurate Can Still Be Wrong

A data-driven model can fit observed measurements and still be physically wrong. Data can be corrupted. Data can show correlation without causal relationship. Hidden confounding sources can make the model learn the wrong association.

In applied mechanics, that is not a small issue. These models can support decisions about design, monitoring, remaining life, maintenance, and failure prevention. A wrong but confident prediction can affect structures, machines, performance, and safety.

Interpretability And Explainability Are Different Jobs

Interpretability asks how the prediction was made. Explainability asks whether the prediction can be communicated to support human decision-making. Both matter because engineers need to know not only what the model says, but when it succeeds, when it fails, and why.

The talk also stresses uncertainty. A useful explanation should communicate the remaining uncertainty instead of hiding it. Critical decisions still end up with people, so the model must support human reasoning, not replace it with a black box.

how was it predicted?
when does it fail?
can humans use it?
what uncertainty remains?

Physics Can Enter Four Ways

Cicirello describes four kinds of bias. Observational bias means adding or choosing data sources that carry the physics we care about. Inductive bias means building physical constraints into the architecture, such as symmetries, boundaries, conservation laws, or structural assumptions.

Learning bias means shaping the loss function, regularization, constraints, or inference algorithm. Physics-model bias means embedding known equations, partial equations, model forms, or discrepancy terms. These biases can be combined, but each one is a modeling choice that must be justified.

inductive bias
learning bias
physics-model bias

There Is No One Physics-ML Recipe

The right method depends on the system complexity, the amount of informative data, and the purpose. Sometimes the goal is to learn an unknown equation term. Sometimes it is to learn a reduced latent space. Sometimes it is to quantify uncertainty in a non-physics model. Sometimes it is to learn missing terms in a partially known physics model.

This matters because "physics-informed" is not one method. PINNs, sparse system identification, autoencoders, probabilistic machine learning, Gaussian-process latent force models, and physics-enhanced sparse discovery can all sit under the broad umbrella, but they solve different problems.

Friction Is Hard Because You Cannot Measure It Directly

The case study is friction. Friction resists relative motion between surfaces. It can be useful because it dissipates energy and reduces vibration. It can also cause wear, noise, large accelerations, stick-slip motion, and reduced remaining useful life.

The hard part is measurement. The friction force happens inside a contact. If we open the contact, the friction disappears. If we place a sensor inside, we change the contact. So the goal is to infer friction from measured response away from the contact.

surfaces touch
friction force is hidden
measure response elsewhere
infer force-velocity law

Stick-Slip Creates Discontinuous Behavior

The test setup uses a base plate, a top aluminum plate, flexible connecting bars, and a brass contact element. The base moves harmonically. The contact mass can stick, slip, stop twice, stop four times, or move continuously within a cycle.

Stick-slip is difficult because the behavior changes state. During sticking, the contact is locked. During slipping, it moves. At transitions, energy can release suddenly. A smooth model or ordinary differentiating method can struggle at those sharp changes.

base excites structure
contact sticks
contact slips
sharp transitions appear

Extended SINDy Separates Motion From Sticking

The first strategy extends sparse identification of nonlinear dynamics. Ordinary SINDy builds a library of candidate functions and chooses a sparse governing equation. But with friction, ordinary SINDy can confuse the governing law because the data mixes moving and sticking regimes.

Extended SINDy adds physics knowledge. It partitions data by velocity into moving and sticking pieces. It applies SINDy to the motion data, then uses stick-slip constraints to correct the coefficients. The extra cost is small because the expensive part is still basically the SINDy solve.

candidate function library
split moving and sticking data
apply SINDy to motion
correct with constraints

The Extended Method Helps But Still Has Limits

For continuous motion, extended SINDy reduces to ordinary SINDy. For two-stop and four-stop stick-slip cases, the extended method can recover behavior that ordinary SINDy may miss. That is the value of using the regime information.

But it is still sensitive to noise and differentiation. It also degrades as the number of stops increases, and it does not naturally provide uncertainty bounds. This motivates the second strategy.

works for simple stopping

Switching Gaussian Processes Learn The Hidden Force Curve

The second strategy assumes we know the structural model except for the friction force. The friction force is treated as a latent force: a hidden input that explains the observed displacement. A Gaussian process latent force model can infer an unknown function and uncertainty.

A plain Gaussian process is too smooth for stick-slip. It smooths out the sharp discontinuity and gives a poor force-velocity law near zero velocity. The fix is a switching Gaussian process latent force model with separate modes for sliding, sticking, and resetting.

known structure model
unknown friction force
sliding, sticking, reset modes
force curve with uncertainty

The Switching Model Captures Regime Changes

The switching model uses filtering and smoothing to infer the posterior distribution of the hidden force and the motion regime. A Markov model decides which mode is active: stick, slip, or reset.

This gives a better friction force versus velocity curve and uncertainty bounds. Its limit is scalability. Gaussian-process methods face dimensionality issues, and this particular setup handles one type of nonlinearity at a time.

filter and smooth response
detect active mode
recover sharp force curve
dimensionality limits scale

Physics-Enhanced Sparse Identification Combines The Strengths

The third strategy tries to keep the speed and explicit equation discovery of sparse identification while embedding more physics. It assumes part of the model is known and only an unknown functional term must be discovered.

The method uses a Runge-Kutta time-stepping scheme inside the learning process and includes event conditions for stick-slip. That event information matters. Without it, the model can fit displacement and velocity in the training case but discover the wrong governing equation.

Wrong Physics Can Fit And Still Fail

One example assumes the base excitation is a perfect harmonic input. That assumption is wrong because the actual system does not provide a perfect harmonic base excitation. The learned model can still reproduce displacement and velocity, but the discovered equation is wrong and misses the friction sign term.

This is the chapter's central warning. Physics-informed learning is not automatically safer. If the physics bias is wrong, it can push the search into the wrong region of solution space. The answer may look accurate on measured outputs and fail as a general law.

Hard Cases Can Look Identical In The Measurements

The talk compares Coulomb friction and a Dahl friction law. In some parameter ranges, their measured displacement-force behavior can look almost the same. That makes the inverse problem hard because the data alone may not distinguish the laws.

With appropriate candidate functions and physics constraints, the physics-enhanced sparse identification method can recover the correct governing equation in the shown cases, even with noisy measurements. The remaining missing piece is uncertainty quantification.

The Q And A Sharpens The Practical Advice

The Q and A confirms that extended SINDy uses the same library as ordinary SINDy. The difference is the regime separation and constraints. It also confirms that if the candidate library is too open, the method may return a fitted regressor but not a generalizable physical law.

Another question asks whether the embedded physics must be a closed-form equation. The answer is no: it can be a finite-element model or another surrogate, but then the whole architecture must be built around how that model takes inputs and returns outputs. Differential equation residuals are convenient in neural networks because derivatives can be computed directly, but they are not the only possible physics bias.

Why This Matters For Design And Topology

Design and topology workflows often use learned models to choose geometry, joints, contacts, material placement, damping, or maintenance action. Friction is a good warning example because the hidden law affects vibration, energy dissipation, wear, and failure, but it cannot be measured directly at the contact.

If a topology optimizer or digital twin uses the wrong friction law, it may design a joint that looks safe in simulation but amplifies motion in operation. If it uses a data-only fit, it may work in one test and fail under a new frequency ratio, load, or stop pattern. The right workflow must ask what physics bias is being used, what data supports it, where it fails, and what uncertainty remains.

The broader lesson is that physics-informed learning is a responsibility. Physics can shrink the search space and make equations generalizable. It can also shrink the search space around the wrong answer. The design loop should therefore treat physics knowledge as evidence to check, not decoration to add.

The Chapter In One Chain

First, engineering data is often sparse, noisy, incomplete, and safety-relevant. Second, data must become informative, accurate, reliable information before it supports decisions. Third, engineering usually has some data and some physics, so the problem is integration. Fourth, data-only models can fit measurements while learning the wrong physical relationship. Fifth, interpretability asks how the prediction was made, and explainability asks whether humans can use it for decisions with uncertainty. Sixth, physics can enter through observational, inductive, learning, and physics-model biases. Seventh, there is no one physics-informed recipe because different goals require different methods. Eighth, friction is hard because it happens inside contact and cannot be directly measured without changing the contact. Ninth, stick-slip creates discontinuous switching between stuck and sliding regimes. Tenth, extended SINDy separates moving and sticking data and adds constraints to ordinary sparse identification. Eleventh, that helps for stick-slip but remains noise-sensitive and lacks uncertainty. Twelfth, switching Gaussian-process latent force models infer the hidden friction curve with stick, slip, and reset modes plus uncertainty. Thirteenth, this captures discontinuities but has dimensionality limits. Fourteenth, physics-enhanced sparse identification uses a partial known model, RK4 learning, and event constraints to learn missing friction terms. Fifteenth, wrong physics can fit displacement and velocity while discovering the wrong law. Sixteenth, Coulomb and Dahl friction can be hard to distinguish from measurements alone, so constraints and candidate functions matter. Seventeenth, design and topology workflows need the same discipline: use physics to guide learning, but verify that the physics bias is the right one for the operating regime.

The chapter's core idea: physics-informed machine learning is not "add an equation and trust it." It is a controlled use of bias. The right bias can make a sparse, noisy engineering problem learnable and generalizable. The wrong bias can produce a clean-looking answer that fails when the structure is used.
